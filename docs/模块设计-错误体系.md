# 模块设计：错误体系

## 模块位置

`src/core/error.rs`

## 职责

定义统一的错误类型 `ConstructError`，覆盖所有构造器在 parse/build/sizeof 操作中可能产生的错误。所有错误携带 `path` 字段用于错误追踪。

## 详细设计

### ConstructError 枚举

```rust
#[derive(Debug, thiserror::Error)]
pub enum ConstructError {
    // ── 通用错误 ──
    #[error("construct error at {path}: {message}")]
    Generic { path: String, message: String },

    // ── 流错误 ──
    #[error("stream error at {path}: {source}")]
    Stream {
        path: String,
        #[source]
        source: std::io::Error,
    },

    // ── 格式字段错误 ──
    #[error("format field error at {path}: expected {expected} bytes but got {actual}")]
    FormatField {
        path: String,
        expected: usize,
        actual: usize,
    },

    // ── 大小计算错误 ──
    #[error("cannot compute sizeof at {path}: {reason}")]
    Sizeof { path: String, reason: String },

    // ── 常量不匹配 ──
    #[error("const error at {path}: expected {expected:?} but got {actual:?}")]
    Const {
        path: String,
        expected: String,
        actual: String,
    },

    // ── 值校验失败 ──
    #[error("validation failed at {path}: {message}")]
    Validation { path: String, message: String },

    // ── 数组错误 ──
    #[error("array error at {path}: expected {expected} elements but got {actual}")]
    Array {
        path: String,
        expected: usize,
        actual: usize,
    },

    // ── 索引越界 ──
    #[error("index out of range at {path}: index {index} in list of length {length}")]
    Index {
        path: String,
        index: usize,
        length: usize,
    },

    // ── 填充错误 ──
    #[error("padding error at {path}: {message}")]
    Padding { path: String, message: String },

    // ── 检查失败 ──
    #[error("check failed at {path}: {message}")]
    Check { path: String, message: String },

    // ── 终止符错误 ──
    #[error("stream not terminated at {path}: {remaining} bytes remaining")]
    Terminated { path: String, remaining: usize },

    // ── 字符串编解码错误 ──
    #[error("string encoding error at {path}: {source}")]
    StringEncoding {
        path: String,
        #[source]
        source: std::string::FromUtf8Error,
    },

    // ── 映射查找失败 ──
    #[error("mapping error at {path}: key {key:?} not found in mapping")]
    Mapping { path: String, key: String },

    // ── 表达式求值错误 ──
    #[error("expression error at {path}: {message}")]
    Expr { path: String, message: String },

    // ── Union 错误 ──
    #[error("union error at {path}: {message}")]
    Union { path: String, message: String },

    // ── Switch 分支错误 ──
    #[error("switch error at {path}: no branch for key {key:?}")]
    Switch { path: String, key: String },

    // ── 字段缺失 ──
    #[error("field missing at {path}: field {field:?} not found in container")]
    FieldMissing { path: String, field: String },

    // ── 类型不匹配 ──
    #[error("type mismatch at {path}: expected {expected} but got {actual}")]
    TypeMismatch {
        path: String,
        expected: String,
        actual: String,
    },
}
```

### 错误路径辅助

```rust
impl ConstructError {
    /// 获取错误路径
    pub fn path(&self) -> &str { ... }

    /// 拼接路径前缀，用于子构造器错误追踪。
    ///
    /// **按值消费 self**（而非 &self），原因：
    /// `Stream` 变体含 `std::io::Error`，`StringEncoding` 变体含
    /// `std::string::FromUtf8Error`，二者均未实现 `Clone`。
    /// 按值消费可原样移动 source 字段，完整保留底层错误链，
    /// 避免 `source.kind().into()` 导致错误信息丢失。
    pub fn with_path_prefix(self, prefix: &str) -> Self {
        match self {
            ConstructError::Stream { path, source } => ConstructError::Stream {
                path: join_path(prefix, &path),
                source,
            },
            // ... 每个变体都拼接路径，原样移动所有字段
        }
    }
}

/// 辅助函数：拼接路径前缀与子路径。
/// 若子路径为空，直接返回 prefix（避免尾部分隔符）；
/// 否则用 "." 连接。
fn join_path(prefix: &str, path: &str) -> String {
    if path.is_empty() {
        prefix.to_string()
    } else {
        format!("{prefix}.{path}")
    }
}
```

### 流错误转换

```rust
impl From<std::io::Error> for ConstructError {
    fn from(err: std::io::Error) -> Self {
        ConstructError::Stream {
            path: String::new(),
            source: err,
        }
    }
}
```

## 错误路径追踪机制

Python 版本中，每个构造器在解析时维护 `path` 字符串，格式如 `(parsing) -> header -> magic`（使用 `" -> "` 分隔符，见 `core.py` 第 2772 行）。当子构造器出错时，路径会自动拼接。

Rust 版本的实现策略：

1. 每个构造器的 parse/build 方法在出错时设置当前路径
2. 父构造器捕获子构造器的错误并拼接路径前缀
3. 最终错误消息包含完整的字段路径

**路径分隔符决策**：Rust 版本使用 `"."` 作为路径分隔符（而非 Python 的 `" -> "`），理由：
- `"."` 更简洁，与 Rust 的模块路径风格一致（如 `std::io::Error`）
- `"."` 不含空格，便于程序化解析和日志处理
- 错误路径仅用于人类可读的诊断信息，分隔符格式不影响功能正确性
- 路径格式将在 1.6 Construct trait 的 Renamed 包装器中最终定型

```
示例：
Struct("header") → field "magic" → Const
  → ConstructError::Const {
      path: "header.magic",
      expected: "b\"PNG\"",
      actual: "b\"JPG\"",
    }
```

## 扩展策略

后续阶段如需新增错误类型，直接在 `ConstructError` 枚举中添加变体。每个变体都必须携带 `path: String`。
