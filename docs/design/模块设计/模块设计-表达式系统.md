## 1. 概述

### 1.1 目标

为 construct-rs 引入表达式系统，使用户能够在 StructMixin 子类中声明字段间的引用关系
（如 `Bytes(count)` 引用前序字段 `count` 的值），以及条件解析（Switch / IfThenElse）、
计算字段（Computed / Tell）等高级能力。

**性能目标**：表达式场景 ≥8x vs Python construct 2.10.70（10x 为理想目标）。

### 1.2 范围

本设计覆盖以下内容，供 PM 拆分为 Phase 2（框架验证）和 Phase 3（完整实现）：

| 能力 | 涉及组件 |
|------|---------|
| 字段引用（FieldRef） | `_FieldDescriptor` 扩展、`BytesNode` 表达式长度 |
| 算术表达式（ExprRef） | `_ExprRef` 类、`ExprOp` VM 指令集 |
| 三种 field 函数（RW/RO/WO） | `field()` / `rfield()` / `wfield()` |
| default 参数 | `field(subcon, default=value)` 自动 kw_only |
| Context 恢复 | `Context::new_root` + `set_field` |
| 计算字段 | `TellNode`、`ComputedNode` |
| 常量校验 | `ConstNode` |
| 条件解析 | `SwitchNode`、`IfThenElseNode` |
| 跨层引用 | `context=` 参数、`ContextParam` 构造器 |

> **[PM 决定 CONFIRM-2] Phase 2 已知限制 — Rebuild 场景不可用**：
> 经典 Rebuild 模式（长度字段在前、数据字段在后、`length=len(data)`）需要后序字段引用
> （build 方向引用后续字段），而 Phase 2 的前向引用限制（§3.4.2）统一拒绝引用后序字段。
> 这使得 `count = Computed(len(data))` 在 Phase 2 中不可用。**RebuildNode 在 Phase 3
> 单独设计**。理由：Rebuild 需要更复杂的后序字段引用机制，Phase 2 聚焦验证核心表达式架构。

### 1.3 与 Phase 1 的衔接

Phase 1 已实现 5 个 Node（FormatField、Bytes、GreedyBytes、Struct、StructRef），性能达 8-12x。
Phase 2-3 的设计**不破坏** Phase 1 的行为：

- 现有 `field(Int8ub)` 语义不变（RW 模式）
- 现有 `Bytes(4)` 常量长度语义不变
- 现有 `Context::placeholder` 仍可用于无表达式的 Struct（性能优化保留）
- P0 优化（LTO、Path 零成本、interned key）全部保留

**关键改造点**：

| Phase 1 状态 | Phase 2-3 改造 |
|-------------|---------------|
| `Context::placeholder`（parse/build 入口） | 有表达式的 Struct 改用 `Context::new_root`；无表达式的保留 placeholder |
| StructNode.parse 不写 context | 有表达式的 Struct 改为复用 parse dict 作为 context fields |
| StructNode.build 不写 context | 有表达式的 Struct 每个 RW/RO 字段后 `ctx.set_field`（WO 不写，方案 A） |
| BytesNode.length: usize | 改为 `BytesLength` 枚举（Const 或 Expr） |
| Node enum 5 个变体 | 新增 6 个变体：Tell/Computed/Const/Switch/IfThenElse/ContextParam |

### 1.4 核心设计原则

1. **编译期翻译**：所有表达式在 `__init_subclass__` 中翻译为扁平的 `ExprOp` 指令序列，
   运行时零 Python 对象创建（决策 2）
2. **VM 求值零 FFI**：`eval_expr` 全程在 Rust 内部，栈式执行（决策 2）
3. **i64 栈**：VM 栈统一用 `i64`，覆盖 95% 用例（长度、计数、偏移量均为整数）；
   非 整数引用（如 Switch 的字符串 key）走单独路径
4. **Context 复用**：parse 方向复用实例 dict 作为 context fields，零额外 set_item 开销
5. **mode 正交**：field 函数管用户语义（RW/RO/WO），构造器管字节语义，两维度正交（决策 5、7）

## 2. Python 接口设计

### 2.1 三种 field 函数：RW / RO / WO（决策 5）

从用户视角定义两个布尔属性：

- **R**（Readable）：parse 后用户能读到（出现在实例属性中）
- **W**（Writable）：build 时用户需要提供（出现在 `__init__` 参数中）

{R, W} 的非空子集为 {RW, RO, WO}——数学完备，可证明穷尽。

| 函数 | 签名 | mode | dataclass 配置 | 用户视角 |
|------|------|------|---------------|---------|
| `field(subcon, ...)` | RW | rw | 正常 field，在 `__init__` 中 | build 要填，parse 能读 |
| `rfield(subcon, ...)` | RO | ro | `init=False` | build 不用填，parse 能读 |
| `wfield(subcon, ...)` | WO | wo | 正常 field，在 `__init__` 中 | build 要填，parse 读不到 |

**用户心智模型**：`r` = 读得到，`w` = 要填，`field` = 两者都要。

#### 2.1.1 `_FieldDescriptor` 扩展

Phase 1 的 `_FieldDescriptor` 仅存储 `subcon`。Phase 2 扩展为携带 mode 和 default：

```python
# 哨兵值：表示"未指定 default"
_MISSING = object()

class _FieldDescriptor:
    """field()/rfield()/wfield() 的返回值。

    同时满足三套协议：
    - **@dataclass 字段协议**：作为字段默认值。@dataclass 视其为普通默认值。
    - **Mixin 编译协议**：__init_subclass__ 提取 mode、subcon、default。
    - **FieldRef 协议**：可被其他字段的表达式引用（如 Bytes(count) 中的 count）。
      通过对象 identity（id()）唯一标识，编译期建立 id→field_index 映射。

    该对象同时是 FieldRef——支持算术运算重载（__add__ 等），返回 _ExprRef。
    """
    __slots__ = ("subcon", "mode", "default", "name", "_context_injections")

    def __init__(self, subcon, *, mode="rw", default=_MISSING, context=None):
        self.subcon = subcon          # 类型描述符（Int8ub, Bytes(n), Tell(), ...）
        self.mode = mode              # "rw" / "ro" / "wo"
        self.default = default        # _MISSING（无默认）或具体值
        self.name = None              # __set_name__ 填充（用于错误信息）
        self._context_injections = context  # dict 或 None（决策 4 的 context= 参数）

    def __set_name__(self, owner, name):
        """Python 3.6+ 描述符协议：类创建时自动调用，填充字段名。"""
        self.name = name

    def __repr__(self):
        return "_FieldDescriptor(name={!r}, mode={!r}, subcon={!r})".format(
            self.name, self.mode, self.subcon
        )

    # --- FieldRef 算术运算重载（返回 _ExprRef） ---
    # 详见 §2.3

# __class_getitem__ 支持 FieldRef[int] 语法（T 仅用于 IDE 提示，运行时忽略）
def _class_getitem(cls, item):
    return cls
_FieldDescriptor.__class_getitem__ = classmethod(_class_getitem)
```

#### 2.1.2 三个 field 函数的实现

```python
def field(subcon, *, default=_MISSING, context=None):
    """声明一个 RW 字段（build 要填，parse 能读）。

    :param subcon: 类型描述符。
    :param default: 可选默认值。指定后自动设为 kw_only=True（决策 6）。
    :param context: 可选，跨层引用的 context 注入映射（决策 4）。
    :return: _FieldDescriptor(mode="rw")。
    """
    return _FieldDescriptor(subcon, mode="rw", default=default, context=context)


def rfield(subcon, *, context=None):
    """声明一个 RO 字段（build 不用填，parse 能读）。

    RO 字段在 build 时自动计算（不从实例取值）：
    - Tell()/Computed()：build 时求值表达式/取流位置
    - Const()：build 时用常量值
    - Bytes(expr)：build 时求值表达式长度（但 RO 的 Bytes 少见）

    :param subcon: 类型描述符。
    :return: _FieldDescriptor(mode="ro")。
    """
    return _FieldDescriptor(subcon, mode="ro", context=context)


def wfield(subcon, *, default=_MISSING, context=None):
    """声明一个 WO 字段（build 要填，parse 读不到）。

    parse 时正常解析（消费字节），但结果不存入实例属性（丢弃）。
    典型场景：padding、reserved 字段。

    :param subcon: 类型描述符。
    :param default: 可选默认值。指定后自动设为 kw_only=True。
    :return: _FieldDescriptor(mode="wo")。
    """
    return _FieldDescriptor(subcon, mode="wo", default=default, context=context)
```

### 2.2 default 参数与 kw_only（决策 6）

有 `default` 的字段自动设为 `kw_only=True`，使其可以出现在任意位置而不受 dataclass
"无默认值字段在前"的约束。

```python
@dataclass
class Packet(StructMixin):
    count: int = field(Int8ub)                    # 必填，positional
    data: bytes = field(Bytes(count))             # 必填，positional
    version: int = field(Int8ub, default=1)       # 可选 → kw_only=True
    reserved: int = field(Int8ub, default=0)      # 可选 → kw_only=True

Packet(count=1, data=b'\x01\x02')                # version=1, reserved=0
Packet(count=1, data=b'\x01\x02', version=2)     # version=2
```

#### 2.2.1 `__init_subclass__` 中的 dataclass 配置注入

`__init_subclass__` 在 `@dataclass` **之前**执行，此时 `__dataclass_fields__` 尚不存在。
但 `@dataclass` 会读取类属性上的 `dataclasses.field()` 对象来配置字段。

**机制**：`__init_subclass__` 将 `_FieldDescriptor` 替换为 `dataclasses.field()` 调用结果
（携带正确的 `init`、`default`、`kw_only` 参数），然后 `@dataclass` 正常处理。

```python
def _apply_dataclass_field_config(cls, descriptors):
    """将有 default 的 _FieldDescriptor 转换为 dataclasses.field 配置。

    在 __init_subclass__ 末尾调用（编译完成后，@dataclass 执行前）。
    将类属性上的 _FieldDescriptor 替换为 dataclasses.field() 返回值，
    使 @dataclass 能正确配置 init/default/kw_only。

    :param cls: StructMixin 子类。
    :param descriptors: [(field_name, _FieldDescriptor), ...] 有序列表。
    """
    import dataclasses

    for name, desc in descriptors:
        if desc.mode == "ro":
            # RO 字段：init=False，无 default（parse 时计算）
            setattr(cls, name, dataclasses.field(init=False, default=None))
        elif desc.default is not _MISSING:
            # RW/WO 字段且有 default：kw_only=True + default
            setattr(cls, name, dataclasses.field(
                kw_only=True, default=desc.default
            ))
        else:
            # RW/WO 字段无 default：保持 _FieldDescriptor 作为默认值
            # @dataclass 会将其视为普通默认值（Phase 1 行为不变）
            pass
```

> **注意**：`dataclasses.field(init=False)` 需要一个 `default` 或 `default_factory`，
> 否则 @dataclass 会报错。RO 字段用 `default=None` 作为占位（parse 时会被 force_setattr
> 覆盖）。

#### 2.2.2 字节顺序与 init 顺序解耦（决策 8）

**字节布局顺序 = 声明顺序**（不可变）。`__init__` 参数顺序 = 按字段性质自动排列。
`rfield` 的 `init=False` 不参与 dataclass 参数排序约束。

```python
@dataclass
class Packet(StructMixin):
    count: int = field(Int8ub)              # 字节第 1 字节，__init__ 第 1 参数
    crc: int = rfield(Checksum(...))        # 字节第 2 字节，但 __init__ 无此参数
    data: bytes = field(Bytes(count))       # 字节第 3+ 字节，__init__ 第 2 参数

# 字节布局：count(1) + crc(1) + data(count) ← 声明顺序
# __init__：Packet(count, data) ← rfield 不参与
```

dataclass 自动将无 default 的 RW/WO 字段排在前面，有 default 的 kw_only 字段排在后面，
RO 字段（init=False）不出现。三者独立排列，不影响字节布局。

### 2.3 FieldRef / ExprRef 类型系统（决策 1）

**核心设计**：字段名本身就是引用对象。`Bytes(count)`。
`count` 是 `_FieldDescriptor` 实例，在类体中作为类属性存在，可被其他字段的 subcon 引用。

#### 2.3.1 为什么 `_FieldDescriptor` 充当 FieldRef

在 Python 类定义中：

```python
@dataclass
class Packet(StructMixin):
    count: int = field(Int8ub)          # count → _FieldDescriptor(Int8ub)
    data: bytes = field(Bytes(count))   # Bytes(count) 引用上面的 _FieldDescriptor
```

类体执行时，`count = field(Int8ub)` 创建一个 `_FieldDescriptor` 对象并存入类命名空间。
随后 `Bytes(count)` 被执行，`count` 取的是这个 `_FieldDescriptor` 对象（不是 int 值）。

因此 `_FieldDescriptor` 天然就是可被引用的 FieldRef——无需额外机制。

**编译期绑定**：`__init_subclass__` 中 `_collect_field_descriptors` 收集
`[(field_name, descriptor), ...]`，建立 `id(descriptor) → field_index` 映射。
表达式中的 FieldRef 通过 `id()` 查找对应的字段索引，翻译为 `ExprOp::GetInt(field_index)`。

#### 2.3.2 类型参数 T

`FieldRef[int]` / `ExprRef[int]` 中的 `T` **仅用于 IDE 类型提示和文档**，运行时无意义。

通过 `__class_getitem__` 支持 `FieldRef[int]` 语法：

```python
_FieldDescriptor.__class_getitem__ = lambda cls, item: cls
# FieldRef[int] 返回 _FieldDescriptor 类本身，T 被忽略
```

用户通常不需要直接写 `FieldRef[int]`——类型注解 `count: int = field(Int8ub)` 已经告诉
IDE 这个字段的值是 `int`。当用户在其他字段引用 `count` 时，IDE 通过 `@overload`
装饰器推断算术表达式的类型。

#### 2.3.3 算术运算重载

`_FieldDescriptor` 重载 Python 运算符，返回 `_ExprRef`（表达式节点）：

```python
import operator

class _ExprRef:
    """表达式节点，编译期翻译为 ExprOp 指令序列。

    _ExprRef 形成一棵二叉表达式树：
    - lhs / rhs 可以是 _FieldDescriptor、_ExprRef 或常量（int/float）
    - op 是 operator 模块的函数（operator.add 等）

    _ExprRef 本身也重载算术运算，支持无限嵌套。
    通过对象 identity 与 _FieldDescriptor 区分。
    """
    __slots__ = ("op", "lhs", "rhs")

    def __init__(self, op, lhs, rhs):
        self.op = op    # operator.add / operator.sub / ...
        self.lhs = lhs  # _FieldDescriptor | _ExprRef | int | float
        self.rhs = rhs  # _FieldDescriptor | _ExprRef | int | float

    def __repr__(self):
        return "_ExprRef(op={!r})".format(getattr(self.op, "__name__", self.op))

    # _ExprRef 也支持继续运算
    def __add__(self, other):
        return _ExprRef(operator.add, self, other)

    def __radd__(self, other):
        return _ExprRef(operator.add, other, self)

    def __sub__(self, other):
        return _ExprRef(operator.sub, self, other)

    def __rsub__(self, other):
        return _ExprRef(operator.sub, other, self)

    def __mul__(self, other):
        return _ExprRef(operator.mul, self, other)

    def __rmul__(self, other):
        return _ExprRef(operator.mul, other, self)

    def __floordiv__(self, other):
        return _ExprRef(operator.floordiv, self, other)

    def __rfloordiv__(self, other):
        return _ExprRef(operator.floordiv, other, self)

    def __mod__(self, other):
        return _ExprRef(operator.mod, self, other)

    def __rmod__(self, other):
        return _ExprRef(operator.mod, other, self)

    def __and__(self, other):
        return _ExprRef(operator.and_, self, other)

    def __or__(self, other):
        return _ExprRef(operator.or_, self, other)

    def __xor__(self, other):
        return _ExprRef(operator.xor, self, other)

    def __lshift__(self, other):
        return _ExprRef(operator.lshift, self, other)

    def __rshift__(self, other):
        return _ExprRef(operator.rshift, self, other)

    def __neg__(self):
        return _ExprRef(operator.neg, self, None)

    def __pos__(self):
        return self  # 正号无操作

    def __invert__(self):
        return _ExprRef(operator.invert, self, None)

    # 比较运算（返回 _ExprRef，编译为 Eq/Lt/Gt 等，VM 返回 0/1）
    def __eq__(self, other):
        return _ExprRef(operator.eq, self, other)

    def __ne__(self, other):
        return _ExprRef(operator.ne, self, other)

    def __lt__(self, other):
        return _ExprRef(operator.lt, self, other)

    def __le__(self, other):
        return _ExprRef(operator.le, self, other)

    def __gt__(self, other):
        return _ExprRef(operator.gt, self, other)

    def __ge__(self, other):
        return _ExprRef(operator.ge, self, other)

    __hash__ = None  # 表达式不可哈希（与 Python construct 一致）

# _ExprRef 也支持 __class_getitem__（ExprRef[int] 语法）
_ExprRef.__class_getitem__ = lambda cls, item: cls
```

`_FieldDescriptor` 的算术重载与 `_ExprRef` 完全对称（方法体相同，返回 `_ExprRef`）。
为避免代码重复，可在 `_FieldDescriptor` 上使用 mixin 或直接复制方法。

**运算符支持矩阵**：

| 分类 | Python 运算符 | ExprOp | 说明 |
|------|-------------|--------|------|
| 算术 | `a + b` | `Add` | 加法 |
| 算术 | `a - b` | `Sub` | 减法 |
| 算术 | `a * b` | `Mul` | 乘法 |
| 算术 | `a // b` | `FloorDiv` | 整除（仅整数） |
| 算术 | `a % b` | `Mod` | 取模 |
| 位运算 | `a & b` | `BitAnd` | 按位与 |
| 位运算 | `a \| b` | `BitOr` | 按位或 |
| 位运算 | `a ^ b` | `BitXor` | 按位异或 |
| 位运算 | `a << b` | `Shl` | 左移 |
| 位运算 | `a >> b` | `Shr` | 右移 |
| 一元 | `-a` | `Neg` | 取负 |
| 一元 | `~a` | `Not` | 按位取反 |
| 比较 | `a == b` | `Eq` | 等于（VM 返回 0/1） |
| 比较 | `a != b` | `Ne` | 不等于 |
| 比较 | `a < b` | `Lt` | 小于 |
| 比较 | `a <= b` | `Le` | 小于等于 |
| 比较 | `a > b` | `Gt` | 大于 |
| 比较 | `a >= b` | `Ge` | 大于等于 |

> **不支持 `truediv`（`/`）**：结果可能为浮点数，VM 栈为 i64 不支持。
> 需要除法时用 `//`（FloorDiv）。
>
> **不支持 `and`/`or`**：Python 的 `and`/`or` 是短路求值，无法重载。
> 条件组合用嵌套 `IfThenElse` 或位运算（`&`/`|`）替代。

#### 2.3.4 表达式树示例

```python
count: int = field(Int8ub)
flag: int = field(Int8ub)
extra: bytes = field(Bytes(count + flag))
```

`count + flag` 展开过程：
1. `count` 取 `_FieldDescriptor(Int8ub)` 对象
2. `flag` 取 `_FieldDescriptor(Int8ub)` 对象
3. `count.__add__(flag)` → `_ExprRef(operator.add, count_desc, flag_desc)`

表达式树：
```
_ExprRef(add)
├── lhs: _FieldDescriptor("count")   → ExprOp::GetInt(0)
└── rhs: _FieldDescriptor("flag")    → ExprOp::GetInt(1)
```

编译后的 ExprOp 序列（后序遍历）：
```
[GetInt(0), GetInt(1), Add]
```

### 2.4 跨层引用：context= 参数（决策 4）

嵌套 Struct 的跨层引用用显式 `context=` 参数传递。

#### 2.4.1 外层注入

```python
@dataclass
class Outer(StructMixin):
    machine: int = field(Int16ub)
    section_count: int = field(Int8ub)
    sections: list = field(
        Array(section_count, Section),
        context={"machine": machine}  # 显式注入
    )
```

`context={"machine": machine}` 中的 `machine` 是 FieldRef，引用当前 Struct 的 `machine` 字段。
编译器将其翻译为 context injection map：`{inject_name: ExprProgram}`。

#### 2.4.2 内层接收

Section 内部用 `ContextParam` 构造器声明依赖：

```python
@dataclass
class Section(StructMixin):
    machine: int = rfield(ContextParam("machine"))  # 从注入的 context 取值
    offset: int = field(Int32ub)
    data: bytes = field(Bytes(machine * 4))  # 引用注入的 machine
```

`ContextParam("machine")` 的语义：
- **parse**：从 context 取 "machine" 的值（由外层注入），不从流读取
- **build**：从 context 取 "machine" 的值，不写流
- **sizeof**：返回 0（不占字节）

#### 2.4.3 context= 在编译期的处理

`_FieldDescriptor` 的 `_context_injections` 字段存储 `context=` 参数。

编译流程（详见 §3）：
1. 收集 `context={"machine": machine}` → `{inject_name: "machine", expr: FieldRef(machine)}`
2. 编译 expr 为 ExprProgram
3. 存入 StructNode 的字段元数据中

运行时（parse 方向）：
1. 解析到 sections 字段时，先求值所有 injection expressions
2. 创建子 Context（new_child），将注入值 `set_field` 到子 context
3. 将子 Context 传给 Array/StructRef 的 parse

运行时（build 方向）：
1. 类似，但从用户实例取值后求值 injection expressions
2. 创建子 Context，注入值

#### 2.4.4 ContextParam 构造器

```python
class ContextParam:
    """从注入的 context 取值的构造器。不读写流。

    与 Computed 的区别：
    - Computed(expr)：从当前 context 的表达式计算
    - ContextParam(name)：从父级注入的 context 取固定值

    典型用法：rfield(ContextParam("machine"))
    """
    __slots__ = ("name",)

    def __init__(self, name):
        self.name = name

    def __repr__(self):
        return "ContextParam({!r})".format(self.name)
```

`ContextParam` 是纯 Python 描述符（非 Rust pyclass），编译时翻译为 `ContextParamNode`。
完整的 Python 侧描述符定义见 §3.7.4。

### 2.5 构造器与 field 函数的组合（决策 7）

**分层原则**：field 函数管用户语义（谁填值、默认值是什么）；
构造器只管字节语义（怎么读、怎么写、怎么校验）。

#### 2.5.1 Python construct 构造器映射

| Python construct | 我们的处理 | 理由 |
|-----------------|-----------|------|
| `Default(subcon, value)` | `field(subcon, default=value)` | 纯用户语义，归 field 层 |
| `Const(value, subcon)` | `rfield(Const(subcon, value))` | 字节层有用——parse 时校验字节匹配 |
| `Computed(expr)` | `rfield(Computed(expr))` | 字节层有用——parse 时从 context 计算 |
| `Rebuild(subcon, expr)` | `rfield(subcon)` + 表达式系统 | build 时自动算，parse 时正常读 |
| `Tell` | `rfield(Tell())` | 记录流位置 |
| `Checksum(checksumfield, hashfunc, bytesfunc)` | `rfield(Checksum(...))` | Phase 3 实现 |

#### 2.5.2 使用示例

```python
@dataclass
class Packet(StructMixin):
    # RW 字段：build 要填，parse 能读
    count: int = field(Int8ub)
    data: bytes = field(Bytes(count))

    # RO 字段：build 不用填，parse 能读
    start: int = rfield(Tell())
    end: int = rfield(Tell())
    actual_length: int = rfield(Computed(end - start))
    magic: bytes = rfield(Const(Bytes(2), b"MZ"))  # parse 校验字节

    # WO 字段：build 要填，parse 读不到（padding）
    reserved: int = wfield(Int8ub, default=0)

    # 有 default 的 RW 字段：自动 kw_only
    version: int = field(Int8ub, default=1)
```

对应 `__init__` 签名：
```python
Packet(count, data, *, reserved=0, version=1)
# RO 字段（start/end/actual_length/magic）不在 __init__ 中
```

### 3.2 表达式收集

```python
def _compile_expressions(descriptors, field_index_map):
    """遍历所有字段的 subcon，编译其中的表达式。

    :param descriptors: [(name, _FieldDescriptor), ...]
    :param field_index_map: {id(descriptor): field_index}
    :return: {field_index: {param_name: ExprProgram}}
             ExprProgram 是 (ops_list, result_type) 元组
    """
    expr_programs = {}
    for idx, (name, desc) in enumerate(descriptors):
        subcon = desc.subcon
        field_exprs = _extract_and_compile_exprs(subcon, field_index_map, name)
        if field_exprs:
            expr_programs[idx] = field_exprs
    return expr_programs


def _extract_and_compile_exprs(subcon, field_index_map, field_name):
    """从 subcon 提取含表达式的参数，编译为 ExprProgram。

    通过 _expr_params 协议（§3.7.2）检测描述符中的表达式参数。
    每个实现了 _expr_params 的描述符返回 {param_name: value} 字典，
    其中 value 可以是 int/常量（不编译）或 FieldRef/ExprRef（编译）。

    :return: {param_name: ExprProgram} 或空 dict
    """
    result = {}

    # 通过 _expr_params 协议统一检测（覆盖所有描述符类型）
    # BytesDescriptor: {"length": <value>}
    # ComputedDescriptor: {"func": <expr>}
    # SwitchDescriptor: {"keyfunc": <expr>}
    # IfThenElseDescriptor: {"condfunc": <expr>}
    # ConstDescriptor/TellDescriptor/ContextParam: {} （无表达式参数）
    if hasattr(subcon, '_expr_params'):
        for param_name, param_value in subcon._expr_params.items():
            if isinstance(param_value, (_FieldDescriptor, _ExprRef)):
                ops = _compile_expr_tree(param_value, field_index_map, field_name)
                result[param_name] = ops
            # 常量值（int/bytes/str）不编译（留在描述符中供 Rust 侧读取）

    return result
```

### 3.3 表达式树翻译（后序遍历）

```python
# operator 函数 → ExprOp 名称的映射
_OP_TO_EXPROP = {
    operator.add: "add",
    operator.sub: "sub",
    operator.mul: "mul",
    operator.floordiv: "floordiv",
    operator.mod: "mod",
    operator.and_: "bitand",
    operator.or_: "bitor",
    operator.xor: "bitxor",
    operator.lshift: "shl",
    operator.rshift: "shr",
    operator.neg: "neg",
    operator.invert: "not",
    operator.eq: "eq",
    operator.ne: "ne",
    operator.lt: "lt",
    operator.le: "le",
    operator.gt: "gt",
    operator.ge: "ge",
}


def _compile_expr_tree(node, field_index_map, referencing_field_name):
    """将 FieldRef/ExprRef 树翻译为 ExprOp 指令列表（后序遍历）。

    :param node: _FieldDescriptor | _ExprRef | int | float
    :param field_index_map: {id(descriptor): field_index}
    :param referencing_field_name: 引用方字段名（用于错误信息）
    :return: list of ExprOp tuples, 如 [("getint", 0), ("getint", 1), ("add",)]
    :raises CompilationError: 字段引用未找到 / 不支持的节点类型
    """
    ops = []
    _emit_expr_ops(node, field_index_map, referencing_field_name, ops)
    return ops


def _emit_expr_ops(node, field_index_map, ref_name, ops):
    """递归遍历表达式树，后序发射 ExprOp 指令。"""
    if isinstance(node, _FieldDescriptor):
        # 字段引用：查 field_index_map
        idx = field_index_map.get(id(node))
        if idx is None:
            raise CompilationError(
                "字段引用未找到：字段 '{}' 引用了未知字段 '{}'"
                "。请检查拼写或确保被引用的字段在当前 Struct 中声明。".format(
                    ref_name, node.name or "<unnamed>"
                )
            )
        ops.append(("getint", idx))

    elif isinstance(node, _ExprRef):
        # 表达式节点：递归 lhs、rhs，然后发射操作符
        if node.op in (operator.neg, operator.invert):
            # 一元运算
            _emit_expr_ops(node.lhs, field_index_map, ref_name, ops)
            ops.append((_OP_TO_EXPROP[node.op],))
        else:
            # 二元运算
            _emit_expr_ops(node.lhs, field_index_map, ref_name, ops)
            _emit_expr_ops(node.rhs, field_index_map, ref_name, ops)
            op_name = _OP_TO_EXPROP.get(node.op)
            if op_name is None:
                raise CompilationError(
                    "不支持的表达式运算符：{}（在字段 '{}' 中）".format(node.op, ref_name)
                )
            ops.append((op_name,))

    elif isinstance(node, int):
        # 整数常量
        ops.append(("const", node))

    elif isinstance(node, float):
        raise CompilationError(
            "浮点常量不支持（VM 栈为 i64）。"
            "请使用整数表达式（在字段 '{}' 中）".format(ref_name)
        )

    else:
        raise CompilationError(
            "不支持的表达式节点类型 {}：{!r}（在字段 '{}' 中）".format(
                type(node).__name__, node, ref_name
            )
        )
```

### 3.4 编译期验证

#### 3.4.1 字段名存在性检查

`_emit_expr_ops` 中 `field_index_map.get(id(node))` 返回 `None` 时立即抛
`CompilationError`。这覆盖了：

- **拼写错误**：`Bytes(cout)` 中 `cout` 不是已声明的 descriptor → id 查不到 → 报错
- **前向引用**：`Bytes(later_field)` 中 `later_field` 尚未声明（类体从上到下执行，
  `later_field` 的 descriptor 还不存在）→ 引用的是 Python 的 `NameError` 或未定义变量

#### 3.4.2 循环引用检测

表达式只能引用**前序**字段（声明顺序在当前字段之前的字段）。

```python
def _check_forward_reference(expr_ops, current_field_index, ref_name):
    """检查表达式中是否引用了后序字段（前向引用）。

    parse 方向只能引用已解析的前序字段。引用后序字段是逻辑错误。
    """
    for op in expr_ops:
        if op[0] == "getint" and op[1] >= current_field_index:
            raise CompilationError(
                "字段 '{}' 的表达式引用了后序字段（索引 {} >= {}）。"
                "表达式只能引用在当前字段之前声明的字段。".format(
                    ref_name, op[1], current_field_index
                )
            )
```

> **注意**：此检查在 `_compile_expr_tree` 后调用，对每个字段的表达式验证。

#### 3.4.3 类型兼容性

Phase 2 不做静态类型检查（Python 动态类型限制）。运行时 `eval_expr` 的 `GetInt` 操作
从 PyDict 取值并 `extract::<i64>()`，类型不匹配时返回 `ConstructError::ExprType`。

#### 3.4.4 WO 字段引用禁止（方案 A）

**设计决策**：表达式**不允许引用 WO 字段**。编译期检测到 `getint` 指令引用 WO 字段时，
立即抛出 `CompilationError`。

**理由**：
- WO 字段的实际用途是 padding/reserved byte，被表达式引用的场景极少
- WO 字段不写入 context（§5.3 方案 A），因此表达式运行时无法取到 WO 字段的值
- 编译期禁止引用 WO 字段是合理的约束（类似前向引用禁止）
- 这使 dict 复用优化（dict = ctx.fields 同一对象）无矛盾地保留

```python
def _check_wo_reference(expr_ops, descriptors, ref_name):
    """检查表达式中是否引用了 WO 字段。

    WO 字段不写入 context（方案 A），表达式运行时无法取到其值。
    引用 WO 字段是逻辑错误，编译期拒绝。

    :param expr_ops: 编译后的 ExprOp 指令列表
    :param descriptors: [(name, _FieldDescriptor), ...] 完整字段列表
    :param ref_name: 引用方字段名（用于错误信息）
    """
    wo_indices = {
        idx for idx, (_, desc) in enumerate(descriptors) if desc.mode == "wo"
    }
    for op in expr_ops:
        if op[0] == "getint" and op[1] in wo_indices:
            wo_name = descriptors[op[1]][0]
            raise CompilationError(
                "字段 '{}' 的表达式引用了 WO 字段 '{}'。"
                "WO 字段（padding/reserved）不写入 context，"
                "表达式无法引用。如需引用，请将该字段改为 field() 或 rfield()。".format(
                    ref_name, wo_name
                )
            )
```

> **注意**：此检查在 `_compile_expr_tree` 后调用，与 `_check_forward_reference` 并行执行。
> 两者共同保证表达式只引用前序的 RW/RO 字段。

### 3.5 编译产物传给 Rust

表达式编译产物（ExprOp 列表）随 descriptor 一起传给 Rust `compile_schema`：

```python
def _compile_schema_for_class(cls, descriptors, expr_programs):
    """Phase 2 扩展：传入 mode 和 expr_programs。"""
    field_names = [name for name, _ in descriptors]
    subcons = [desc.subcon for _, desc in descriptors]
    modes = [desc.mode for _, desc in descriptors]
    defaults = [desc.default for _, desc in descriptors]
    context_injections = [desc._context_injections for _, desc in descriptors]

    # expr_programs: {field_index: {param_name: [(op_name, *args), ...]}}
    # 序列化为 Rust 可解析的格式
    cls._construct_compiled = _compile_schema(
        cls=cls,
        field_names=field_names,
        descriptors=subcons,
        modes=modes,
        defaults=defaults,
        context_injections=context_injections,
        expr_programs=expr_programs,  # 新增
    )
```

Rust 侧 `compile_schema` 接收 `expr_programs` 参数，解析 ExprOp 元组列表为
`Vec<ExprOp>`，存入对应的 Node（如 `BytesNode.length = BytesLength::Expr(ExprProgram)`）。

### 3.7 Python 侧描述符与构造器扩展设计

> **本节解决 MUST-FIX-2**：明确 Python 侧 `Bytes()` 如何接受表达式参数，
> 以及新增构造器（Tell/Computed/Const/Switch/IfThenElse/ContextParam）
> 的 Python 侧定义方式。

### 3.7.1 设计原则

1. **描述符仍为 `#[pyclass(frozen)]`（不可变）**：与 Phase 1 一致。
   用户在 Python 侧创建描述符对象，Rust 侧编译（compile_schema）。
2. **两种描述符形态并存**：
   - **Rust pyclass 描述符**（`BytesDescriptor`、`FormatFieldDescriptor`、`GreedyBytesDescriptor`）：
     由 Rust 定义，通过 pyo3 暴露给 Python，支持 `extract` 类型识别。
   - **纯 Python 描述符**（`TellDescriptor`、`ComputedDescriptor`、`ConstDescriptor`、
     `SwitchDescriptor`、`IfThenElseDescriptor`、`ContextParam`）：
     由 Python 定义（`__slots__` 类），compile_schema 通过 `hasattr` + duck typing 识别。
3. **尽量复用 Phase 1 的 pyclass 模式**，减少 Python↔Rust 边界。
4. **表达式参数通过 `_expr_params` 协议暴露**：每个可能含表达式的描述符
   实现 `_expr_params` 属性，返回 `{param_name: value}` 字典。
   compile_schema 的 Python 包装层（`_extract_and_compile_exprs`）读取此属性。

### 3.7.2 `_expr_params` 协议

`_expr_params` 是描述符暴露"可能含表达式的参数"的标准协议：

```python
class _ExprParamsProtocol:
    """协议定义（仅为文档说明，非真实基类）。

    任何可能含表达式参数的描述符应实现 _expr_params 属性，
    返回 {param_name: value} 字典。

    value 可以是：
    - int/常量：不编译，留在描述符中
    - _FieldDescriptor：编译为 [GetInt(idx)]
    - _ExprRef：编译为后序遍历指令序列
    """

    @property
    def _expr_params(self):
        """返回可能含表达式的参数字典。"""
        raise NotImplementedError
```

**协议约定**：

| 描述符 | `_expr_params` 返回值 | 说明 |
|--------|----------------------|------|
| `BytesDescriptor` | `{"length": value}` | value 是 int（常量）或 FieldRef/ExprRef |
| `ComputedDescriptor` | `{"func": expr}` | expr 是 FieldRef/ExprRef |
| `SwitchDescriptor` | `{"keyfunc": expr}` | expr 是 FieldRef/ExprRef 或常量 int |
| `IfThenElseDescriptor` | `{"condfunc": expr}` | expr 是 FieldRef/ExprRef |
| `ConstDescriptor` | `{}` | 无表达式参数（value 是常量） |
| `TellDescriptor` | `{}` | 无参数 |
| `ContextParam` | `{}` | 无表达式参数 |
| `FormatFieldDescriptor` | 无此属性 | 不实现协议（无表达式参数） |

`_extract_and_compile_exprs`（§3.2）通过 `hasattr(subcon, '_expr_params')` 检测，
然后遍历字典中的每个值，对 `_FieldDescriptor`/`_ExprRef` 类型的值编译为 ExprProgram。

### 3.7.3 `Bytes()` 扩展：接受表达式长度

**问题**：Phase 1 的 `BytesDescriptor` 是 `#[pyclass(frozen)]` + `#[new] fn new(length: usize)`，
只接受 `usize`。Phase 2 需要接受 `int`（常量）或 `_FieldDescriptor`/`_ExprRef`（表达式）。

**方案：修改 Rust pyclass 的 `length` 字段类型为 `Py<PyAny>`**

```rust
/// Phase 2 扩展：Bytes 描述符。
///
/// length 可以是：
/// - Python int → 常量长度（BytesLength::Const）
/// - _FieldDescriptor / _ExprRef → 表达式长度（BytesLength::Expr）
///
/// 通过 _expr_params 协议暴露表达式参数供编译器检测。
#[pyclass(frozen, name = "BytesDescriptor", module = "construct")]
#[derive(Debug)]
pub struct BytesDescriptor {
    /// Python 可见属性：长度参数（int 或表达式对象）。
    #[pyo3(get)]
    pub length: Py<PyAny>,
}

#[pymethods]
impl BytesDescriptor {
    /// 创建一个 Bytes 描述符。
    ///
    /// Python 用法：
    /// - `Bytes(4)` → 常量长度
    /// - `Bytes(count)` → 表达式长度（count 是 _FieldDescriptor）
    /// - `Bytes(count + flag)` → 表达式长度（count + flag 是 _ExprRef）
    #[new]
    fn new(length: Py<PyAny>) -> Self {
        Self { length }
    }

    /// 暴露表达式参数供编译器检测。
    /// compile_schema 的 Python 包装层通过 getattr 读取此属性。
    #[getter]
    fn _expr_params(&self, py: Python<'_>) -> Py<PyDict> {
        let dict = PyDict::new_bound(py);
        dict.set_item("length", self.length.bind(py)).unwrap();
        dict.into_any().unbind()
    }

    fn __repr__(&self, py: Python<'_>) -> String {
        format!("BytesDescriptor(length={:?})", self.length.bind(py))
    }
}
```

**Python 侧无变化**：用户代码 `Bytes(4)` / `Bytes(count)` / `Bytes(count + flag)` 不变。
pyo3 的 `#[new]` 接受 `Py<PyAny>`，Python 侧传入 int 或 _FieldDescriptor/_ExprRef 均可。

**compile_schema 中的处理**：


`build_node_from_descriptor` 的识别优先级扩展为：

```rust
fn build_node_from_descriptor(
    py: Python<'_>,
    desc: &Bound<'_, PyAny>,
    expr_programs: &ExprProgramMap,  // 新增参数
) -> Result<Node, ConstructError> {
    // 1. FormatFieldDescriptor → Node::FormatField（Phase 1 不变）
    if let Ok(fmt) = desc.extract::<Py<FormatFieldDescriptor>>() { ... }

    // 2. BytesDescriptor → Node::Bytes（Phase 2 扩展：支持表达式长度）
    if let Ok(b) = desc.extract::<Py<BytesDescriptor>>() {
        let b_ref = b.bind(py).get();
        let length_obj = b_ref.length.bind(py);

            return Ok(Node::Bytes(BytesNode::new_const(n)));
        }

        let program = expr_programs.get("length")?;
        return Ok(Node::Bytes(BytesNode::new_expr(program)));
    }

    // 3. GreedyBytesDescriptor → Node::GreedyBytes（Phase 1 不变）
    if desc.extract::<Py<GreedyBytesDescriptor>>().is_ok() { ... }

    // 4. StructMixin 子类 → Node::StructRef（Phase 1 不变）
    ...

    // 5. 纯 Python 描述符（按类型名识别）
    let type_name = desc.get_type().name()?.to_str()?;
    match type_name {
        "TellDescriptor" => Ok(Node::Tell(TellNode)),
        "ComputedDescriptor" => {
            let program = expr_programs.get("func")?;
            Ok(Node::Computed(ComputedNode { expr: program }))
        }
        "ConstDescriptor" => {
            let subcon = desc.getattr("subcon")?;
            let inner = Box::new(build_node_from_descriptor(py, &subcon, &empty_map)?);
            let value = desc.getattr("value")?.clone().unbind();
            Ok(Node::Const(ConstNode { inner, expected: value }))
        }
        "SwitchDescriptor" => {
            let selector = expr_programs.get("keyfunc")?;
            let cases = compile_switch_cases(py, desc)?;
            let default = compile_switch_default(py, desc)?;
            Ok(Node::Switch(SwitchNode { selector, cases, default }))
        }
        "IfThenElseDescriptor" => {
            let cond = expr_programs.get("condfunc")?;
            let then_branch = ...;
            let else_branch = ...;
            Ok(Node::IfThenElse(IfThenElseNode { cond, then_branch, else_branch }))
        }
        "ContextParam" => {
            let name_obj = desc.getattr("name")?;
            let name = intern_string(py, name_obj)?;
            Ok(Node::ContextParam(ContextParamNode { name }))
        }
        _ => Err(ConstructError::Compilation { ... })
    }
```

### 3.7.6 compile_schema 签名扩展

Phase 1 的 `compile_schema` 签名为：
```python
compile_schema(cls, field_names: list[str], descriptors: list) -> CompiledSchema
```

Phase 2 扩展为：
```python
compile_schema(
    cls,
    field_names: list[str],
    descriptors: list,
    modes: list[str],             # 新增：["rw", "ro", "wo", ...]

```

**expr_programs 的数据结构**：

```python
# expr_programs 是嵌套字典：
# {
#   field_index: {
#       "param_name": [("getint", 0), ("getint", 1), ("add",)]
#   }
# }
#
# field_index 是该字段在 fields 列表中的序号
# param_name 是 _expr_params 中的 key（如 "length"、"func"、"keyfunc"、"condfunc"）
# 值是 ExprOp 元组列表（后序遍历产生，详见 §3.3）
#
# compile_schema 的 Rust 侧将元组列表解析为 Vec<ExprOp>，构建 ExprProgram
```

**Rust 侧 compile_schema 接收方式**：

```rust

    ...
```

### 3.7.7 描述符→Node 映射中的表达式参数处理

compile_schema 构建 Node 时，对每个字段：

1. **从 expr_programs 查找该字段的编译结果**：
   ```python
   field_exprs = expr_programs.get(field_index, {})
   # field_exprs: {"length": [expr_ops], "func": [expr_ops], ...}
   ```

2. **传递给 build_node_from_descriptor**：
   - Rust 侧 `build_node_from_descriptor` 接收 `ExprProgramMap`
   - `ExprProgramMap` 是 `{param_name: Vec<ExprOp>}` 的封装
   - 构建 Node 时从 Map 中取对应 param 的 ExprOp 列表

3. **Node 构建**：
   - `BytesDescriptor` + `expr_programs["length"]` → `BytesNode::new_expr(program)`
   - `ComputedDescriptor` + `expr_programs["func"]` → `ComputedNode { expr: program }`
   - `SwitchDescriptor` + `expr_programs["keyfunc"]` → `SwitchNode { selector: program, ... }`
   - `IfThenElseDescriptor` + `expr_programs["condfunc"]` → `IfThenElseNode { cond: program, ... }`

4. **无表达式的描述符**（FormatField、Const value、Tell、ContextParam）：
   - expr_programs 中无对应条目
   - 直接从描述符属性读取常量值

### 3.7.8 与 Phase 1 的兼容性

| Phase 1 行为 | Phase 2 影响 | 兼容性保证 |
|-------------|-------------|-----------|
| `BytesDescriptor(length: usize)` | `length: Py<PyAny>` | ✅ Python 侧 `Bytes(4)` 仍传 int，Rust 侧 extract::<usize> 成功 |
| `BytesDescriptor` 是 Copy | 非 Copy（Py<PyAny>） | ✅ frozen 保证不可变；Copy 仅用于内部优化，不影响正确性 |
| compile_schema 3 参数 | 7 参数（4 个有默认值） | ✅ Phase 1 调用方式不传新参数，默认值等价于 Phase 1 行为 |
| build_node_from_descriptor 无 expr 参数 | 新增 expr_programs 参数 | ✅ 对无表达式的描述符，expr_programs 为空 Map |

## 4. Rust 执行模型

### 4.1 ExprOp 指令集

```rust
/// 表达式 VM 指令。编译期由 FieldRef/ExprRef 树后序遍历产生。
/// 运行时由 [`eval_expr_int`] 在 Rust 内部栈式执行，零 FFI。
///
/// VM 栈统一为 `i64`，覆盖长度、计数、偏移量等整数场景。
/// 非 整数引用（如 Switch 的字符串 key）走单独路径（直接从 Context get_field）。
#[derive(Debug, Clone, Copy)]
pub enum ExprOp {
    /// 从 context 取整数字段值，压入栈顶。
    /// `idx` 是字段在当前 StructNode 中的声明序号（编译期确定）。
    /// 执行：ctx.get_int(idx, py) → stack.push(i64)
    GetInt(usize),

    /// 压入编译期常量整数。
    Const(i64),

    // --- 算术运算（二元，弹出栈顶两个 a/b，压入结果）---
    /// 栈顶弹出 b、a，压入 a + b（wrapping_add，对齐 Python 无溢出异常语义）。
    Add,
    /// 栈顶弹出 b、a，压入 a - b（wrapping_sub）。
    Sub,
    /// 栈顶弹出 b、a，压入 a * b（wrapping_mul）。
    Mul,
    /// 栈顶弹出 b、a，压入 a / b（整除，b==0 返回 Err）。
    FloorDiv,
    /// 栈顶弹出 b、a，压入 a % b（b==0 返回 Err）。
    Mod,

    // --- 位运算（二元）---
    /// 栈顶弹出 b、a，压入 a & b。
    BitAnd,
    /// 栈顶弹出 b、a，压入 a | b。
    BitOr,
    /// 栈顶弹出 b、a，压入 a ^ b。
    BitXor,
    /// 栈顶弹出 b、a，压入 a << b。
    Shl,
    /// 栈顶弹出 b、a，压入 a >> b。
    Shr,

    // --- 一元运算 ---
    /// 栈顶弹出 a，压入 -a（wrapping_neg）。
    Neg,
    /// 栈顶弹出 a，压入 !a（按位取反）。
    Not,

    // --- 比较运算（二元，弹出 a/b，压入 0 或 1）---
    /// 栈顶弹出 b、a，压入 (a == b) as i64。
    Eq,
    /// 栈顶弹出 b、a，压入 (a != b) as i64。
    Ne,
    /// 栈顶弹出 b、a，压入 (a < b) as i64。
    Lt,
    /// 栈顶弹出 b、a，压入 (a <= b) as i64。
    Le,
    /// 栈顶弹出 b、a，压入 (a > b) as i64。
    Gt,
    /// 栈顶弹出 b、a，压入 (a >= b) as i64。
    Ge,
}
```

### 4.2 ExprProgram

```rust
/// 编译后的表达式程序：指令序列 + 求值所需的最大栈深度。
///
/// 存储在 Node 中（如 BytesNode、ComputedNode、SwitchNode），parse/build 时
/// 传给 [`eval_expr_int`] 求值。
#[derive(Debug, Clone)]
pub struct ExprProgram {
    /// 指令序列（后序遍历产生）。
    ops: Vec<ExprOp>,
    /// 最大栈深度（编译期计算，用于 `Vec::with_capacity` 预分配，避免运行时扩容）。
    max_stack: usize,
}

impl ExprProgram {
    /// 从 ExprOp 列表构建，自动计算 max_stack。
    pub fn new(ops: Vec<ExprOp>) -> Self {
        let max_stack = compute_max_stack(&ops);
        Self { ops, max_stack }
    }

    /// 空表达式（常用于无表达式的兼容路径）。
    pub fn empty() -> Self {
        Self { ops: Vec::new(), max_stack: 0 }
    }

    /// 返回是否为空程序（无表达式）。
    pub fn is_empty(&self) -> bool {
        self.ops.is_empty()
    }

    /// 返回指令序列引用。
    pub fn ops(&self) -> &[ExprOp] {
        &self.ops
    }

    /// 返回预计算的栈深度。
    pub fn max_stack(&self) -> usize {
        self.max_stack
    }
}

/// 编译期计算表达式所需的最大栈深度。
/// 模拟执行指令序列，追踪栈高度峰值。
fn compute_max_stack(ops: &[ExprOp]) -> usize {
    let mut depth = 0usize;
    let mut max = 0usize;
    for op in ops {
        match op {
            ExprOp::GetInt(_) | ExprOp::Const(_) => {
                depth += 1;
                if depth > max { max = depth; }
            }
            // 二元运算：弹 2 压 1，净减 1
            ExprOp::Add | ExprOp::Sub | ExprOp::Mul | ExprOp::FloorDiv | ExprOp::Mod
            | ExprOp::BitAnd | ExprOp::BitOr | ExprOp::BitXor | ExprOp::Shl | ExprOp::Shr
            | ExprOp::Eq | ExprOp::Ne | ExprOp::Lt | ExprOp::Le | ExprOp::Gt | ExprOp::Ge => {
                depth = depth.saturating_sub(1);
            }
            // 一元运算：弹 1 压 1，净不变
            ExprOp::Neg | ExprOp::Not => {}
        }
    }
    max
}
```

### 4.3 VM 求值器

```rust
use crate::context::Context;
use crate::error::ConstructError;
use pyo3::prelude::*;

/// 在 Rust 内部栈式求值表达式，零 FFI（GetInt 除外，需从 PyDict 取值）。
///
/// # 参数
///
/// - `program`: 编译后的表达式程序
/// - `names`: interned 字段名列表（与 StructNode.fields 对齐），GetInt(idx) 用此取值
/// - `ctx`: 当前上下文（持有 PyDict）
/// - `py`: GIL token
///
/// # 返回
///
/// 求值结果（i64）。栈底应恰好剩一个值。
///
/// # 错误
///
/// - `ExprType`: GetInt 取到的值无法 extract 为 i64
/// - `ExprStack`: 栈下溢（指令序列不合法，理论上编译期保证不会发生）
/// - `ExprDivByZero`: FloorDiv / Mod 除数为 0
pub fn eval_expr_int(
    program: &ExprProgram,
    names: &[Py<PyString>],
    ctx: &Context<'_>,
    py: Python<'_>,
) -> Result<i64, ConstructError> {
    if program.is_empty() {
        return Err(ConstructError::Generic {
            message: "eval_expr_int: empty expression program".to_string(),
            path: String::new(),
        });
    }

    let mut stack: Vec<i64> = Vec::with_capacity(program.max_stack());

    for op in program.ops() {
        match op {
            ExprOp::GetInt(idx) => {
                let val = ctx.get_int_by_name(names[*idx].bind(py), py)?;
                stack.push(val);
            }
            ExprOp::Const(v) => {
                stack.push(*v);
            }
            // 二元算术
            ExprOp::Add => binop(&mut stack, i64::wrapping_add)?,
            ExprOp::Sub => binop(&mut stack, i64::wrapping_sub)?,
            ExprOp::Mul => binop(&mut stack, i64::wrapping_mul)?,
            ExprOp::FloorDiv => {
                let (a, b) = pop2(&mut stack)?;
                if b == 0 {
                    return Err(ConstructError::ExprDivByZero {
                        message: "expression division by zero".to_string(),
                    });
                }
                stack.push(a.wrapping_div(b));
            }
            ExprOp::Mod => {
                let (a, b) = pop2(&mut stack)?;
                if b == 0 {
                    return Err(ConstructError::ExprDivByZero {
                        message: "expression modulo by zero".to_string(),
                    });
                }
                stack.push(a.wrapping_rem(b));
            }
            // 位运算
            ExprOp::BitAnd => binop(&mut stack, |a, b| a & b)?,
            ExprOp::BitOr => binop(&mut stack, |a, b| a | b)?,
            ExprOp::BitXor => binop(&mut stack, |a, b| a ^ b)?,
            ExprOp::Shl => binop(&mut stack, |a, b| a.wrapping_shl(b as u32))?,
            ExprOp::Shr => binop(&mut stack, |a, b| a.wrapping_shr(b as u32))?,
            // 一元
            ExprOp::Neg => {
                let a = stack.pop().ok_or(ConstructError::ExprStackUnderflow)?;
                stack.push(a.wrapping_neg());
            }
            ExprOp::Not => {
                let a = stack.pop().ok_or(ConstructError::ExprStackUnderflow)?;
                stack.push(!a);
            }
            // 比较
            ExprOp::Eq => cmp(&mut stack, |a, b| a == b)?,
            ExprOp::Ne => cmp(&mut stack, |a, b| a != b)?,
            ExprOp::Lt => cmp(&mut stack, |a, b| a < b)?,
            ExprOp::Le => cmp(&mut stack, |a, b| a <= b)?,
            ExprOp::Gt => cmp(&mut stack, |a, b| a > b)?,
            ExprOp::Ge => cmp(&mut stack, |a, b| a >= b)?,
        }
    }

    stack.pop().ok_or(ConstructError::ExprStackUnderflow)
}

/// 弹出栈顶两个元素 (a, b)，注意顺序：先弹出的是 rhs(b)，后弹出的是 lhs(a)。
fn pop2(stack: &mut Vec<i64>) -> Result<(i64, i64), ConstructError> {
    let b = stack.pop().ok_or(ConstructError::ExprStackUnderflow)?;
    let a = stack.pop().ok_or(ConstructError::ExprStackUnderflow)?;
    Ok((a, b))
}

/// 二元运算辅助：弹出 (a, b)，压入 f(a, b)。
fn binop<F>(stack: &mut Vec<i64>, f: F) -> Result<(), ConstructError>
where
    F: FnOnce(i64, i64) -> i64,
{
    let (a, b) = pop2(stack)?;
    stack.push(f(a, b));
    Ok(())
}

/// 比较运算辅助：弹出 (a, b)，压入 f(a, b) as i64（0 或 1）。
fn cmp<F>(stack: &mut Vec<i64>, f: F) -> Result<(), ConstructError>
where
    F: FnOnce(i64, i64) -> bool,
{
    let (a, b) = pop2(stack)?;
    stack.push(if f(a, b) { 1 } else { 0 });
    Ok(())
}
```

```rust
///
/// parse 返回当前 ParseStream 的读取位置（usize → PyLong）。

        let pos = stream.tell();
        Ok(pos.into_py(py))  // usize → PyLong
    }

    fn build(&self, py, _obj, stream, _ctx, _path) -> Result<(), ConstructError> {
        // Tell 在 build 方向不写字节，只返回位置（位置由上层处理）
```

#### 4.6.3 ConstNode

```rust
/// 常量校验。对应 Python construct 的 Const(value, subcon)。
///
/// parse：用 inner 解析，校验结果 == expected。
/// build：用 expected 构建（不从实例取值，因为是 RO）。
#[derive(Debug)]
pub struct ConstNode {
    /// 被包装的子节点（读取/写入字节的构造器）。
    inner: Box<Node>,
    /// 预期值（编译期常量 PyObject）。
    expected: Py<PyAny>,
}

impl Construct for ConstNode {
    fn parse(&self, py, stream, ctx, path) -> Result<Py<PyAny>, ConstructError> {
        let obj = self.inner.parse(py, stream, ctx, path)?;
        // 校验 obj == expected（Python == 比较）
        let expected = self.expected.bind(py);
        let obj_bound = obj.bind(py);
        let eq = obj_bound
            .eq(expected)
            .map_err(|e| ConstructError::Generic {
                message: format!("Const comparison failed: {}", e),
                path: String::new(),
            })?;
        if !eq {
            return Err(ConstructError::ConstMismatch {
                expected: format!("{:?}", expected),
                actual: format!("{:?}", obj_bound),
            });
        }
        Ok(obj)
    }

    fn build(&self, py, _obj, stream, ctx, path) -> Result<(), ConstructError> {
        // RO：用 expected 构建，不从实例取值
        let expected = self.expected.bind(py);
        self.inner.build(py, expected, stream, ctx, path)
    }

    fn sizeof(&self, ctx) -> Result<usize, ConstructError> {
        self.inner.sizeof(ctx)
    }
}
```

#### 4.6.4 SwitchNode

```rust
/// 条件分支。对应 Python construct 的 Switch(keyfunc, cases)。
///
/// parse：求值 selector → 从 cases 查找 → 委托对应 Node 的 parse。
#[derive(Debug)]
pub struct SwitchNode {
    /// 选择器表达式（求值为整数 key）。
    selector: ExprProgram,
    /// cases：整数 key → Node。编译期从 Python dict 构建。
    cases: Vec<(i64, Node)>,
    /// 默认节点（可选，对应 Switch 的 default 参数）。
    default: Option<Box<Node>>,
}

impl Construct for SwitchNode {
    fn parse(&self, py, stream, ctx, path) -> Result<Py<PyAny>, ConstructError> {
        let names = ctx.field_names();
        let key = eval_expr_int(&self.selector, names, ctx, py)?;
        let node = self.cases
            .iter()
            .find(|(k, _)| *k == key)
            .map(|(_, n)| n)
            .or(self.default.as_deref())
            .ok_or_else(|| ConstructError::SwitchNoCase { key })?;
        node.parse(py, stream, ctx, path)
    }

    fn build(&self, py, obj, stream, ctx, path) -> Result<(), ConstructError> {
        let names = ctx.field_names();
        let key = eval_expr_int(&self.selector, names, ctx, py)?;
        let node = self.cases
            .iter()
            .find(|(k, _)| *k == key)
            .map(|(_, n)| n)
            .or(self.default.as_deref())
            .ok_or_else(|| ConstructError::SwitchNoCase { key })?;
        node.build(py, obj, stream, ctx, path)
    }

    fn sizeof(&self, ctx) -> Result<usize, ConstructError> {
        // Switch 的 sizeof 取决于运行时 key，编译期无法确定。
        // 若所有 case 的 sizeof 相同，返回该值；否则返回 Err。
        let mut sizes: Vec<usize> = Vec::new();
        for (_, node) in &self.cases {
            sizes.push(node.sizeof(ctx)?);
        }
        if let Some(d) = &self.default {
            sizes.push(d.sizeof(ctx)?);
        }
        if sizes.windows(2).all(|w| w[0] == w[1]) {
            Ok(sizes[0])
        } else {
            Err(ConstructError::Generic {
                message: "Switch has cases with different sizes".to_string(),
                path: String::new(),
            })
        }
    }
}
```

### 4.7 BytesNode 扩展

Phase 1 的 `BytesNode` 只支持常量长度。Phase 2 扩展为支持表达式长度：

```rust
/// Bytes 的长度来源。
#[derive(Debug, Clone)]
pub enum BytesLength {
    /// 固定长度（Phase 1 兼容）。
    Const(usize),
    /// 表达式长度（Phase 2 新增）。parse/build 时求值为 usize。
    Expr(ExprProgram),
}

#[derive(Debug)]
pub struct BytesNode {
    /// 长度来源：常量或表达式。
    length: BytesLength,
}

impl BytesNode {
    /// Phase 1 兼容构造器：固定长度。
    pub fn new_const(length: usize) -> Self {
        Self { length: BytesLength::Const(length) }
    }

    /// Phase 2 新增：表达式长度。
    pub fn new_expr(program: ExprProgram) -> Self {
        Self { length: BytesLength::Expr(program) }
    }
}

impl Construct for BytesNode {
    fn parse(&self, py, stream, ctx, path) -> Result<Py<PyAny>, ConstructError> {
        let length = match &self.length {
            BytesLength::Const(n) => *n,
            BytesLength::Expr(prog) => {
                let names = ctx.field_names();
                let n = eval_expr_int(prog, names, ctx, py)?;
                if n < 0 {
                    return Err(ConstructError::FieldLength {
                        message: format!("Bytes length expression evaluated to negative: {}", n),
                    });
                }
                n as usize
            }
        };
        let data = stream.read(length, path)?;
        Ok(PyBytes::new_bound(py, data).into_any().unbind())
    }

    fn build(&self, py, obj, stream, ctx, path) -> Result<(), ConstructError> {
        let data: &[u8] = obj.extract().map_err(|_| ConstructError::FieldLength {
            message: "Bytes build expects bytes-like object".to_string(),
        })?;
        // 对齐 Python construct：Bytes._build（core.py:969-973）计算 length 后调用
        // stream_write(stream, data, length, path)，stream_write（core.py:194-195）
        // 校验 len(data) == length，不匹配抛 StreamError。因此 build 必须求值期望
        // 长度并校验，不能直接写。
        // 注：原设计文档（2026-06 P2 前）误判为"Python 不校验，直接写"，已修正。
        let expected = match &self.length {
            BytesLength::Const(n) => *n,
            BytesLength::Expr(prog) => {
                let names = ctx.field_names();
                let n = eval_expr_int(prog, names, ctx, py)?;
                if n < 0 {
                    return Err(ConstructError::FieldLength {
                        message: format!("Bytes length expression evaluated to negative: {}", n),
                    });
                }
                n as usize
            }
        };
        if data.len() != expected {
            return Err(ConstructError::FieldLength {
                message: format!(
                    "bytes object of wrong length, expected {}, found {}",
                    expected,
                    data.len()
                ),
            });
        }
        stream.write(data);
        Ok(())
    }

    fn sizeof(&self, ctx: &Context<'_>) -> Result<usize, ConstructError> {
        match &self.length {
            BytesLength::Const(n) => Ok(*n),
            BytesLength::Expr(prog) => {
                // sizeof 需要求值表达式，但 sizeof 签名不接收 py/ctx mutably。
                // 设计决策：含表达式的 Bytes 的 sizeof 返回 Err，因为 sizeof 在编译期
                // 无法求值（需要 context + Python GIL）。需要运行时大小的场景（如 Prefixed）
                // 走 parse/build 路径。
                //
                // 错误类型：使用 `Generic`（携带 path），而非 SizeofError。
                // 原因：error.rs 中没有 SizeofError 变体（参见 greedy_bytes.rs:93 先例：
                // "我们的错误枚举无 SizeofError 变体，使用 Generic 表示大小未知"）。
                // Python construct 的 SizeofError 在 Python 侧映射，Rust 内部统一用 Generic。
                let _ = prog;
                let _ = ctx;
                Err(ConstructError::Generic {
                    message: "Bytes with expression length has no static size".to_string(),
                    path: String::new(),
                })
            }
        }
    }
}
```

## 5. StructNode 改造

### 5.1 改造目标

StructNode 需要支持：
1. **三种 mode**（RW/RO/WO）在 parse/build 路径的行为差异
2. **Context 恢复**（Phase 1 placeholder → Phase 2 new_root + set_field）
3. **RO 字段的值获取**（不从实例 getattr，而是执行表达式/构造器逻辑）

### 5.2 StructField 结构

Phase 1 的 `fields: Vec<(FieldName, Node)>` 扩展为携带 mode 信息：

```rust
/// 字段模式：RW（读写）、RO（只读）、WO（只写）。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FieldMode {
    /// 读写：build 从实例取值，parse 存入实例。
    Rw,
    /// 只读：build 自动计算（不从实例取值），parse 存入实例。
    Ro,
    /// 只写：build 从实例取值，parse 不存入实例（丢弃）。
    Wo,
}

/// StructNode 的单个字段：携带模式信息。
#[derive(Debug)]
pub struct StructField {
    /// 字段名（interned PyString + Rust String）。
    pub name: FieldName,
    /// 子节点。
    pub node: Node,
    /// 字段模式（RW/RO/WO）。
    pub mode: FieldMode,
    /// 该字段引用的所有字段名（编译期从 ExprProgram 提取，用于前向引用检查）。
    /// 仅用于编译期校验，运行时不使用。
    pub references: Vec<usize>,
}

#[derive(Debug)]
pub struct StructNode {
    /// 有序字段列表（携带模式）。
    fields: Vec<StructField>,
    /// 用户类引用。
    cls: Py<PyType>,
    /// 编译期检测：类是否定义了 __post_init__。
    has_post_init: bool,
    /// 字段数（用于 PyDict 预分配）。
    field_count: usize,
    /// 该 Struct 是否含有表达式（决定 parse/build 入口用 new_root 还是 placeholder）。
    /// 无表达式 → placeholder（Phase 1 性能优化保留）
    /// 有表达式 → new_root
    has_expressions: bool,
}
```

### 5.3 parse 路径改造（三种 mode）

```rust
impl Construct for StructNode {
    fn parse(&self, py, stream, ctx, path) -> Result<Py<PyAny>, ConstructError> {
        // 方案 B' 步骤 1：创建独立 dict。
        // Phase 2 优化：若 has_expressions，复用 ctx 的 dict 作为 instance dict
        // （零额外 PyDict 创建开销）。
        let dict = if self.has_expressions {
            // 有表达式：从 ctx 获取 dict 引用（复用）
            // ctx.fields() 返回 &Bound<PyDict>
            ctx.fields().expect("context must have dict for expression struct").clone_ref(py)
        } else {
            // 无表达式：新建 dict（Phase 1 行为）
            PyDict::new_bound(py).into_any().unbind().downcast_into::<PyDict>().unwrap()
        };

        // 方案 B' 步骤 2：逐字段解析
        for field in &self.fields {
            let value = match field.node.parse(py, stream, ctx, path) {
                Ok(v) => v,
                Err(mut e) => {
                    e.push_path_segment(field.name.rust_name());
                    return Err(e);
                }
            };

            // 根据模式处理
            match field.mode {
                FieldMode::Rw | FieldMode::Ro => {
                    // RW/RO：存入 dict（成为实例属性 + context 字段）
                    dict.set_item(field.name.py_name().bind(py), value.bind(py))?;
                    // 有表达式时：ctx 的 dict 已被更新（因为是同一个 dict）
                }
                FieldMode::Wo => {
                    // WO（方案 A）：仅消费字节，既不存入 dict 也不写入 context。
                    // WO 字段（padding/reserved）不被表达式引用——
                    // 编译期已禁止表达式引用 WO 字段（§3.4.4）。
                    // 因此无需写入 context，dict 复用优化与 WO 语义无矛盾。
                    drop(value); // 显式丢弃解析结果
                }
            }
        }

        // 方案 B' 步骤 3-5：create_class + force_setattr + __post_init__
        // （与 Phase 1 相同，dict 已包含所有 RW/RO 字段）
        let instance = create_class(self.cls.bind(py)).map_err(|e| ...)?;
        force_setattr(py, &instance, "__dict__", dict.into_any().unbind()).map_err(|e| ...)?;
        if self.has_post_init {
            instance.call_method0("__post_init__").map_err(|e| ...)?;
        }

        Ok(instance.unbind())
    }
}
```

**三种 mode 的 parse 行为差异**：

| mode | node.parse 结果 | 存入 instance dict | 存入 context |
|------|----------------|-------------------|-------------|
| RW | 从流解析 | ✅ | ✅（dict 即 context） |
| RO | 从流解析 / 表达式计算 | ✅ | ✅ |
| WO | 从流解析（消耗字节） | ❌（丢弃） | ❌（方案 A：不写入，编译期禁止引用 WO） |

> **WO 字段不写入 context（方案 A）**：WO 字段 parse 时仅消费字节，既不存入实例 dict
> 也不写入 context。由于编译期已禁止表达式引用 WO 字段（§3.4.4），后续字段的表达式
> 不会依赖 WO 字段的值。这保证 dict 复用优化（dict = ctx.fields 同一对象）与 WO
> "parse 读不到"语义无矛盾：WO 字段不会出现在 force_setattr 后的实例属性中。

### 5.4 build 路径改造（三种 mode）

```rust
impl Construct for StructNode {
    fn build(&self, py, obj, stream, ctx, path) -> Result<(), ConstructError> {
        for field in &self.fields {
            match field.mode {
                FieldMode::Rw => {
                    // RW：从实例 getattr 取值，写入 context，递归 build
                    let value = obj.getattr(field.name.py_name().bind(py)).map_err(|e| {
                        ConstructError::Generic {
                            message: format!(
                                "object has no attribute '{}' (required for build): {}",
                                field.name.rust_name(), e
                            ),
                            path: path.to_string(),
                        }
                    })?;

                    // 写入 context（供后续表达式引用）
                    if self.has_expressions {
                        ctx.set_field_interned(field.name.py_name(), &value)?;
                    }

                    // 递归 build
                    match field.node.build(py, &value, stream, ctx, path) {
                        Ok(()) => {}
                        Err(mut e) => {
                            e.push_path_segment(field.name.rust_name());
                            return Err(e);
                        }
                    }
                }
                FieldMode::Wo => {
                    // WO（方案 A）：从实例 getattr 取值，递归 build。
                    // 不写入 context（编译期已禁止表达式引用 WO 字段，§3.4.4）。
                    let value = obj.getattr(field.name.py_name().bind(py)).map_err(|e| {
                        ConstructError::Generic {
                            message: format!(
                                "object has no attribute '{}' (required for build): {}",
                                field.name.rust_name(), e
                            ),
                            path: path.to_string(),
                        }
                    })?;

                    // 递归 build（不写 context）
                    match field.node.build(py, &value, stream, ctx, path) {
                        Ok(()) => {}
                        Err(mut e) => {
                            e.push_path_segment(field.name.rust_name());
                            return Err(e);
                        }
                    }
                }
                FieldMode::Ro => {
                    // RO：不从实例取值。
                    // 获取值的方式取决于节点类型：
                    // - Tell()：取 stream.tell()
                    // - Computed(expr)：eval_expr
                    // - Const(subcon, value)：用 expected 值
                    // - Bytes(expr)：表达式长度，build 时需先求长度
                    // - ContextParam(name)：从 context 取值
                    //
                    // 统一处理：调用一个 "compute_ro_value" 方法获取值，
                    // 然后写入 context 并 build。

                    let value = compute_ro_value(py, &field.node, stream, ctx, path)?;

                    // 写入 context
                    if self.has_expressions {
                        ctx.set_field_interned(field.name.py_name(), &value)?;
                    }

                    // build（对于 sizeof=0 的节点如 Tell/Computed/ContextParam，build 是 no-op）
                    // 对于 Const，build 用 expected 值写字节
                    match field.node.build(py, &value, stream, ctx, path) {
                        Ok(()) => {}
                        Err(mut e) => {
                            e.push_path_segment(field.name.rust_name());
                            return Err(e);
                        }
                    }
                }
            }
        }
        Ok(())
    }
}

/// 为 RO 字段计算值（build 方向）。
///
/// RO 字段不从实例取值，而是通过节点自身的逻辑计算。
fn compute_ro_value(
    py: Python<'_>,
    node: &Node,
    stream: &mut BuildStream,
    ctx: &Context<'_>,
    path: &mut Path,
) -> Result<Py<PyAny>, ConstructError> {
    match node {
        // Tell：返回当前写入位置
        Node::Tell(_) => Ok(stream.tell().into_py(py)),
        // Computed：求值表达式
        Node::Computed(c) => {
            let names = ctx.field_names();
            let v = eval_expr_int(c.expr(), names, ctx, py)?;
            Ok(v.into_py(py))
        }
        // Const：返回 expected 值
        Node::Const(c) => Ok(c.expected().clone_ref(py)),
        // ContextParam：从 context 取值
        Node::ContextParam(cp) => {
            ctx.get_obj_by_name(cp.name().bind(py))?
                .map(|b| b.unbind())
                .ok_or_else(|| ConstructError::ExprFieldMissing {
                    field: cp.name().to_string().unwrap_or_default(),
                })
        }
        // 其他节点（如 Bytes(expr) 用于 RO 场景极少）：
        // 这些节点的 RO 行为需要特殊处理。例如 Rebuild 的语义是 build 时
        // 从表达式计算值再 build。我们的 rfield(subcon) + 表达式系统覆盖了此场景。
        // 对于 rfield(Bytes(expr))：build 时先求长度，再从... 但 RO 不从实例取值，
        // 那 build 的数据从哪来？这是逻辑矛盾——RO 的 Bytes(expr) 不合理。
        // 编译期应拒绝 rfield(Bytes(expr))（因为 Bytes build 需要 bytes 数据，
        // 但 RO 不提供数据）。详见 §5.6 编译期校验。
        _ => Err(ConstructError::Generic {
            message: format!(
                "RO field with node type {:?} is not supported. \
                 RO fields must be Tell, Computed, Const, or ContextParam.",
                node.variant_name()
            ),
            path: path.to_string(),
        }),
    }
}
```

**三种 mode 的 build 行为差异**：

| mode | 值来源 | 写入 context | node.build 行为 |
|------|--------|-------------|----------------|
| RW | 实例 getattr | ✅ | 正常 build（写字节） |
| RO | compute_ro_value | ✅ | Tell/Computed/ContextParam: no-op；Const: 写 expected |
| WO | 实例 getattr | ❌（方案 A） | 正常 build（写字节） |

### 5.5 Context 恢复与性能优化

#### 5.5.1 入口选择

CompiledSchema 的 `_parse_raw` / `_build_raw` 根据是否有表达式选择 Context 模式：

```rust
impl CompiledSchema {
    pub fn _parse_raw(&self, py, data) -> PyResult<...> {
        let mut stream = ParseStream::new(data);
        // 根据 root node 是否含表达式选择 context
        let mut ctx = if self.root_has_expressions() {
            Context::new_root(py)?  // 创建 PyDict（~80-150ns 固定开销）
        } else {
            Context::placeholder(py)  // 零开销（Phase 1 优化保留）
        };
        let mut path = Path::new();
        let result = self.root.parse(py, &mut stream, &mut ctx, &mut path)?;
        Ok(result.into_bound(py))
    }
}
```

> **无表达式的 Struct 继续使用 placeholder**：Phase 1 的性能优化完全保留。
> 只有含有表达式的 Struct 才恢复 Context::new_root。

#### 5.5.2 Context 复用 dict 的机制

有表达式时，StructNode.parse 复用 ctx 的 PyDict 作为 instance dict：

- **ctx.fields 指向 dict A**（new_root 创建）
- StructNode.parse 从 ctx 取 dict A 的引用
- 每字段 parse → RW/RO 字段 set_item 到 dict A；WO 字段仅消费字节（§5.3 方案 A）
- force_setattr 时 clone_ref dict A（增加引用计数，~2-5ns），转给实例
- ctx 仍持有 dict A 引用，但 parse 结束后 ctx 被丢弃

**零额外 PyDict 创建**：dict A 同时充当 context 存储和 instance dict。
parse 方向的 context 更新（set_field）就是 set_item 到 dict A——本来就要做的操作。
WO 字段既不写入 dict A 也不写入 context（编译期禁止表达式引用 WO，§3.4.4），
因此 dict A 中只包含 RW/RO 字段，force_setattr 后实例属性正确。

#### 5.5.3 build 方向的 context 开销

build 方向 RW/RO 字段需要额外的 `ctx.set_field`（RW 从 getattr 取值后写入 context，
RO 从 compute_ro_value 取值后写入 context）。WO 字段不从实例取值写入 context（方案 A）。

- `ctx.set_field` = PyDict SetItem（interned key）≈ 10-15ns/field（仅 RW/RO 字段）
- WO 字段不触发 set_field（编译期禁止表达式引用 WO，§3.4.4）
- 这是表达式系统的必需开销（后续字段的表达式需要从 context 取值）
- 对比 Phase 1 build（不写 context）：每 RW/RO 字段多 ~10-15ns

### 5.6 编译期校验

compile_schema 中对字段组合做校验：

```rust
fn validate_field_combinations(fields: &[StructField]) -> Result<(), ConstructError> {
    for field in fields {
        // RO 字段的节点类型限制：只允许 Tell/Computed/Const/ContextParam
        if field.mode == FieldMode::Ro {
            match &field.node {
                Node::Tell(_) | Node::Computed(_) | Node::Const(_) | Node::ContextParam(_) => {}
                _ => {
                    return Err(ConstructError::Compilation {
                        message: format!(
                            "RO 字段 '{}' 的构造器 {:?} 不支持。\
                             RO 字段只允许 Tell, Computed, Const, ContextParam。",
                            field.name.rust_name(),
                            field.node
                        ),
                    });
                }
            }
        }

        // WO 字段不应使用 Tell/Computed/Const（这些不消费字节，WO 的语义是消费字节但不存储）
        // 实际上 WO + Tell 没有实际意义（Tell 不消费字节），但编译期不强制拒绝，
        // 只是会让 WO 字段变成 sizeof=0 的 padding——无害但无用。
    }
    Ok(())
}
```

### 5.7 Context 需要提供的字段名列表

VM 的 `eval_expr_int` 需要通过 `names: &[Py<PyString>]` 将 GetInt(idx) 解析为字段名。
这个 names 列表来自 StructNode 的字段名。

设计方案：Context 持有当前 Struct 的字段名列表引用。

```rust
pub struct Context<'py> {
    fields: Option<Bound<'py, PyDict>>,
    parent: Option<&'py Context<'py>>,
    /// 当前 Struct 的 interned 字段名列表（ExprOp GetInt 的索引对应此列表）。
    /// None 表示占位 context 或无表达式的 context。
    field_names: Option<&'py [Py<PyString>]>,
}
```

StructNode.parse/build 进入时设置 `ctx.field_names = &self.field_name_table`：

```rust
impl StructNode {
    /// 编译期缓存的字段名列表（供 VM GetInt 索引）。
    fn field_name_table(&self) -> &[Py<PyString>] {
        // 从 self.fields 提取 interned py_name 列表
        // 或在编译期预构建并缓存
        ...
    }
}
```

> **生命周期注意**：`field_names` 引用 StructNode 的内部数据，其生命周期不能超过
> StructNode 本身。由于 StructNode 存储在 CompiledSchema（程序生命周期），引用安全。

## 6. 条件解析

SwitchNode 和 IfThenElseNode 的 Rust 实现已在 §4.6.4-4.6.5 定义。本节讨论 Python 侧
描述符设计和使用模式。完整的 Python 侧描述符定义（含 `_expr_params` 协议实现）见 §3.7.4。

### 6.1 Switch 描述符

```python
class SwitchDescriptor:
    """条件分支：根据 selector 表达式的值从 cases 中选择子构造器。

    对应 Python construct 的 Switch(keyfunc, cases, default)。
    完整定义（含 _expr_params）见 §3.7.4。

    :param keyfunc: 选择器表达式（FieldRef/ExprRef 或常量 int）。
    :param cases: dict 映射 {int_key: subcon}。
    :param default: 可选，key 不匹配时使用的默认 subcon。
    """
    __slots__ = ("keyfunc", "cases", "default")

    def __init__(self, keyfunc, cases, default=None):
        self.keyfunc = keyfunc
        self.cases = dict(cases)  # 确保是 dict
        self.default = default

    @property
    def _expr_params(self):
        return {"keyfunc": self.keyfunc}
```

**使用示例**：

```python
@dataclass
class VariantPacket(StructMixin):
    type_code: int = field(Int8ub)
    payload: object = field(Switch(
        type_code,                          # FieldRef 引用
        {1: Int8ub, 2: Int16ub, 4: Int32ub} # cases
    ))
```

编译期：
- `type_code` 是 FieldRef → 编译为 ExprProgram
- `cases` 字典的 keys 必须是整数（编译期常量）
- Rust 侧构建 `SwitchNode { selector: ExprProgram, cases: Vec<(i64, Node)>, ... }`

### 6.2 IfThenElse 描述符

```python
class IfThenElseDescriptor:
    """条件分支：if cond then subcon_a else subcon_b。

    对应 Python construct 的 IfThenElse(condfunc, thensubcon, elsesubcon)。
    完整定义（含 _expr_params）见 §3.7.4。

    :param condfunc: 条件表达式（FieldRef/ExprRef，求值为 0/1）。
    :param thensubcon: 条件为真时使用的 subcon。
    :param elsesubcon: 条件为假时使用的 subcon。
    """
    __slots__ = ("condfunc", "thensubcon", "elsesubcon")

    def __init__(self, condfunc, thensubcon, elsesubcon):
        self.condfunc = condfunc
        self.thensubcon = thensubcon
        self.elsesubcon = elsesubcon

    @property
    def _expr_params(self):
        return {"condfunc": self.condfunc}
```

**使用示例**：

```python
@dataclass
class ConditionalPacket(StructMixin):
    flag: int = field(Int8ub)
    value: int = field(IfThenElse(
        flag > 0,       # 比较表达式（FieldRef > 常量 → ExprRef）
        Int32ub,        # flag > 0: 4 字节
        Int8ub          # flag <= 0: 1 字节
    ))
```

`flag > 0` 编译过程：
1. `flag` 是 `_FieldDescriptor` → FieldRef
2. `flag.__gt__(0)` → `_ExprRef(operator.gt, flag_desc, 0)`
3. 编译为 `[GetInt(0), Const(0), Gt]`
4. 运行时求值：flag 值 > 0 → 1（true）或 0（false）

### 6.3 与表达式 VM 的集成

Switch 和 IfThenElse 的 selector/cond 都是 ExprProgram，运行时通过 `eval_expr_int` 求值：

```
Switch/IfThenElse.parse(stream, ctx, path):
    1. key/cond = eval_expr_int(&self.selector/cond, names, ctx, py)
    2. 根据 key/cond 选择子节点
    3. 委托子节点的 parse
```

**性能特征**：
- eval_expr_int 开销 ≈ 25-35ns（1 个 GetInt）
- 子节点 parse 开销取决于具体构造器
- 条件分支本身几乎零开销（一次表达式求值 + 一次 match 查找）

### 6.4 嵌套条件

条件可以无限嵌套：

```python
value: int = field(IfThenElse(
    flag > 0,
    IfThenElse(flag > 10, Int64ub, Int32ub),  # 嵌套
    Int8ub
))
```

编译期：每个 IfThenElse 编译为独立的 IfThenElseNode，嵌套结构通过 Node 树表达。

### 7.1 Phase 2：框架验证（最小可验证集）

| P1 | `Tell()` + `rfield(Tell())` | 流位置记录 |
| P1 | `Computed(expr)` + `rfield(Computed(...))` | 表达式计算字段 |

### 8.2 表达式 VM 求值开销预测

#### 8.2.1 单指令开销

| 指令 | 预测开销 (ns) | 构成 |
|------|-------------|------|
| `GetInt(idx)` | 25-35 | PyDict get_item(interned key) ~15-25ns + extract i64 ~5-10ns |
| `Const(v)` | < 1 | 纯 Rust Vec push |
| `Add/Sub/Mul` | 1-2 | 纯 Rust 整数运算 + Vec pop/push |
| `FloorDiv/Mod` | 2-3 | 含除零检查分支 |
| 位运算 `BitAnd/BitOr/...` | 1-2 | 同算术 |
| 比较 `Eq/Lt/Gt/...` | 1-2 | 同算术 + bool→i64 |
| 一元 `Neg/Not` | 1-2 | Vec pop/push |

> **GetInt 是唯一涉及 CPython 的指令**。其余指令纯 Rust，LTO 后接近零成本。
> GetInt 的 PyDict get_item 使用 interned key（命中 hash cache），开销接近理论下界。

#### 8.2.2 典型表达式开销

| 表达式 | 指令序列 | 预测开销 (ns) |
|--------|---------|-------------|
| `count`（1 GetInt） | `[GetInt(0)]` | 26-36 |
| `count + flag`（2 GetInt + Add） | `[GetInt(0), GetInt(1), Add]` | 43-55 |
| `count * 2`（1 GetInt + Const + Mul） | `[GetInt(0), Const(2), Mul]` | 28-38 |
| `count + flag + 1` | `[GetInt(0), GetInt(1), Add, Const(1), Add]` | 46-58 |
| `count > 0`（比较） | `[GetInt(0), Const(0), Gt]` | 28-38 |

#### 8.2.3 eval_expr_int 函数调用开销

`eval_expr_int` 本身是一个 Rust 函数。在 fat LTO 下，如果调用点固定（如 BytesNode.parse
内部），编译器会将其内联到调用者中，函数调用开销趋近于零。

保守估计：每次 `eval_expr_int` 调用额外 ~1-3ns（栈帧创建，LTO 后接近 0）。

### 8.3 Context 恢复开销预测

#### 8.3.1 parse 方向

| 操作 | 开销 (ns) | 对比 Phase 1 |
|------|----------|-------------|
| `Context::new_root`（PyDict::new） | 80-150 | PyDict 创建从 StructNode 内部移到入口，**净增 0** |
| ctx 持有 dict 引用 | 2-5 | 新增（Context struct 字段初始化） |
| set_field（每字段） | 0 | **零额外开销**——复用 instance dict，set_item 本来就在做 |

**parse 方向 context 恢复净开销 ≈ 2-5ns/call**（仅 Context struct 初始化）。

#### 8.3.2 build 方向

| 操作 | 开销 (ns) | 对比 Phase 1 |
|------|----------|-------------|
| `Context::new_root`（PyDict::new） | 80-150 | Phase 1 build 用 placeholder，**新增固定开销** |
| set_field（每字段） | 10-15 | **新增每字段开销**（PyDict SetItem） |

build 方向 context 恢复是**真正的额外开销**：
- 固定 +80-150ns/call
- 每字段 +10-15ns/field

> **但**：Python construct 的 build 方向也有 context.update 开销（且更高，~50-100ns/field）。
> 因此 build 方向的加速比不受影响甚至更高。

### 8.4 对比 Python construct 表达式开销

Python construct 每次 `evaluate(param, context)` 的开销：

| 操作 | Python construct 开销 (ns) |
|------|--------------------------|
| `callable(param)` 检查 | 20-50 |
| `Path.__call__(obj)` 函数调用 | 80-150 |
| `obj[field]` dict 查找（Container） | 50-100 |
| **`this.field` 总计** | **150-300** |
| `BinExpr.__call__` 函数调用 | 80-150 |
| lhs/rhs 递归 callable 检查 | 10-20 |
| `operator.add(a, b)` | 10-20 |
| **`this.a + this.b` 总计** | **390-570** |
| **`this.a + 2` 总计**（rhs 是常量） | **250-370** |

**增量比**（Python construct vs construct-rs）：

| 表达式 | Python construct | construct-rs VM | 增量比 |
|--------|-----------------|----------------|--------|
| `count`（简单引用） | 150-300 ns | 26-36 ns | **4-11x** |
| `count + flag`（算术） | 390-570 ns | 43-55 ns | **7-13x** |
| `count > 0`（比较） | 250-400 ns | 28-38 ns | **7-14x** |

> 表达式求值本身的加速比 4-14x，与整体加速比的目标一致。

### 8.5 端到端加速比预测

使用修正后的基线模型：
- construct-rs：固定 ~229ns + per-field ~33ns + 表达式字段 +30ns/expr-field（parse 方向）
- Python construct：固定 ~1816ns + per-field ~413ns + 表达式字段 +200ns/expr-field

**加速比公式**：

```
ratio = (1816 + 413*N + 200*K) / (229 + 33*N + 30*K)
```

其中 N = 总字段数，K = 含表达式的字段数。

#### 8.5.1 典型场景预测

| 场景 | N | K | Python construct (ns) | construct-rs (ns) | 预测加速比 | 达标 |
|------|---|---|-----------------------|-------------------|----------|------|
| 最小表达式（count + Bytes(count)） | 2 | 1 | 2| 2642 | 327 | **8.1x** | ✅ |
| 典型小结构（3 字段，1 表达式） | 3 | 1 | 3255 | 358 | **9.1x** | ✅ |
| 算术表达式（count + flag + Bytes(count+flag)） | 3 | 1 | 3255 | 358 | **9.1x** | ✅ |
| 中等结构（10 字段，3 表达式） | 10 | 3 | 6546 | 649 | **10.1x** | ✅ |
| 大结构（50 字段，5 表达式） | 50 | 5 | 23500 | 2029 | **11.6x** | ✅ |
| 大结构（100 字段，10 表达式） | 100 | 10 | 45116 | 3859 | **11.7x** | ✅ |

> **结论**：所有典型场景预测加速比 ≥8x，目标可达。小结构（N=2-3）约 8-9x，
> 大结构 11-12x。

#### 8.5.2 最不利场景

最不利场景是**极小结构（N=1，K=1）**：只有 1 个字段且它含表达式。

```
ratio = (1816 + 413 + 200) / (229 + 33 + 30) = 2429 / 292 = 8.3x
```

仍 ≥8x。因为 Python construct 的固定开销（~1816ns）远高于 construct-rs（~229ns），
即使只有 1 个字段，固定开销的比率（~8x）已经托底。

#### 8.5.3 build 方向预测

build 方向 construct-rs 有额外的 context set_field 开销（~10-15ns/field）。

```
construct-rs build = 229 + 80(PyDict) + N*(33+15) + K*30
                   = 309 + 48*N + 30*K
```

| 场景 | N | K | Python build (ns) | construct-rs build (ns) | 加速比 |
|------|---|---|-------------------|------------------------|--------|
| N=3, K=1 | 3 | 1 | ~3500 | 483 | **7.2x** |
| N=10, K=3 | 10 | 3 | ~6800 | 849 | **8.0x** |
| N=50, K=5 | 50 | 5 | ~24000 | 2929 | **8.2x** |

> build 方向小结构（N=3）可能略低于 8x（~7.2x），因为 set_field 的额外开销。
> 大结构达标。这是可接受的——build 方向通常不如 parse 频繁。
>
> **[PM 决定 CONFIRM-1]**：build 方向 N=3,K=1 预测 7.2x **可接受**。理由：
> - 用户要求的 ≥8x 主要关注 parse 方向（解析是主要使用场景）
> - build 方向 N=3 的 7.2x 仍远超 4x 硬目标
> - 大结构（N≥10）build 方向 ≥8x 达标
> - P0 经验表明实测通常优于预测

### 8.6 性能风险识别

#### 风险 1：GetInt 开销高于预期（中风险）

**风险描述**：GetInt 从 PyDict get_item + extract i64 ≈ 25-35ns。如果 PyDict 的
get_item 开销因 interned key 未命中 hash cache 而更高（~40-50ns），表达式字段的
增量开销会上升。

**影响**：增量比从 7-13x 降至 4-8x，小结构加速比可能降至 6-7x。

**缓解**：
- 确保 GetInt 使用 interned PyString（StructNode 已缓存 interned field names）
- 如果仍不够快，可在 Context 内部维护 i64 并行缓存（仅缓存被表达式引用的整数字段）
  - 缓存方案：set_field 时同时写入 PyDict 和 i64 cache
  - GetInt 优先读 i64 cache（~2-5ns），fallback 到 PyDict
  - 但此优化增加复杂度，Phase 2 暂不实现，作为 Phase 2 性能不达标时的备选

**失败门槛**：如果 benchmark 显示 GetInt >50ns，启动 i64 cache 优化。

#### 风险 2：Context 创建的固定开销（低风险）

**风险描述**：有表达式的 Struct 每次 parse/build 创建 PyDict（~80-150ns）。
对于极小结构（N=2），这占 parse 总耗时的 ~25-40%。

**影响**：小结构加速比可能从 9x 降至 7-8x。

**缓解**：
- parse 方向已通过复用 dict 消除此开销
- build 方向是真正新增开销，但 Python construct build 的 context.update 开销更高
- 无进一步优化空间（PyDict::new 是 CPython 不可压缩成本）

**失败门槛**：build 方向加速比 <6x 时调查。

#### 风险 3：fat LTO 未生效（极低风险，已有防护）

**风险描述**：VM 求值器如果未被 LTO 内联，eval_expr_int 的函数调用开销 ~5-10ns/次
会累积。100 个表达式字段增加 ~500-1000ns。

**缓解**：Cargo.toml 已配置 `lto = "fat"` + `codegen-units = 1`。
Phase 2 验收时确认 release build 使用了正确配置。

**失败门槛**：如果 benchmark 加速比 <4x，首先排查 LTO 配置。

#### 风险 4：表达式字段过多导致栈溢出（极低风险）

**风险描述**：VM 栈 Vec 的 max_stack 在编译期计算并预分配。理论上不会溢出。
但如果表达式极深嵌套（如 100 层 BinExpr），max_stack 可能很大。

**缓解**：max_stack 在编译期计算，`Vec::with_capacity` 预分配。
实际场景中表达式深度很少超过 5-10 层（max_stack ≤ 10）。

### 8.7 性能假设的可证伪性

每个预测都包含具体数值、验证方法和失败门槛：

| 假设 | 预测值 | 验证方法 | 失败门槛 |
|------|--------|---------|---------|
| GetInt 开销 | 25-35 ns | micro-benchmark：循环 10000 次 eval_expr_int(GetInt) | >50 ns |
| Const+Add 开销 | 1-2 ns | micro-benchmark：eval_expr_int([Const, Add]) | >10 ns |
| Context::new_root | 80-150 ns | micro-benchmark：Context::new_root 循环 | >200 ns |
| set_field(build) | 10-15 ns | micro-benchmark：ctx.set_field 循环 | >25 ns |
| Bytes(count) 端到端 | ≥8x | benchmark vs Python construct Struct("count"/Byte, "data"/Bytes(this.count)) | <6x |
| Bytes(count+flag) 端到端 | ≥8x | benchmark vs Python construct 等价 | <6x |
| 大结构(N=50,K=5) | ≥10x | benchmark vs Python construct | <8x |
| build 方向 N=3 | ≥7x | benchmark vs Python construct build | <5x |

**Phase 2 性能门禁**（S-PERF）：

- <4x 视为设计失败，暂停后续开发

## 10. 需 PM/用户确认的开放问题

### 10.1 ContextParam 的命名（低优先级）

`ContextParam("machine")` 是否是最佳 API 名称？备选：
- `ContextParam("machine")`（当前设计）
- `FromContext("machine")`
- `Injected("machine")`
- `Provided("machine")`

**建议**：`ContextParam`——语义最清晰（"从 context 参数取值"）。PM 确认即可。

### 10.2 RO 字段与 Rebuild 的等价关系（中优先级）

决策 7 提到 `Rebuild(subcon, expr)` → `rfield(subcon)` + 表达式系统。

但 Rebuild 的语义是：
- parse：正常解析（用 subcon）
- build：从表达式计算值（忽略用户传入的值）

这对应的是 `rfield(subcon)` 中 subcon 本身正常解析，但 build 时不从实例取值。

**问题**：如果 Rebuild 的 subcon 是 `Bytes(len_(this.items))`，在我们的系统中：
- parse：正常 Bytes 解析（但长度从表达式求值）
- build：自动计算长度（不从实例取 bytes 数据？）

这里有一个语义冲突：build 时 Bytes 需要 bytes 数据，但 RO 不从实例取值。
**结论**：`rfield(Bytes(expr))` 在编译期应被拒绝（§5.6 已处理）。

Rebuild 的正确映射应该是：
```python
# Python construct
"count" / Rebuild(Int8ub, len_(this.items))

# 我们的系统
count: int = rfield(Rebuild(Int8ub, len(items)))
```

Rebuild 是一个特殊的 RO 节点：
- parse：用 inner subcon 正常解析
- build：从表达式计算值，用 inner subcon 构建

**需要 Phase 3 单独设计 RebuildNode**。Phase 2 不实现。

> **[PM 决定 CONFIRM-2] 确认为 Phase 2 已知限制**：
> Rebuild 需要后序字段引用（build 方向引用后续字段），这是更复杂的特性。
> Phase 2 聚焦验证核心表达式架构，RebuildNode 在 Phase 3 单独设计。
> 前向引用限制（§3.4.2）在编译期统一拒绝引用后序字段（不区分 parse/build 方向），
> 简化设计。build 方向的后序引用能力推迟到 Phase 3 RebuildNode。

### 10.3 浮点字段的表达式引用（低优先级）

当前 VM 栈为 i64。如果用户有浮点字段（Float32/Float64，Phase 2 暂不支持），
表达式无法引用浮点值。

**建议**：Phase 2 不支持浮点表达式（与 Phase 1 一致，Phase 1 不支持浮点格式）。
Phase 3+ 如果需要浮点表达式，考虑双栈设计（i64 + f64）或 Value 枚举。

### 10.4 sizeof 对表达式长度的处理（低优先级）

含表达式长度的 Bytes（`Bytes(count)`）的 sizeof 返回 `Err(ConstructError::Generic)`（Rust 内部无 `SizeofError` 变体，统一用 `Generic` 表示大小未知，参见 `greedy_bytes.rs` 先例；Python 侧仍映射为 `SizeofError`）。
这意味着 `Prefixed` 等依赖 sizeof 的构造器不能直接用于含表达式的字段。

**建议**：这是合理的限制。需要运行时大小的场景走 parse/build 路径。
sizeof 的语义本来就是"编译期可确定的大小"。

## 11. 边界条件清单

### 11.1 表达式编译期

|------|---------|
| `context={"machine": machine}` 注入字段 | 子 Struct 可通过 ContextParam("machine") 取值 |
| 子 Struct 未声明 ContextParam 但有注入 | 注入值存入 context，不影响子 Struct |
| 子 Struct 声明 ContextParam 但外层未注入 | ExprFieldMissing 错误（parse 时） |
| 多个注入 `context={"a": x, "b": y}` | 都存入子 context |
| 注入值是表达式 `context={"total": count + flag}` | 编译期编译为 ExprProgram，运行时求值 |

### 11.6 条件解析

| 场景 | 预期行为 |
|------|---------|
| Switch key 不匹配任何 case 且无 default | SwitchNoCase 错误 |
| Switch key 不匹配但有 default | 用 default subcon |
| IfThenElse cond=0 | 走 else 分支 |
| IfThenElse cond=非零 | 走 then 分支 |
| Switch cases 为空且有 default | 总是用 default |
| 嵌套 IfThenElse | 正常递归委托 |
