# 测试设计：用户面行为覆盖评估与新用例矩阵

> 任务：v0.1.2-7a [用例覆盖评估与专业测试设计]。本文是**设计文档**（不含测试
> 实现）。范围：Python 用户面（`neoconstruct` 包导出的 101 构造器 + `field/
> rfield/wfield` + `StructMixin.parse/build`）的行为空间；Rust 内部单测
> （1395 个 `#[test]`）不在本设计范围，仅作为分层置信度参考。
>
> 期望值原则（§0#9）：全部新用例期望值由 **neoconstruct 自主语义** 推导——
> ① README/SKILL 文档承诺（文档即契约）② 语义自然性（parse/build 对称、
> 最小惊讶）③ 既有绿灯行为基线（防漂移锚定）。**不以 Python construct 行为
> 作为期望值来源**；既有 parity 机制保留现状、不再扩展。

## 1. 行为空间模型与现状覆盖地图

### 1.1 行为空间维度定义

用户面行为空间 = 构造器 × 维度笛卡尔积的语义裁剪子集（非全积——语义无关
组合无测试价值）：

| 维度 | 取值域 | 说明 |
|------|--------|------|
| D1 构造器 | 101 导出名（`docs/constructors-inventory.csv` implemented 口径） | 值语义框架已将其收敛为 9 类 ValueKind（Instance/Const/Default/Rebuild/Computed/Tell/Void/Control/Index） |
| D2 字段模式 | `field` / `rfield` / `wfield`（+ 显式 `default=`） | RW/RO/WO 三模式；WO 编译期禁表达式引用 |
| D3 值时机 | 实例化 / parse / build 缺省 / build 显式等值 / build 显式不等值 / build 显式 None | 104 矩阵的六时机框架 |
| D4 嵌套位置 | 顶层 / 子 Struct / Prefixed×1 / Prefixed×2 / Switch case 内 / Array 元素内 / GreedyRange 元素内 / BitStruct 内 / Union 分支内 | 表达式只能引用同层前序字段 |
| D5 表达式形态 | 字段引用 / 算术 / 位运算 / 比较 / 常量折叠 / 禁用面（`/`、`and/or`、浮点常量） | i64 VM |
| D6 表达式消费者 | Bytes(len) / Array(count) / Switch / If / IfThenElse / Computed / Rebuild / Default / Prefixed / PrefixedArray / Checksum(start,end) | 读 ctx 前序有效值 |
| D7 操作 | parse / build / round-trip / 实例化 / 编译（`__init_subclass__`） | 五操作各自错误面 |
| D8 错误路径 | 缺值（FieldValueMissing）/ 类型错 / 流不足（StreamError）/ 范围越界 / 校验失败（Const/Check/OneOf/Checksum/Terminated）/ 编译错（CompilationError 族） | 29 个导出异常类 |
| D9 边界值 | 数值 0/1/极值/负极值；长度 0/1/最大声明/超剩余；Unicode 1-4 字节/代理对/astral；bit 宽 1..64/总和 8 倍数；对齐 0 余/恰整/差 1 | 等价类+边界值 |

## 2. 缺口清单（风险排序）

排序准则：**用户最可能踩到 × 后果最重** 优先。每项标注维度组合 / 重要性 /
预估用例数 / 优先级（P0 发布前必须；P1/P2 可迭代）。

### G1【P0】16 构造器用户面零覆盖

- **维度组合**：D1（Enum/FlagsEnum/Mapping/OneOf/NoneOf/Union/Hex/HexDump/
  NamedTuple/Sequence/Aligned/AlignedStruct/Probe/Timestamp/ProcessXor/
  ProcessRotateLeft + Pointer 纳入门禁 + Half/Double 别名）× D2 × D7 × D8。
- **为什么重要**：README「功能覆盖 101/134」公开承诺这些构造器可用；SKILL
  §3.3/§4.8 给出用户面用法。当前仅有 Rust 节点单测——**Python 侧 field()
  嵌入路径、实例化值语义（ValueKind 框架 D2 面）、parse/build 对称、错误
  类（MappingError/UnionError/SelectError/ValidationError/NamedTupleError/
  TimestampError/RotationError 共 7 个未测异常类都挂在这批构造器上）**。
  用户按 README 使用即进入无防线区域。Pointer 的 smoke 文件不在 CI pytest
  路径，等效零门禁。
- **预估**：~72（每构造器 happy path 2-3 + 边界 1-2 + 错误 1；见 §4.1）。

### G2【P0】RepeatUntil parity 门禁静默失效

- **维度组合**：D7 parity × RepeatUntil（Expr 路径 R1/R3、PyCallable 路径 R2）。
- **为什么重要**：12 个 skip 是 **impl error（子进程崩溃）**而非文档化差异
  ——parity 门禁对这些 case 名存实亡，回归无感知。且 RepeatUntil 用户面
  单测仅 12 例（descriptor 层），与 GreedyRange/Switch 组合面未测。
- **预估**：~6（修复 case 脚本使 12 case 恢复执行；补 4 例组合面）。

### G3【P0】错误路径系统性薄覆盖

- **维度组合**：D8 × D4（深嵌套错误 path 质量）× D7。
- **为什么重要**：错误是 API 承诺的一部分（§0#7：错误携带 path）。29 个
  异常类 19 个未测——用户触发 MappingError/SelectError/TerminatedError 等
  时行为完全未锁定；错误消息在 Array 元素级 / Switch case 级 / Prefixed
  子流级的 path 定位质量仅 2 用例。错误恢复（parse 失败后对象/流状态）无
  断言。
- **预估**：~38（19 异常类 × 类型+path 各 1 + 深位置 path 8 + parse 失败
  后实例不可用的不变量 3）。

### G4【P0】表达式 VM 算术边界零覆盖

- **维度组合**：D5 × D8：`//0`、`%0`、i64 溢出（大数乘/左移）、移位 ≥64、
  负移位、一元负极值 `-(-2**63)`、比较链。
- **为什么重要**：VM 是自研 i64 栈机（无 Python 语义兜底），错误形态
  （IntegerError？panic？回绕？）未锁定——若发生 panic 即违反红线（非测试
  代码禁 panic）。消费者场景 `Bytes(n % 0)` 用户可直接写出。
- **预估**：~12。

### G5【P1】零长度/单位长度边界

- **维度组合**：D9 × Array/Bytes/Strings/Prefixed：`Array(0)`、`Array(1,x)`、
  `Bytes(0)`、`b""` parse、空 GreedyRange、count=0 的 PrefixedArray、
  `CString("")`（仅终止符）、PaddedString 空串、GreedyBytes 空。
- **为什么重要**：`Array(0)` 全树 0 命中；长度 0 是真实协议值（CAN DLC=0
  仅 system 一处）；历史经验（Array(0) Index parse 是已知 B1 类边界）表明
  零长度路径有独立分支。
- **预估**：~18。

### G6【P1】Unicode/编码边界

- **维度组合**：D9 × Strings×5 编码面：UTF-8 2/3/4 字节字符、UTF-16 代理对
  （BMP/astral）、emoji（U+1F600）、空串、纯 ASCII、混合多字节、
  PaddedString 多字节填充交互、PascalString 长度=字节数≠字符数。
- **为什么重要**：编码错误（StringError 未测）与长度语义（字节 vs 字符）
  是字符串构造器两类经典坑；SKILL 明确要求显式后缀编码但后缀正确性仅
  parity 常规串覆盖。
- **预估**：~14。

### G7【P1】深组合嵌套（3+ 层）

- **维度组合**：D4 × D6：Switch→Struct→Array→Prefixed、GreedyRange→
  Prefixed→Switch→GreedyBytes（SKILL §4.5.6 SCTP 模式）、BitStruct×
  Prefixed、IfThenElse×Array、值语义构造器（Const/Default）位于 Array/
  GreedyRange 元素 Struct 内、Enum 字段作 Switch key。
- **为什么重要**：BUG-1 家族（v0.1.1）正是嵌套包装器的表达式收集缺陷
  ——该家族回归只有 Prefixed×1/×2 与 Bitwise×1；3+ 层与 Array 内位置
  是同族未探测面。SKILL 把 SCTP 模式作为核心 Cookbook，但 system 层无
  SCTP/无该组合的端到端。
- **预估**：~16。

### G8【P1】流位置状态机

- **维度组合**：D10：Seek whence 0/1/2 × parse/build、Seek 负偏移/越 EOF、
  build 侧 Seek 前跳（零填充）与后跳（覆盖 or 追加）、Pointer 绝对/相对/
  负偏移/重叠区双写、Pointer build 到已写区域（保留 or 覆盖语义）、
  Tell 在 Array 迭代内/Prefixed 子流内的值、Seek+Tell+Checksum 三者交错。
- **为什么重要**：流位置是隐式全局状态，错误形态是**静默错读**（比报错
  更危险，B2 家族同型）。J1-4 仅 4 例；Pointer 全部用户面断言在门禁外。
  build 侧填充/覆盖语义直接决定 wire 正确性。
- **预估**：~15。

### G9【P2】用户旅程与文档契约巡检

- **维度组合**：README 三示例逐句、SKILL §8 速查表逐行可运行、§4 Cookbook
  每模式 1 例端到端（SCTP/CRC/Peek→Computed→Switch 链）、实例 `repr`/`==`/
  dataclass 互操作、`parse` 对非 bytes 输入的错误形态。
- **为什么重要**：文档即契约（期望值三源之一）；文档腐烂是发布后最廉价的
  防线缺口。
- **预估**：~15。

### G10【P2】值语义矩阵位置/消费者维扩展

- **维度组合**：104 矩阵 D4 扩展（Array 元素内/GreedyRange 内/BitStruct
  内/Union 分支内的值语义字段）+ D6 扩展（Enum 值作 Switch key、Select
  内值语义、PrefixedArray(count)×Const）。
- **为什么重要**：矩阵 D4 只到 Prefixed×2/Switch×1；值语义构造器在迭代
  容器内（每元素 resolve）是新语义面，框架 §8 未覆盖。Enum 的
  EnumInteger fallback 与 ValueKind Instance 的交互是文档化行为未锁定。
- **预估**：~24。

**缺口规模合计**：~230（P0 ~128 / P1 ~63 / P2 ~39）。

## 3. 测试设计方法论（方法 × 适用维度）

| 方法 | 适用维度/缺口 | 应用方式 |
|------|--------------|----------|
| 等价类划分 + 边界值分析 | D9（G4/G5/G6） | 数值域（已由 INT_FORMATS 表建立范式）；长度域取 {0,1,2,声明值-1,声明值,声明值+1,超剩余}；Unicode 取每字节宽代表 + 空串 + astral；bit 宽取 {1,4,8,63,64,65→编译错}；移位取 {0,63,64→?,负→?} |

| 状态转移 | D10（G8） | 状态 = (流位置 p, parse/build)；事件 = Seek(whence,a)/Pointer(off,rel)/Tell/Prefixed 进出/读写 n 字节。设计覆盖每事件 × 两模式 + 越界迁移（p+n>EOF parse→StreamError / build→扩展）+ 回迁（Pointer 后主流位置不变） |
| 错误推测法 | D8（G3）+ 历史家族外推 | v0.1.1 BUG-1 家族（包装器内表达式收集）→ 新包装器（Union/Hex/Select 内表达式）；BUG-2/B1 家族（值提供型实例化）→ 19 个未测构造器的 `field()/rfield()/wfield()` 实例化时机逐一断言；B2 家族（ctx 有效值/静默错读）→ 迭代容器内值语义（G10）；B4 家族（静默忽略）→ G2 的 skip 静默失效是同型，另巡检其余 skip 理由 |
| 用户旅程 | G9 | README 三示例逐句复制运行；SKILL §8 速查表 22 行逐行；§4 Cookbook 8 模式各 1 E2E |

## 4. 新用例族设计

### 4.0 全局约定（所有新用例族共用）

- **文件与用例命名**：语义命名、不带版本号（§0#10）。文件落位：
  - `tests/integration/test_<语义名>.py`（组合/端到端族）
  - `tests/unit/test_<语义名>.py`（单构造器/编译期族）
  - `tests/errors/test_error_taxonomy.py`（异常族）
  用例名 `test_<被测语义>_<条件>_<期望>`（如 `test_enum_unknown_value_falls_back_to_int`）。
- **双重断言**（每用例强制）：①对象字段值（parse 后实例属性逐个断言，
  非仅 `==` 整对象）②字节（build→期望字节；parse→`.build()` round-trip
  == 输入字节）。异常用例断言类型 + `path` 含字段名/语义词（不逐字锚定
  消息全文，防脆弱）。
- **期望值三源**（docstring 内标注来源编号：[文档]/[自然]/[基线]）：
  [文档]=README/SKILL 承诺；[自然]=语义自然性推导（对称/最小惊讶）；
  [基线]=既有绿灯行为锚定。禁止出现 construct 对照表述。
- **dataclass 定义在测试函数体内**（既有惯例，编译期错误用例尤其必需）。

### 4.1 P0 族设计

#### P0-A 未测构造器用户面族（G1，~72 例，7 文件）

每构造器统一覆盖切面：**实例化值语义**（ValueKind 归属断言：`field(X())`
无参实例化 → 字段值是什么）× **parse 值** × **build 对称** × **round-trip**
× **错误类** × **1 个语义边界**。骨架示例（非实现）：

```python
def test_enum_label_parse_and_roundtrip():
    """Enum 命中 label：parse → EnumIntegerString（int()==1）[文档 §4.8.1]。

    双重断言：op == "READ" 且 int(op)==1；build 回 b"\\x01"。
    """
```

### 6.2 执行时间预算

- 实测基线：全量 pytest ~44s（1014 passed）。
- 非 parity 新用例均摊 ~40-50ms/例（编译 `__init_subclass__` 占主导）：
  P0 ~130 例 ≈ 6-7s；P1+P2 ~102 例 ≈ 5s。
- RepeatUntil parity 恢复执行：12 case × 2 impl 子进程 ≈ +3-5s。
- **全量增量 ≈ 15-18s，远低于 60s 预算**；即使 P0+P1+P2 一次全交亦可行
  （建议仍按优先级分批交付，P0 先行锁定发布风险）。

### 6.3 参数化生成 vs 手写取舍

| 用例类型 | 建议 | 理由 |
|----------|------|------|
| 等价类表（数值/长度/编码/异常类） | **parametrize 表驱动** | 已有 INT_FORMATS 成功范式；期望值可从 Python `struct`/`str.encode` 推导（独立于被测实现）；增量行成本低 |
| 判定表（Switch/Select/Union/Enum 分支） | parametrize（条件列 × 动作断言函数） | 分支语义同构，差异仅在期望值列 |
| 深组合/流位置/用户旅程 | **手写语义命名用例** | 每例期望值推导链独立（[文档]/[自然]/[基线] 标注），生成器会掩盖期望来源；可读性即文档 |
| 值语义扩展（P2-B） | 手写（矩阵风格延续） | 与 104 矩阵同风格，docstring 承载语义约定 |

### 6.4 交付顺序建议

1. P0-B（先修门禁空洞——parity 恢复后才谈得上其他覆盖的可信度）。
2. P0-C + P0-D（错误面与 VM 边界——可能暴露实现缺陷，需预留修复轮）。
3. P0-A（体量最大，按文件分 7 个子任务可并行）。
4. P1 → P2（迭代批次）。

每批交付门禁：pytest 全绿 + 增量执行时间记录 + 本文档 §1.2 覆盖地图更新。
