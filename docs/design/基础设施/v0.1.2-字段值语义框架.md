## 1. 问题模型：三个值解析点，五处散落特判

neoconstruct 的 dataclass 模型比原版多出一个**实例化时机**。字段值语义必须在三个点
解析，当前散落在五处（无单源）：

| 解析点 | 现状实现位置 | 缺陷形态 |
|--------|-------------|----------|
| **I 实例化**（`__init__` 默认值） | `_mixin.py _apply_dataclass_field_config` 的 `value_providing` isinstance 元组 | B1：Const/Default 实例化值 None；B3：表达式派生字段强制实参 |
| **P parse**（存/弃） | `FieldMode::{Rw,Ro,Wo}`（struct_node.rs） | 语义本身正确，但与 I/B 无关联 |
| **B build**（值来源） | ① `FieldMode` 分支 ② `Node::compute_ro_value`（mod.rs，按节点类型 match）③ 各节点 build 的 None 特判（Const/Default/Padding…） | B1e：RW 字段 getattr 到 None 时 **ctx 写入原始 None**（非有效值），流入表达式报 wrong type；B1f：`rfield(Const)` build 直接失败（compute_ro_value 无 Const 分支） |
| **ctx 注入**（B4） | `_FieldDescriptor._context_injections` 存了但**无任何消费** | 静默忽略（比报错更危险） |
| **表达式求值域**（B2） | `_expr_params` 协议 + 槽位递归收集 + expr_programs | 嵌套收集缺陷（DEV v0.1.2-2 止血中）；框架层缺口=ctx 写原始值而非有效值 |

## 2. 原版锚点实测表（construct 2.10.70，.venv-pc 实测）

原版的字段值语义框架是三个机制（`Struct._build`/`_parse` 源码 + 实测确认）：

1. **`flagbuildnone` 布尔**＝build 值来源唯一分类点：True 的构造器缺键时收到
   `obj.get(name, None)`；False 缺键直接 `KeyError`。
2. **parse 存储**＝`if sc.name: obj[name] = subobj`（凡有名必存，Padding 存 None）。
3. **ctx 回写**＝build 前全量 `context.update(obj)`，每个 subcon build 后
   `context[name] = buildret`（**有效值回写**——后续表达式读到的是节点实际使用的值）。
   v2 精确化：buildret 因构造器而异——值类=编码值；Const/Default=有效值；
   Peek=传入哑值（None）[A1-A3]；Seek=**新流位置 int**（非传入值）[S1]；
   Checksum=**重算 digest**（非传入值）[C1]；Padding/Pass=传入哑值。

| 构造器 | flagbuildnone | parse 结果 | build 缺省 | build 显式值 | build 值=None |
|--------|:---:|--------|--------|--------|--------|
| Const(5,Byte) | T | 5 | b'\x05'（用 value） | 等值→用；不等→ConstError | 用 value |
| Default(Byte,0) | T | inner 值 | b'\x00' | 用显式值 | 用默认 |
| Default(Byte,this.x+1) | T | inner 值 | 表达式求值 | 用显式值 | 表达式求值 |
| Rebuild(Byte,f) | T | inner 值 | 重算 f(ctx) | **忽略**，重算 | 重算 |
| Computed(expr) | T | 求值值 | no-op 不写不校验 | 忽略，no-op | no-op |
| Computed(42) | T | 42 | no-op | no-op | no-op |
| Padding(2) | T | **None（存入）** | 写 pattern×2 | **忽略**，写 pattern | 写 pattern |
| Tell | T | 流位置 | 不写字节 | 忽略 | — |

## 4. 候选方案（≥2，含否决理由）

### 候选 1【协议化补丁集】（否决）
- **机制**：把 `value_providing` isinstance 元组泛化为描述符协议 `_init_default`
  属性；Rust 侧不动；B2 靠 DEV 止血。
- **覆盖**：B1 仅实例化面（**ctx None 流入未修**，B1e/B1f 仍在）；B3 需另加规则；
  B4 不覆盖。
- **§0**：合规（纯冷路径）。**性能**：零热路径变化。
- **否决理由**：build 侧语义仍散落三处（FieldMode/compute_ro_value/节点特判），
  rfield(Const) 类缺陷修一处漏一处——本质是止血泛化，不满足"公共收敛"要求。

### 候选 2【ValueKind 编译期单源分类 + resolve 统一】（**推荐**，spike 已验证）
- **机制**：见 §5。编译期把每个字段的 build 值来源分类为封闭枚举 `ValueKind`，
  build 循环统一走 `resolve → 有效值 → ctx 回写 → node.build`；实例化默认值从
  **同一分类**派生；`compute_ro_value` 全量迁移删除。
- **覆盖**：B1（实例化 + ctx 流入）、B1f、B2 机制层（ctx 有效值 + 矩阵锁定）、
  B3（Optional + 错误时机后移到 build，对齐原版 KeyError 时机）、B4（分期，见 §5.6）。
- **§0**：合规（§6 对照表）。**性能**：spike 实测噪声级（§7）。

### 候选 3【build 签名返回值全量回写（construct 全对齐）】（否决）
- **机制**：`Construct::build` 改返回 `Result<Py<PyAny>>`，StructNode 用返回值做
  ctx 回写（逐节点复刻原版 buildret）。
- **否决理由**：30+ 节点签名全改（改动面 ×5）；每个节点强制产出返回值（多数字段
  弃用）带来 per-field 引用计数churn，555 测量点回退风险未经证；候选 2 的字段级
  resolve 已覆盖全部值语义构造器的锚点行为（§2 表逐行对齐），语义增益为零。

## 5. 推荐方案详细设计（候选 2）

### 5.1 核心类型（Rust，`compile.rs`/`struct_node.rs`）

```rust
/// 字段 build 值来源分类（编译期封闭枚举，静态 match 分派，禁 trait）。
pub enum ValueKind {
    /// 值必须来自实例。build 时 None → BuildValueMissing（对齐原版 KeyError 时机）。
    /// expr_derived：subcon 树内含表达式消费者（expr_programs[idx] 非空）→
    ///              init_default 降为 Optional（B3：错误时机后移）。
    Instance { expr_derived: bool },
    /// Const：编译期持有 Python 常量对象；None→补值（Bound clone）；ctx 写常量。
    Const(Py<PyAny>),
    /// Default：None→求值；非 None→用显式；ctx 写有效值。
    Default(Arc<ExprProgram>),
    /// Rebuild：忽略实例值，求值；ctx 写求值值；inner.build(求值值)。
    Rebuild(Arc<ExprProgram>),
    /// Computed：求值→ctx；build no-op（不写不校验）。
    Computed(Arc<ExprProgram>),
    /// Tell：ctx 写 stream.tell()；build no-op。
    Tell,
    /// Padding/Pass：ctx 写 None；节点自身写 pattern 字节/空。
    Void,
    /// 低频控制与流操作（StopIf/Check/Terminated/Element/**Peek/Seek/Checksum**，
    /// v2 新增后三者）：resolve 产哑值 None（实例可省），build 值语义由节点自理
    /// （Peek no-op / Seek 移动流指针 / Checksum 重算 digest 写入 / Check 校验 /
    /// StopIf 哨兵 / Terminated no-op）。
    Control,
    /// Index：resolve 产 ctx.index()。
    Index,
}
```

**分类规则**（编译期，按字段 subcon **根节点**判定——与原版 flagbuildnone 挂在
Struct 直接子构造器上一致，锚点 §2 已验证 Prefixed(普通) 归 Instance）：
ConstNode→Const、DefaultNode→Default、RebuildNode→Rebuild、ComputedNode→Computed、
TellNode→Tell、Padding/BitPadding/Pass→Void、
StopIf/Check/Terminated/Element/**Peek/Seek/Checksum**→Control（v2 新增后三者）、
IndexNode→Index、其余（含一切包装器根）→Instance{expr_derived}。

**哑值可省的语义依据（v2，P1 决策）**：原版 `flagbuildnone=True` 的运行期语义 =
Struct._build 缺键时 `obj.get(name, None)` 补 None（core.py:2252/2309）；其 15 个
叶类的共同特征是 **`_build` 实现不依赖 obj 的语义值**——或完全忽略（Seek 移指针
[源码:4602-4605]、Checksum 重算 [源码:5567-5569]、Peek/RestreamData no-op
[源码:4494/5194]、Error 无条件抛 [源码:3147-3148]），或将 None 仅作触发默认的
哑信号（Const/Default）。因此框架侧等价判定 = "**节点 build 忽略实例值 → resolve
产哑值、实例侧 init_default=None 可省**"，ValueKind 的非 Instance 变体全集恰好
覆盖原版 15 叶类中已实现的 13 个（对账表 [AST] 全量验证，非 Instance ⇔
flagbuildnone=True 无一例外）。三者归类 Control 而非新增枚举变体的理由：
① resolve 视角行为同构（哑值 None，无 i64 ExprProgram 可承载的单一求值——
Checksum 的 digest 来自 bytes_source 双表达式+hashfunc 组合 [源码:5567-5575]，
Seek 依赖流副作用，Peek 无 build 值语义）；② 枚举形态不变，DEV 无返工；
③ §5.2 分工原则不被破坏（hash 计算/流移动留在节点内，resolve 只补哑值）。

**§5.1b 未实现构造器预留分类**（原版 flagbuildnone=True，对账表单列）：
Error→Control（parse/build 无条件 ExplicitError）、RestreamData→Control（build
no-op return obj）。实现时直接落 Control，无需改枚举。

**§5.1c 包装器传播差异（v2 新识别，有意差异记录）**：原版传播规则（§2 [AST]）
使"包装器包裹全哑值分支"的字段也可省哑值——实测 W1：`field(If(this.flag>0,
Padding(2)))` 原版缺省 build 成功写 pattern（and(Padding=T,Pass=T)=T）。框架按根
节点判定 → IfThenElseNode 根 → Instance{expr_derived:true} → build 缺省报
BuildValueMissing（**过严于原版**）。决策：v0.1.2 不实现包装器传播，理由：
① 值类 inner（主流场景）传播结果 = 必填，与 Instance 一致（实测 W2：原版
If(cond,Byte) 缺省即 KeyError，错误形态反而更差）；全哑值分支 inner（W1 型）为
罕见病态组合；② Switch 的 case 运行期选择与编译期分类存在根本张力，正确实现需
引入"运行期可选"第三态，属 v0.1.3+ 演进项；③ 过严方向的错误形态是显式
BuildValueMissing（非静默），安全。矩阵 W 族锁定该差异（§8），防止未来语义漂移
无感知。

**§5.1d 三者的 ctx 回写差异（v2 附注）**：原版 buildret 语义（§2 机制 3）下
Seek 写新位置 int、Checksum 写重算 digest、Peek 写传入哑值——框架 Control 统一
写 None。受影响面 = "后继表达式引用 seek 位置/checksum 摘要/peek 显式值"的病态
场景（引用流位置应使用 Tell，引用摘要值应引用 RawCopy 数据源）。决策：接受差异
（显式记录），v0.1.3 有真实需求再升级专用 kind（如 `SeekPos`/`ChecksumDigest`）。
矩阵不设期望该形态 build 成功的用例（与 §10.12 呼应）；已交付 IEC104 真实链
（Peek→Computed→Switch，test_iec104:180-191）的差异锁定见 I5——parse 全链
PASS + build 腿显式报错（REV-N1 修订）。

### 5.2 build 循环（StructNode/SequenceNode 同模式）

```rust
for (idx, field) in self.fields.iter().enumerate() {
    let value: Bound<'_, PyAny> = match &field.kind {
        ValueKind::Instance { .. } => {
            let v = obj.getattr(field.name.py_name())?;       // C API
            if v.is_none() { return Err(BuildValueMissing { field, path }) }
            v
        }
        ValueKind::Const(c) => {
            let v = obj.getattr(field.name.py_name())?;       // RW/RO 均取（校验留给节点）
            if v.is_none() { c.bind(py).clone() } else { v }  // 就地补值，无 owned 中转
        }
        ValueKind::Default(p) => { /* None→eval_expr_int(p,ctx)?.into_py→bind；否则 v */ }
        ValueKind::Rebuild(p)  => { /* 忽略 attr；eval → PyLong */ }
        ValueKind::Computed(p) => { /* eval → ctx；node.build 是 no-op */ }
        ValueKind::Tell        => stream.tell().into_py(py).into_bound(py),
        ValueKind::Void        => py.None().into_bound(py),
        ValueKind::Control     => py.None().into_bound(py),
        ValueKind::Index       => ctx.index().into_py(py).into_bound(py),
    };
    if self.has_expressions { ctx.set_field_at(idx, field.name, &value, py)?; } // ★写有效值
    // WO 字段（v2 注）：编译期禁表达式引用（_check_wo_reference），故 WO 恒有
    // has_expressions=false 对其槽位——此行对 WO 字段不执行（"WO 不写 ctx"由
    // 编译期保证，非运行期分支；与正文一致，伪码特此对齐）。
    field.node.build(py, &value, stream, ctx, path)?;
}
```

> Sequence 差异（v2 注，REV P8）：SequenceNode 的 Instance 分支取值是 **list
> 位置访问**（`obj.get_item(idx)`，非 getattr）——Sequence 实例是 tuple/list 而
> 非 dataclass。resolve 循环同模式迁移时仅取值入口不同，分类/哑值/ctx 语义一致。

**分工原则**：resolve 只做"缺省补值"（value completion）；节点保留"值校验与编码"
（ConstNode 的相等校验保留——Switch/Array 等**无字段包装**的语境仍依赖节点自治）。
节点 build 的 None 分支保留但字段路径不再触发。

**取代的散落特判**（审计清单）：
| 现有散落点 | 框架下去向 |
|-----------|-----------|
| `mod.rs compute_ro_value` 全部 **11 分支**（v2 修正：止血已加 Const/Padding 两分支，v1 误写 10） | 迁移进 resolve（映射：Tell→Tell、Computed→Computed、Index→Index、StopIf/Check/Terminated/Element→Control、Rebuild→Rebuild、Default→Default、**Const→Const、Padding→Void**（v2 补全））；**函数删除**，B1f（Const 缺支）随之消灭 |
| `struct_node.rs` build 的 Rw/Wo/Ro 三分支 | 统一 ValueKind 循环；Rw/Wo 差异仅剩"是否写 ctx"（WO 编译期禁表达式引用，维持） |
| `sequence.rs` RO 旁路 | 同模式迁移 |
| 节点层 Const/Default 的 None 容忍 | 保留（非字段语境必需），字段路径由 resolve 前置补值 |
| `_mixin.py value_providing` 元组 | 删除，改消费编译产物 init_default（§5.3） |
| WO 引用编译期禁令（`_check_wo_reference`） | 保留（与 resolve 正交：WO 不写 ctx 依旧） |

### 5.3 实例化默认值派生（I 点，单一事实源＝Rust 分类）

`compile_schema` 返回值增加 `init_defaults: Vec<Option<Py<PyAny>>>`（编译期一次
FFI 内计算，冷路径；备选：CompiledSchema 暴露 `init_default(idx)` 方法）。规则：

| ValueKind | init_default |
|-----------|--------------|
| Const(v) | **v**（int/bytes/str/bool/float 不可变标量；可变对象→None，防共享可变默认值） |
| Default/Rebuild/Computed 且程序可常量折叠（ops==[Const(c)]） | **c**（→PyLong） |
| 其余 Default/Rebuild/Computed/Tell/Void/Control/Index | None |
| Instance{expr_derived:false} | Required（必填 positional，现状保留） |
| Instance{expr_derived:true} | **None+kw_only**（B3：build 时才报 BuildValueMissing） |

v2 注：Peek/Seek/Checksum 落 Control（§5.1）→ init_default=None（实例化可省，
B5 修复：`field(Peek)`/`field(Checksum)` 不再要求必填哑值）；build 侧 resolve 产
哑值 None 传节点（Peek no-op / Seek 移针 / Checksum 重算），三者显式实例值被忽略
（锚点 §2 实测 A2/S1/C2），ctx 写 None（与原版 ctx 回写差异见 §5.1d：Seek
原版写新位置 int、Checksum 原版写 digest——引用 seek 结果/checksum 摘要的后继
表达式属罕见病态，v0.1.3 若有需求再升级专用 kind，矩阵不设该形态用例）。

Python 侧 `_apply_dataclass_field_config` 消费该列表：RO→init=False（不变）；
有显式 `default=` 参数→显式优先（不变）；init_default 有值→`kw_only=True,
default=值`；None→`kw_only=True, default=None`；Required→无参 `field()`。
**用户显式 default 永远优先于框架派生**（现状语义保留）。

### 5.4 parse 侧（P 点）

不变：FieldMode Rw/Ro 存、Wo 弃。`field(Padding)` parse 存 None 对齐锚点 §2；
`wfield` 弃是 neoconstruct 有意的 API 设计（文档既有差异，矩阵记录）。
FieldMode 职责收敛为"init 可见性 + parse 存储"两维，**不再参与 build 分派**。

## 10. 边界条件清单

1. Const 值为可变对象（list/dict）→ init_default 退化为 None（防 dataclass 共享可变默认值）；build 仍用该值。
2. 显式 `default=` 参数 > 框架派生（永远）。
3. `field(Computed(expr))` RW + 实例化 None → build no-op 不报缺值（Computed 无字节语义）。
4. WO + 表达式引用 → 编译期禁令保留（`_check_wo_reference`）。
5. Rebuild/Default 表达式求值失败（前序字段缺）→ 错误沿既有 Expr 通道，path 完整。
6. 双层 Prefixed 内表达式 → 读宿主字段有效值（F9-12 锁定）。
7. frozen dataclass：resolve 不 setattr（只 getattr），行为不变。
8. `has_expressions=false` 的 Struct：resolve 照常（仅跳过 ctx 写），Instance None 检查仍生效（错误时机一致）。
9. BitStruct 域内 Padding/Void 分类同字节域（编译期 bitwise 上下文无关分类）。
10. **非 i64 常量默认值（v2，REV P8）**：`Default(b'ab')/Default('x')` 等非 int
    常量无法经 ADR-006 i64 ExprProgram 常量折叠，init_default 退化为 None（实例
    化不带默认值），build 时走 Default 求值分支（DefaultNode 节点内处理 bytes/str
    常量，现状能力不变）。边界延续至 v0.1.3 表达式 VM 扩展，矩阵不设该形态用例。
11. **Bytes 显式 None（v2，REV P8）**：原版 Bytes(n) build 显式 None → TypeError；
    框架 Instance 分支 None → BuildValueMissing。语义等价（均拒绝），异常类型
    统一为框架异常——有意差异，H 族外单独记录（差异文档随 DEV 交付）。
12. **包装器全哑值分支（v2，§5.1c）**：field(If(cond,Padding)) 等传播型哑值可省
    场景，框架下过严（BuildValueMissing vs 原版成功）——已知差异，W1 锁定，
    v0.1.3+ 候选演进。
