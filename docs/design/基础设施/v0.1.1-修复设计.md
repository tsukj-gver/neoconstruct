# v0.1.1 修复设计笔记

输入：`plans/v0.1.1/traces/v0.1.1-1-BUG复现与遗漏调查.md`（§4.4 monkeypatch 已验证主方案）。
本笔记只给决策、清单与伪代码；不写实现代码。

## 1. P1 核心：expr_programs 键格式选型

### 1.1 候选对比

| 方案 | Rust 改动面 | 风险 | 多同类消费者 |
|---|---|---|---|
| A 路径感知键（"subcon.key"） | **大**：~40 个 `build_*_node` 需穿 path 参数；Python 收集侧与 Rust 构建侧必须逐字符一致地派生路径（隐式跨 FFI 协议耦合，易漂移） | 高 | 支持 |
| B 每节点唯一参数名后缀 | 同 A（Rust fetch 点需知道后缀） | 高 | 支持 |
| **C 扁平键 + 合并冲突检测（选型）** | **零**（数据面） | 低 | 诚实报 CompilationError |
| D 每节点注入描述符（类 RepeatUntil set_compiled_expr_params） | 重构注入机制，超轻量范围 | 中 | 支持 |

### 1.2 选型：方案 C

- Rust 侧所有消费点按 `expr_programs[field_index][param_name]` 取程序，`param_name`
  是描述符类型的固定键（"key"/"cond"/"func"/"length"/"count"/"value"/"terminator"/
  "at"/"offset"/"modulus"/"pad"/"amount"/"group"/"start"/"end"），递归构建时**沿用同一
  field_index 与同一 dict**（compile.rs L2281-2288 / L2719-2726 / L7421-7428 已确认）。
  扁平合并与该消费协议天然兼容，P1 修复闭环在 Python 面。
- §0 约束（AGENTS.md）：不引入跨 FFI 抽象。方案 A/B 需要把"节点路径"这一新概念同步到
  Rust 侧每个 fetch 点，正是要避免的协议膨胀。
- 单消费者场景（BUG-1 全部已知用例，§4.4 矩阵）：合并结果与 monkeypatch 验证行为一致，
  **零行为变化**。

### 1.3 合并语义（伪代码）

```
merge_into(out, param, ops, field_name):
    if param not in out:            out[param] = ops
    elif out[param] == ops:         pass          # 同 ops 去重（diamond / 同表达式的两个消费者）
    else: raise CompilationError(冲突文案)         # 同名不同 ops
```

冲突文案要点：`字段 '<name>' 内有多个同名表达式参数 '<param>'（如两个 Switch 的
'key'），construct-rs 当前无法区分。请拆分为多个字段，或提升其中一个到顶层字段。`
（诚实限制优于静默用错程序；未来确有需求再升级方案 A。）

### 1.4 Rust 侧需要动的位置清单

- **P1 数据面：无**（上述理由）。
- P6 文案两处（独立于 P1）：`construct-rs/src/compile.rs` L2215-2223、L2236-2245，见 §4。
- 可选清理（超批准范围，仅记录）：compile.rs L583/L616/L1753/L1757/L1866 注释中的
  旧引用语法示例字样（非用户可见，不急）。

## 2. P1 辅助：递归范围（槽位协议 + 完整清单）

### 2.1 实现：槽位名协议（而非 35 行类表）

对每个节点，仅遍历约定槽位名集合中的属性：

```
SLOT_NAMES = ("subcon", "subcons", "cases", "default",
              "thensubcon", "elsesubcon", "lengthfield", "countfield", "checksumfield")

值守卫：None/bool/int/float/str/bytes → 跳过；list/tuple → 逐项；dict → .values()；
        其余 → 视为子节点递归。
防环：id(node) 集合，**按字段**新建（模块级单例如 Int8ub 跨字段共享，不可全局去重）。
```

理由：与 `_expr_params` 的 getattr 协议风格一致；自动覆盖未来新增容器（沿用槽位命名
约定即可）；代码量最小，符合轻量定位。已核对全部槽位名持有者无假阳性
（如 "default" 仅 SwitchDescriptor 持有子描述符；Checksum 的 start/end 是表达式参数，
由 `_expr_params` 消费，不进槽位集合）。

## 3. P2+P3：隐式 default 推导规则

### 3.1 类型清单与识别

`ConstDescriptor` / `DefaultDescriptor` / `RebuildDescriptor` / `PaddingDescriptor`
（`_descriptors.py`）+ `ComputedDescriptor`（`_mixin.py:349`）。识别方式：函数内
**isinstance**（元组）。注意 `_mixin.py` 顶部不导入 `_descriptors`（循环导入），沿用
L646 的**延迟导入**模式在函数内导入。

### 3.2 推导规则伪代码（`_apply_dataclass_field_config` 新增分支）

```
for name, desc in descriptors:
    if desc.mode == "ro":                      # 分支 1：不变（rfield → init=False, default=None）
        ...
    elif desc.default is not _MISSING:         # 分支 2：显式 default 优先，不变
        ...  # kw_only=True, default=desc.default
    elif isinstance(desc.subcon, _VALUE_PROVIDING):   # 分支 3（新增，P2+P3）
        setattr(cls, name, dataclasses.field(kw_only=True, default=None))
    else:                                      # 分支 4：不变（必填 positional）
        ...
```

### 3.3 边界决策

- a. **显式优先**：`field(Const(5, Int8ub), default=5)` 走分支 2，隐式不生效（分支顺序
  保证）。
- b. **rfield 不受影响**：`mode=="ro"` 在分支 1 提前返回，确认（RO 本就 init=False）。
- c. **Computed 在 field()（RW）**：同样获得隐式 default=None + kw_only（P2 报告项：
  `field(Computed(x+1))` 此前强制实参）。`P()` 可实例化，parse 后有值；build 传 None →
  节点层求值。与 `rfield(Computed)` 的差异仅在实例上是否可预填值。
- d. **类型注解告警**：`v: int = field(Const(5, Int8ub))` 隐式 default=None 与 int 注解
  在 mypy/pyright strict 下会告警。**决策：接受 + 文档说明**（运行时无影响）。文档建议
  三选一：忽略静态告警 / 显式传 default / 注解写 `int | None`。不为静态检查器改机制。
- e. **值忽略型 vs 值可提供型**：不做类型学区分，统一 `default=None` 语义 = "让节点层
  自动生成值"。行为差异由节点层既有语义决定：Const/Default 传非 None 值会被校验（错值
  报 ConstError，实测自洽）；Padding/Rebuild/Computed 传值被忽略。文档说明即可。
- kw_only=True 是**必需**而非可选：否则隐式 default 字段在前、必填字段在后时
  `@dataclass` 报 "non-default argument follows default argument"。
- 三个调用点（首编译 L901、前向引用桩 L895/L972）共用本函数，单点修改全覆盖。

### 4.3 P4：嵌套 Struct 引用外层字段的 NameError —— 不做机制引导

评估结论：**类体求值期的 NameError 无可靠的拦截点**。

- 类体名字查找链为 类命名空间 → 模块 globals → builtins（LOAD_NAME/LOAD_GLOBAL），
  无 `__missing__` 钩子；PEP 562 模块 `__getattr__` 只作用于模块属性访问，不介入类体
  名字解析。
- metaclass `__prepare__` 返回自定义映射理论上可拦截（PEP 3115），但：(a) CPython
  3.12+ 对类体命名空间有 dict 快路径，dict 子类 `__missing__` 在 LOAD_NAME 下的触发无
  跨版本稳定承诺；(b) 需给 StructMixin 引入元类，改变公开继承链，影响 dataclass/typing
  工具互操作预期；(c) 收益仅一处报错文案。不值得。
- 行为本身与原版一致（原版嵌套 Struct 同样 ctx 隔离，报告 §4 P4 已证）。

**交付文档标注文案**（README FAQ / SKILL，PM 安置）：

```
Q: 嵌套 Struct 里引用外层字段报 NameError？
A: 嵌套 StructMixin 的类体在 Python 类体作用域求值，无法引用外层字段名
（construct-rs 不支持跨层字段引用，与原版 construct 的嵌套 this 语义同样隔离）。
请把所需字段提升到同一层，或在外层用 Computed(...) 预计算。
注意：field(..., context=...) 参数当前未实现（保留位），请勿依赖。
```

## 6. 给 PM 的注意点

1. 冲突检测是**诚实限制**：同字段嵌套多个同类消费者（如 `Union(None, Switch(a), Switch(b))`）
   将得到明确 CompilationError 而非支持。本设计已留方案 A 升级路径评估，未来有真实需求
   再立项。
2. Rebuild 的"RW 编译期拒绝"与 `_field_kind` 是死声明/死协议（与 `context=` 同类），
   docstring 订正已列 §3.4；`context=` 参数的存废建议 v0.2 决策（本次仅文档化）。
3. v0.1.1-2 测试矩阵建议在报告 §5 清单之外补：嵌套 RepeatUntil、嵌套
   Checksum(StreamRange) 各一例（§2.4 风险项）。
