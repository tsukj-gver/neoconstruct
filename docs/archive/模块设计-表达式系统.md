## 1. 概述

### 1.1 模块位置

| 文件 | 内容 |
|------|------|
| `construct-rs/src/expr.rs` | 表达式系统全部实现（类型定义、trait、求值逻辑、便捷构造、测试） |

### 1.2 职责

提供一套**声明式延迟求值表达式系统**，使构造器参数能够在运行时根据上下文（Context）和构建对象（obj）动态计算。这是 construct 库的核心特性之一，允许字段大小、条件分支、数组长度等依赖于先前解析的值。

表达式系统是**纯求值模块**——它不直接进行二进制数据的 parse/build，而是被构造器（通过闭包）调用来计算动态参数。

### 1.3 核心抽象

Python 版本通过运算符重载（`__add__`/`__eq__`/`__neg__` 等）和 `__call__` 协议实现表达式组合与求值。Rust 版本由于类型系统的限制，采用以下映射策略：

| Python 机制 | Rust 对应 |
|-------------|-----------|
| `__call__(obj, *args)` | `Evaluate::evaluate(&self, ctx, obj)` |
| 运算符重载（`a + b`） | builder 方法（`a.add(b)`）或显式 `BinExpr::new(op, a, b)` |
| `__getattr__`（`this.field`） | `Path::field("field")` |
| `__getitem__`（`list_[-1]`） | `ListPath::index(-1)` |
| 全局单例 `this`/`obj_`/`list_` | 便捷构造函数 `this_()`/`obj_()`/`list_()` |

### 1.4 与其他模块的交互

**依赖**：
- `core::context::Context` — 表达式求值的上下文来源
- `core::error::{ConstructError, Result}` — 统一错误类型（`ConstructError::Expr`）
- `value::Value` — 求值结果的数据表示

**被依赖**：
- 表达式系统**不直接**被构造器以 `Evaluate` trait 形式引用。构造器（如 `If`、`Switch`、`Array`）接受的是 `Box<dyn Fn(&Context) -> ...>` 闭包。表达式求值结果由调用方在闭包内桥接：

```rust
// 集成示例：将表达式包装为 If 的条件闭包
let expr = this_().field("x").gt(const_val(Value::Int(5)));
let cond: CondFunc = Box::new(move |ctx| {
    expr.evaluate(ctx, None)
        .map(|v| matches!(v, Value::Bool(true)))
        .unwrap_or(false)
});
If::new(cond, then_con, else_con)
```

> **设计说明**：总纲 5.4 原计划"修改 Phase 2-4 已有构造器参数类型使用 `IntoExpr`"，但 DEV 在实现时决定**不侵入已有构造器**，保持闭包接口不变。表达式系统作为独立工具层，由用户按需桥接。此决策见第 6 节设计决策记录。

## 2. 类型定义

### 2.1 Evaluate trait

表达式系统的核心 trait，所有表达式节点必须实现。对应 Python `ExprMixin` 子类的 `__call__` 协议。

```rust
/// 所有表达式节点实现的 trait。
///
/// 表达式针对 [`Context`] 和可选的 `obj` 引用求值。
/// parse 阶段 `obj` 为 `None`；build 阶段 `obj` 为 `Some(&Value)` 指向构建对象。
pub trait Evaluate: Send + Sync + std::fmt::Debug {
    /// 求值并返回结果 [`Value`]。
    ///
    /// # Errors
    /// 路径解析失败、运算类型不匹配或其他求值错误时返回
    /// [`ConstructError::Expr`]。
    fn evaluate(&self, ctx: &Context, obj: Option<&Value>) -> Result<Value>;
}
```

**设计要点**：
- `Send + Sync` 约束：表达式节点需可跨线程传递（为未来并行解析预留）。
- `Debug` 约束：便于错误诊断与日志输出。
- `obj: Option<&Value>`：统一 parse/build 两种场景。Python 中通过位置参数区分，Rust 用显式 `Option` 表达。

### 2.2 PathRoot

Path 的根类型，区分 `this`（当前上下文）和 `obj_`（构建对象）。

```rust
#[derive(Clone, Debug, PartialEq)]
pub enum PathRoot {
    /// 从当前上下文开始解析（Python `this`）。
    This,
    /// 从构建对象开始解析（Python `obj_`）。
    Obj,
}
```

### 2.3 Path

点分路径，解析到上下文或构建对象中的 `Value`。对应 Python `Path` 类。

```rust
#[derive(Clone, Debug, PartialEq)]
pub struct Path {
    /// 根之后的遍历段（字段名序列）。
    pub segments: Vec<String>,
    /// 路径根——上下文或构建对象。
    pub root: PathRoot,
}

impl Path {
    /// 创建给定根、无段的空 Path。
    pub fn new(root: PathRoot) -> Self;

    /// 追加一个段并返回**新的** Path（不可变语义，不修改原 Path）。
    /// 等价于 Python 的 `this.field` 属性访问。
    pub fn field(&self, name: impl Into<String>) -> Self;
}
```

**Python 对应**：
| Python | Rust |
|--------|------|
| `this` | `Path { root: This, segments: [] }` |
| `this.header` | `Path { root: This, segments: ["header"] }` |
| `this.header.length` | `Path { root: This, segments: ["header", "length"] }` |
| `obj_` | `Path { root: Obj, segments: [] }` |
| `obj_.count` | `Path { root: Obj, segments: ["count"] }` |

> **注意**：Python 的 `Path.__getattr__` 和 `__getitem__` 都创建新的 `Path` 节点。Rust 只保留 `field()` 方法（`__getitem__` 语义由 `ListPath` 覆盖）。Python 的 `_` 父导航段由 `Context::get_path` 内部处理，`Path` 本身不关心段的语义。

### 2.4 ConstExpr

常量值表达式，始终返回同一个 `Value`。用于将字面量包装为表达式节点（如 `this.count + 1` 中的 `1`）。这是 **Rust 扩展类型**，Python 中直接使用原始值（通过 `callable()` 检查区分表达式和常量）。

```rust
#[derive(Clone, Debug, PartialEq)]
pub struct ConstExpr {
    pub value: Value,
}

impl ConstExpr {
    pub fn new(value: Value) -> Self;
}
```

### 2.5 BinOp / BinExpr

二元运算。对应 Python `BinExpr` 类和 `operator` 模块函数。

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum BinOp {
    Add,    // +
    Sub,    // -
    Mul,    // *
    Div,    // /
    Mod,    // %
    Shl,    // <<
    Shr,    // >>
    BitAnd, // &
    BitOr,  // |
    BitXor, // ^
    Eq,     // ==
    Ne,     // !=
    Lt,     // <
    Gt,     // >
    Le,     // <=
    Ge,     // >=
    And,    // and（逻辑与）
    Or,     // or（逻辑或）
}

#[derive(Debug)]
pub struct BinExpr {
    pub op: BinOp,
    pub left: Box<dyn Evaluate>,
    pub right: Box<dyn Evaluate>,
}

impl BinExpr {
    pub fn new<L: Evaluate + 'static, R: Evaluate + 'static>(
        op: BinOp, left: L, right: R,
    ) -> Self;
}
```

**与 Python 的差异**：
- Python 的 `ExprMixin.__add__` 等 20 种运算符重载自动构建 `BinExpr`。Rust 提供显式 `BinExpr::new` 和 `Path` 的 builder 方法。
- Python 支持 `__radd__` 等反向运算符（`1 + this.x`）。Rust 中需手动构造 `BinExpr::new(Add, ConstExpr::new(...), path)`。
- **未实现** `__pow__`（`**`）、`__floordiv__`（`//`）、`__truediv__`（`/`）的区分、`__contains__`（`in`）。理由见第 5 节。

### 2.6 UniOp / UniExpr

一元运算。对应 Python `UniExpr` 类。

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum UniOp {
    Neg,     // -（取负）
    Not,     // not（逻辑非）
    BitNot,  // ~（按位取反）
}

#[derive(Debug)]
pub struct UniExpr {
    pub op: UniOp,
    pub inner: Box<dyn Evaluate>,
}

impl UniExpr {
    pub fn new<E: Evaluate + 'static>(op: UniOp, inner: E) -> Self;
}
```

**与 Python 的差异**：
- Python 的 `__pos__`（一元 `+`，恒等操作）未实现。该操作符在 construct 中无实际使用场景。
- Python 的 `__invert__` 映射到 `UniOp::Not`（`operator.not_`，逻辑非）而非 `UniOp::BitNot`。Rust 将逻辑非和按位取反区分为两个独立变体（`Not` = 逻辑，`BitNot` = 按位），语义更精确。

### 2.7 FuncPath

内置函数表达式。对应 Python `FuncPath` 类和全局实例 `len_`/`sum_`/`min_`/`max_`/`abs_`。

```rust
#[derive(Debug)]
pub struct FuncPath {
    /// 函数名（"len"/"sum"/"min"/"max"/"abs"）
    pub name: String,
    /// 其结果传入函数的内部表达式
    pub inner: Box<dyn Evaluate>,
}

impl FuncPath {
    pub fn new<E: Evaluate + 'static>(name: impl Into<String>, inner: E) -> Self;
}
```

**支持的函数**：

| 名称 | 行为 | Python 对应 |
|------|------|------------|
| `len` | 返回 `List`/`Bytes`/`String`/`Container` 的长度 → `Value::UInt` | `len()` |
| `sum` | 对 `List` 中所有元素求和 → `Value::Int` | `sum()` |
| `min` | 返回 `List` 中最小元素 → `Value::Int` | `min()` |
| `max` | 返回 `List` 中最大元素 → `Value::Int` | `max()` |
| `abs` | 返回整/浮点数的绝对值 | `abs()` |

**与 Python 的差异**：
- Python 的 `FuncPath` 采用两阶段柯里化：`len_` 创建无 operand 的实例，`len_(expr)` 绑定 operand 后才实际调用 `func`。Rust 简化为一步构造：`FuncPath::new("len", expr)`，绑定发生在构造时。
- `sum`/`min`/`max` 的元素通过 `Value::to_i64()` 转换为 `i64` 后计算（Python 直接使用 `int`）。这意味着超过 `i64` 范围的 `BigInt` 元素会报错。这在 construct 典型场景（大小/计数）中不会触发。
- `sum` 使用 `checked_add`（溢出返回 `Err`），而 `BinExpr` 算术使用 `wrapping_*`。这是有意的设计差异，见第 6 节。

### 2.8 CondExpr

条件（三元）表达式。对应 Python 的 `a if cond else b` 模式。这是 **Rust 扩展类型**，Python 中由语言原生 `if-else` 表达式直接提供。

```rust
#[derive(Debug)]
pub struct CondExpr {
    pub cond: Box<dyn Evaluate>,
    pub then_val: Box<dyn Evaluate>,
    pub else_val: Box<dyn Evaluate>,
}

impl CondExpr {
    pub fn new<C, T, E>(cond: C, then_val: T, else_val: E) -> Self
    where
        C: Evaluate + 'static,
        T: Evaluate + 'static,
        E: Evaluate + 'static;
}
```

### 2.9 ListPath

列表索引路径，对应 Python 的 `Path2` 类和 `list_` 全局实例。主要用途是 `list_[-1]`（RepeatUntil 中检查最后解析的元素）。

```rust
#[derive(Debug)]
pub struct ListPath {
    /// 列表索引。负值从末尾计数（Python 风格）。
    pub index: i64,
    /// 解析为 `Value::List` 的内部表达式。
    /// `None` 时从 context 查找 `"list_"` 键（裸 `list_()` 模式）。
    pub inner: Option<Box<dyn Evaluate>>,
}

impl ListPath {
    /// 创建带内部表达式的索引 Path。
    pub fn new_indexed<E: Evaluate + 'static>(index: i64, inner: E) -> Self;

    /// 创建裸 ListPath（无内部表达式），评估时从 context 查找 `"list_"` 键。
    pub fn new_bare() -> Self;

    /// 返回带指定索引的新 ListPath（仅对裸模式有效，链式调用）。
    /// 等价于 Python 的 `list_[-1]`。
    pub fn index(&self, idx: i64) -> Self;
}
```

**Python 对应与语义映射**：

Python 的 `Path2.__call__(self, *args)` 使用 `args[1]` 取列表（由 RepeatUntil 的 `predicate(e, partiallist, context)` 调用协议传入）。Rust 表达式协议为 `evaluate(ctx, obj)` 无 `*args`，因此裸模式从 `context["list_"]` 取列表。**这是合理的架构适配**——Phase 6 的 RepeatUntil 实现需在调用表达式前将 partial list 存入 `context["list_"]`。

| Python | Rust |
|--------|------|
| `list_` | `list_()`（裸，无索引） |
| `list_[-1]` | `list_().index(-1)` |
| `list_[0]` | `list_().index(0)` |

### 2.10 IntoExpr

将值转换为 `Box<dyn Evaluate>` 的便捷 trait。允许 API 接受字面量、`Path` 或已有表达式节点。

```rust
pub trait IntoExpr: 'static {
    fn into_expr(self) -> Box<dyn Evaluate>;
}

// 已实现的转换：
impl IntoExpr for usize;   // → ConstExpr(UInt)
impl IntoExpr for i64;     // → ConstExpr(Int)
impl IntoExpr for u64;     // → ConstExpr(UInt)
impl IntoExpr for Path;    // → Box<Path>
impl IntoExpr for ListPath; // → Box<ListPath>
impl IntoExpr for Box<dyn Evaluate>; // → 自身
```

## 3. 接口设计

### 3.1 Evaluate 求值接口

所有表达式节点通过 `evaluate` 方法求值：

```rust
fn evaluate(&self, ctx: &Context, obj: Option<&Value>) -> Result<Value>;
```

**参数语义**：
- `ctx`：当前上下文。`Path { root: This }` 从此解析。
- `obj`：构建对象引用。`Path { root: Obj }` 从此解析。parse 阶段传 `None`，build 阶段传 `Some(&value)`。

### 3.2 Path 构建与链式方法

`Path` 提供完整的 builder 方法集，避免用户手写 `BinExpr::new(...)`。方法命名刻意与标准库 trait 方法（`Add::add` 等）同名，通过 `#[allow(clippy::should_implement_trait)]` 抑制警告——因为任务设计明确要求 builder 方法而非 trait 重载。

```rust
impl Path {
    // --- 字段导航 ---
    pub fn field(&self, name: impl Into<String>) -> Self;

    // --- 算术运算（返回 BinExpr）---
    pub fn add<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;   // +
    pub fn sub<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;   // -
    pub fn mul<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;   // *
    pub fn div<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;   // /
    pub fn rem<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;   // %
    pub fn shl<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;   // <<
    pub fn shr<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;   // >>

    // --- 位运算（返回 BinExpr）---
    pub fn bitand<E: Evaluate + 'static>(self, rhs: E) -> BinExpr; // &
    pub fn bitor<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;  // |
    pub fn bitxor<E: Evaluate + 'static>(self, rhs: E) -> BinExpr; // ^

    // --- 比较运算（返回 BinExpr）---
    pub fn eq_expr<E: Evaluate + 'static>(self, rhs: E) -> BinExpr; // ==
    pub fn ne_expr<E: Evaluate + 'static>(self, rhs: E) -> BinExpr; // !=
    pub fn lt<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;      // <
    pub fn gt<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;      // >
    pub fn le<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;      // <=
    pub fn ge<E: Evaluate + 'static>(self, rhs: E) -> BinExpr;      // >=

    // --- 一元运算（返回 UniExpr）---
    pub fn neg(self) -> UniExpr;     // -
    pub fn not(self) -> UniExpr;     // not
    pub fn bitnot(self) -> UniExpr;  // ~

    // --- 内置函数（返回 FuncPath）---
    pub fn len_func(self) -> FuncPath;  // len_
    pub fn sum_func(self) -> FuncPath;  // sum_
    pub fn min_func(self) -> FuncPath;  // min_
    pub fn max_func(self) -> FuncPath;  // max_
    pub fn abs_func(self) -> FuncPath;  // abs_
}
```

> **命名说明**：`eq_expr`/`ne_expr` 使用 `_expr` 后缀避免与 `PartialEq::eq` 混淆（`Path` 本身实现了 `PartialEq` 用于结构比较，而非构建比较表达式）。

### 3.3 便捷构造函数


### 3.4 内部辅助函数

以下函数为模块私有（`fn`，非 `pub`），用于 `BinExpr::evaluate` 的分派逻辑：

| 函数 | 职责 |
|------|------|
| `bin_op_symbol(op) -> &'static str` | 返回运算符的可读符号 |
| `is_zero(v) -> bool` | 检查值是否为零（除零/模零检测） |
| `apply_arithmetic(lhs, rhs, int_op, uint_op, bigint_op, float_op)` | 分派整数/浮点算术（wrapping 语义） |
| `apply_bitwise(lhs, rhs, op)` | 分派位运算（拒绝非整数） |
| `apply_shift(lhs, rhs, op)` | 分派移位（限制移位量 ≤ 63） |
| `apply_cmp(lhs, rhs, int_op, float_op)` | 分派比较（整数直接比较，浮点用 float_op） |
| `apply_logical(lhs, rhs, op)` | 分派逻辑运算（Python 真值规则） |
| `value_to_bool(v) -> Result<bool>` | Value → bool 转换（Python truthiness） |

## 4. 行为规格

### 4.1 this 路径解析

`Path { root: PathRoot::This, segments }` 的 `evaluate` 行为：

1. **无段（bare `this`）**：返回 `Err(ConstructError::Expr)`。
   - Python 中 `this(obj)` 返回完整的 `obj` 对象。Rust 选择报错，因为"返回完整上下文"语义模糊（Context 不是 Value）。调用方如需完整上下文应使用显式字段路径。
   - **这是有意的设计差异**（比 Python 更严格），属于合理的额外防护。

2. **有段（`this.field`）**：调用 `ctx.get_path(&segments)`。
   - 段按顺序逐级深入 `Value::Container` 字段。
   - 段 `"_"` 表示父上下文导航（对应 Python `this._`），由 `Context::get_path` 内部处理：前导的 `"_"` 段沿 `parent()` 链上溯，第一个真实 key 在当前层级查找，后续 key 在嵌套 Container 中查找。
   - 缺失字段 → `ConstructError::FieldMissing`。
   - 通过非 Container 值继续查找 → `ConstructError::Generic`。

### 4.2 obj_ 路径解析

`Path { root: PathRoot::Obj, segments }` 的 `evaluate` 行为：

1. **obj 为 None**：返回 `Err(ConstructError::Expr { message: "obj_ path used outside of build context" })`。
2. **无段（bare `obj_`）**：返回 `obj.clone()`（完整构建对象）。
   - 与 bare `this` 不同，bare `obj_` 返回值而非报错，因为 `obj` 本身就是一个 `Value`。
3. **有段（`obj_.field`）**：将段用 `.` 连接为点分路径，调用 `value.get_path(&dotted)`。

### 4.3 二元运算求值

`BinExpr::evaluate` 先求值左右子表达式，再按 `op` 分派：

**算术运算（Add/Sub/Mul/Div/Mod）**：
- 通过 `apply_arithmetic` 分派，根据操作数类型选择对应宽度的运算：
  - `Int + Int` → `i64` wrapping 运算 → `Value::Int`
  - `UInt + UInt` → `u64` wrapping 运算 → `Value::UInt`
  - `Int + UInt`（混合）→ 提升为 `i64` → `Value::Int`
  - `BigInt` 参与 → `i128` wrapping 运算 → `Value::BigInt`
  - `Float` 参与 → `f64` 运算 → `Value::Float`
- **Div/Mod** 前置 `is_zero(&rhs)` 检查，零除数返回 `Err`。
- **溢出使用 wrapping 语义**（见第 6 节设计决策 D1）。

**位运算（BitAnd/BitOr/BitXor）**：
- 通过 `apply_bitwise` 分派，仅接受整数操作数，拒绝 Float/String 等。
- `UInt op UInt` 结果为负时降级为 `Value::Int`，否则保持 `Value::UInt`。

**移位运算（Shl/Shr）**：
- 通过 `apply_shift` 分派，右操作数通过 `to_u64()` 转换。
- 移位量 > 63 返回 `Err`（避免未定义行为）。Python 无此限制（Python int 任意宽度）。

**比较运算（Eq/Ne）**：
- 使用 `Value` 的 `PartialEq`（`==`/`!=`）。
- **注意**：`Int(5) == UInt(5)` 返回 `false`（不同枚举变体）。Python 中 `int` 无符号区分，`5 == 5` 为 `True`。这是 Rust 强类型 Value 的固有差异。

**比较运算（Lt/Gt/Le/Ge）**：
- 通过 `apply_cmp` 分派：
  - 整数对（Int/UInt/BigInt 任意组合）→ `i64` 比较
  - 其他（含 Float）→ `to_f64()` 后用 `float_op` 比较
- 浮点比较已修复截断 bug（见第 6 节 D3）。

**逻辑运算（And/Or）**：
- 通过 `apply_logical` 分派：先将两个操作数用 `value_to_bool` 转为 bool，再应用逻辑运算。
- **非短路求值**：与 Python `and`/`or` 的短路行为不同，Rust 版本先求值两个子表达式再运算。这是 trait 对象模型的固有限制（`Box<dyn Evaluate>` 无法惰性求值单个子表达式而不评估另一个）。影响可忽略——表达式求值无副作用。

### 4.4 一元运算求值

`UniExpr::evaluate` 先求值内部表达式，再按 `op` 处理：

| 运算符 | 接受类型 | 行为 |
|--------|---------|------|
| `Neg` | Int/UInt/BigInt/Float | 取负。UInt → Int（可能为负） |
| `Not` | 任意（经 `value_to_bool`） | 逻辑非 |
| `BitNot` | Int/UInt/BigInt | 按位取反 |

> **已知遗留**（见第 6 节 D2）：`Neg` 对 `i64::MIN` 使用原始 `-i` 运算符，debug 模式下理论 panic。同理 `BigInt(i128::MIN)`。

### 4.5 内置函数求值

`FuncPath::evaluate` 先求值内部表达式，再按 `name` 分派：

| 函数 | 输入 | 输出 | 空输入行为 |
|------|------|------|-----------|
| `len` | List/Bytes/String/Container | `Value::UInt(len)` | 空集合返回 0 |
| `sum` | List（元素可转 i64） | `Value::Int(总和)` | 空列表返回 `Int(0)` |
| `min` | List（元素可转 i64，非空） | `Value::Int(最小值)` | 空列表返回 `Err` |
| `max` | List（元素可转 i64，非空） | `Value::Int(最大值)` | 空列表返回 `Err` |
| `abs` | Int/UInt/BigInt/Float | 同类型绝对值 | UInt 原样返回 |

未知函数名返回 `Err(ConstructError::Expr { message: "unknown function" })`。

### 4.6 条件表达式求值

`CondExpr::evaluate`：
1. 求值 `cond` 子表达式。
2. 用 `value_to_bool` 将结果转为 bool。
3. truthy → 求值并返回 `then_val`；falsy → 求值并返回 `else_val`。

**Python 真值规则**（`value_to_bool`）：
| Value 变体 | true 当且仅当 |
|-----------|--------------|
| `None` | 永远 false |
| `Bool(b)` | b |
| `Int(i)`/`UInt(u)`/`BigInt(i)` | 非零 |
| `Float(f)` | 非 0.0 |
| `Bytes(b)` | 非空 |
| `String(s)` | 非空 |
| `List(l)` | 非空 |
| `Container(c)` | 非空 |

### 4.7 ListPath 求值

`ListPath::evaluate`：
1. 获取列表值：
   - `inner` 为 `Some` → 求值 inner 表达式。
   - `inner` 为 `None`（裸模式）→ 从 `ctx.get("list_")` 查找。
2. 用 `as_list()` 验证为 `Value::List`，否则 `Err`。
3. 解析索引：`index < 0` → `len + index`（Python 风格负索引）。
4. 越界检查：`resolved_index < 0 || resolved_index >= len` → `Err`。
5. 返回 `list[resolved_index]`。

### 5.2 已知差异

**D1 — bare `this` 行为**：
- Python：`this(obj)` 返回完整 `obj`。
- Rust：bare `this`（无段）返回 `Err(ConstructError::Expr)`。
- 评估：Rust 更严格的错误检查是合理的设计选择。Context 不是 Value，"返回完整上下文"语义在 Rust 中不明确。

**D2 — 整数比较的类型严格性**：
- Python：`5 == 5`（int 无符号区分）→ `True`。
- Rust：`Int(5) == UInt(5)`（不同枚举变体）→ `false`。
- 评估：这是 `Value` 强类型枚举的固有差异。`Lt/Gt/Le/Ge` 比较（经 `apply_cmp`）通过数值转换避免了此问题，仅 `Eq/Ne` 受影响。在 construct 典型场景中（比较同类型字段）不会触发。

**D3 — 整数除法语义**：
- Python：`__truediv__`（`/`）产生 float（`10/3=3.333`），`__floordiv__`（`//`）产生 int（`10//3=3`）。
- Rust：`BinOp::Div` 对整数做整数除法（`10/3=3`），对浮点做浮点除法（`7.0/2.0=3.5`）。
- 评估：在 construct 典型场景（大小/偏移/计数计算）中，整数除法更实用且符合预期。记录为已知差异，不影响正确性。若需 Python `truediv` 行为，用户可显式转换为 Float。

**D4 — 逻辑运算非短路**：
- Python：`a and b` 若 `a` 为假则不求值 `b`（短路）。
- Rust：`BinOp::And` 先求值两个子表达式再运算（非短路）。
- 评估：表达式求值无副作用（纯计算），非短路不影响正确性或安全性，仅在不合法表达式（如 `x != 0 and 10/x > 1`）中会暴露差异——但此类模式在 construct 中不典型。

**D5 — 移位量限制**：
- Python：移位量无上限（Python int 任意宽度）。
- Rust：移位量 > 63 返回 `Err`。
- 评估：防止未定义行为的安全措施。construct 中不会出现 > 63 的移位量。

**D6 — `__pow__`/`__contains__`/`__pos__` 未实现**：
- 经查 construct 代码库，这三个运算符在实际构造器中无使用场景。按需补充。

- 功能覆盖：✅ 全部覆盖（list_/ListPath 已补齐）
- 行为一致性：✅ 一致（浮点比较已修正；溢出使用 wrapping 不 panic）
- 错误行为：✅ 对应

## 6. 设计决策记录

### D1 — 算术溢出使用 wrapping 语义（已采纳）

**决策**：`BinExpr` 算术运算（Add/Sub/Mul/Div/Mod）的整数溢出使用 `wrapping_*` 语义（回绕），而非 `checked_*`（返回 Err）。

**背景**：项目编码红线第 2 条要求"禁止 panic"。Python 的 `int` 为任意精度，永不溢出。Rust 的 `i64`/`u64`/`i128` 在 debug 模式下溢出会 panic。

**论证**：
1. `wrapping_*` 保证不 panic，满足红线要求。
2. `checked_*` 在溢出时返回 `Err`，语义上更接近 Python（Python 永不产生错误结果）。但 construct 典型场景中的值（文件大小、字段长度、数组计数）远小于 `i64::MAX`，溢出几乎不会发生。
3. REV 审查建议使用 `checked_*`，DEV 选择 `wrapping_*`。REV 在修复后审查中确认：**两种方案均满足"禁止 panic"要求，wrapping 在典型场景中更实用，属于合理的设计选择**。
4. wrapping 的缺点是溢出时产生"错误"结果（静默回绕而非报错）。在 construct 场景中这不会导致安全问题（最坏情况是错误的字段大小 → 解析错误，而非内存安全漏洞）。

**结论**：**算术溢出使用 wrapping 语义是可接受的**。当前设计在正确性（不 panic）、实用性（典型场景无差异）和简洁性之间取得了合理平衡。若未来需要严格匹配 Python 行为，可在 Phase 9（性能优化）阶段通过 feature flag 切换为 `checked_*`。

### D2 — UniOp::Neg / FuncPath::abs 在 i64::MIN 的理论 panic（已知遗留，后续处理）

**问题**：以下位置仍使用原始运算符，在 debug 模式下 `i64::MIN` / `i128::MIN` 时理论 panic：

| 位置 | 代码 | 触发条件 |
|------|------|---------|
| `expr.rs:701` | `Value::Int(i) => Ok(Value::Int(-i))` | `i == i64::MIN` |
| `expr.rs:703` | `Value::BigInt(i) => Ok(Value::BigInt(-i))` | `i == i128::MIN` |
| `expr.rs:871` | `Value::Int(i) => Ok(Value::Int(i.abs()))` | `i == i64::MIN` |
| `expr.rs:873` | `Value::BigInt(i) => Ok(Value::BigInt(i.abs()))` | `i == i128::MIN` |

**ARCH 回应：后续处理（建议修复但不阻塞当前阶段）**。

**论证**：
1. 触发条件极端：表达式求值恰好遇到 `i64::MIN`（`-9223372036854775808`）或 `i128::MIN` 的取负/取绝对值。construct 的典型值域（文件大小、字段偏移、计数）均为正数或远小于边界值。
2. 与 `apply_arithmetic` 的策略不一致：算术运算已统一为 wrapping，但 `UniExpr::Neg` 和 `FuncPath::abs` 遗漏了。这是审查过程中发现的遗漏，而非有意设计。
3. REF 与 REV 均确认此问题为 LOW 级别，不影响本次验证/审查通过。

**修复建议（供后续 Phase 处理）**：
```rust
// UniOp::Neg
Value::Int(i) => Ok(Value::Int(i.wrapping_neg())),
Value::BigInt(i) => Ok(Value::BigInt(i.wrapping_neg())),

// FuncPath::abs
Value::Int(i) => Ok(Value::Int(i.wrapping_abs())),
Value::BigInt(i) => Ok(Value::BigInt(i.wrapping_abs())),
```

> **注**：`wrapping_abs()` 对 `i64::MIN` 返回 `i64::MIN`（本身），这在数学上不正确（绝对值应为正），但保证不 panic。这是 wrapping 语义的固有妥协。若需正确结果，应在此处返回 `Err`。

**结论**：**建议改为 wrapping 方法以与 `apply_arithmetic` 保持一致**，但因触发条件极端、不影响典型用例，标记为后续处理（Phase 9 统一溢出策略时一并修复），不阻塞 Phase 5 验收。

### D3 — 浮点比较截断 bug（已修复）

**历史问题**：`apply_cmp` 的浮点回退分支原使用 `op(a as i64, b as i64)`，将 `f64` 截断为 `i64` 后用整数比较闭包比较。例如 `Float(0.9) > Float(0.1)` 截断为 `0 > 0` → `false`（应为 `true`）。

**修复**：`apply_cmp` 签名增加 `float_op: impl Fn(f64, f64) -> bool` 参数，回退分支改为 `float_op(a, b)` 直接进行 `f64` 比较。调用点（Lt/Gt/Le/Ge）传入对应的浮点比较闭包。

**验证**：
- 8 个浮点比较测试覆盖全部 6 种比较运算符（含 `Float(0.9) > Float(0.1)` 原始 bug 场景）。
- 测试均通过，确认 bug 已彻底消除。

**结论**：**浮点比较截断 bug 已完全修复**。当前 `apply_cmp` 实现正确：整数对使用 `int_op`（i64 比较），浮点/混合使用 `float_op`（f64 比较），两者分离，无截断。

### D4 — builder 方法而非 trait 重载（已采纳）

**决策**：`Path` 的运算符方法使用 builder 风格（`path.add(rhs)`）而非标准库 trait 重载（`impl Add for Path`）。

**论证**：
1. Trait 重载返回具体类型（如 `BinExpr`），无法自然表达 `Box<dyn Evaluate>` 返回值。Builder 方法可灵活返回具体类型。
2. Builder 方法命名清晰，与 Rust 生态惯例一致（如 `Iterator` 的适配器方法）。
3. 避免 `PartialEq`/`Eq` 的语义冲突：`Path` 实现了 `PartialEq` 用于结构比较（两个 Path 是否相同），若同时重载 `==` 运算符构建 `BinExpr` 会导致歧义。
4. 使用 `#[allow(clippy::should_implement_trait)]` 抑制方法名冲突警告（`add`/`sub` 等与 `Add`/`Sub` trait 方法同名）。

### D5 — 闭包桥接而非侵入已有构造器（已采纳）

**决策**：总纲 5.4 原计划"修改 Phase 2-4 构造器参数类型使用 `IntoExpr`"，DEV 决定**不修改已有构造器**，表达式系统通过闭包桥接。

**论证**：
1. 已有构造器（`If`、`Switch`、`Array` 等）接受 `Box<dyn Fn(&Context) -> ...>` 闭包。这些闭包签名已足够灵活。
2. 表达式求值结果可在闭包内直接使用，无需修改构造器签名：
   ```rust
   let expr = this_().field("count");
   If::new(Box::new(move |ctx| {
       expr.evaluate(ctx, None).map(|v| /* ... */).unwrap_or(false)
   }), ...)
   ```
3. 避免对已验收阶段的侵入性变更，降低回归风险。
4. `IntoExpr` trait 仍保留，为未来构造器原生支持表达式预留接口。

**影响**：当前用户需手写闭包桥接代码。若后续需要更简洁的集成，可提供适配器函数（如 `expr_to_cond(expr) -> CondFunc`）。

### D6 — FuncPath::sum 使用 checked_add 而非 wrapping（已采纳）

**决策**：`FuncPath::sum` 使用 `checked_add`（溢出返回 `Err`），与 `BinExpr` 算术的 `wrapping_*` 不一致。

**论证**：
1. `sum` 对列表元素累加，更容易溢出（列表越长越可能溢出），且求和结果通常有明确的预期值。
2. 二元算术运算（`a + b`）更倾向于性能和一致性（wrapping 无分支判断）。
3. 这是设计选择差异而非 bug——两种策略各有适用场景。REV 在审查备注中确认这一点。

**后续**：可在 Phase 9 统一语义（若决定全局采用 checked 或 wrapping）。

## 7. 边界条件清单

### Path
1. **bare this（无段）**：`Err(ConstructError::Expr)` — 比 Python 更严格
2. **bare obj_（无段）**：返回完整构建对象 `obj.clone()`
3. **obj_ 在 parse 阶段（obj=None）**：`Err(ConstructError::Expr)`
4. **字段缺失**：`Err(ConstructError::FieldMissing)`
5. **通过非 Container 值查找**：`Err(ConstructError::Generic)`
6. **`_` 段父导航**：由 `Context::get_path` 处理，上溯 parent 链
7. **全部为 `_` 段**：`Err(ConstructError::Generic)` — 至少需要一个真实 key

### ConstExpr
8. **无边界条件**：始终返回存储的值

### BinExpr 算术
9. **除零/模零**：`Err(ConstructError::Expr)`
10. **整数溢出**：wrapping 回绕（不 panic）
11. **非数值算术**（如 `String + Int`）：`Err(ConstructError::Expr)`
12. **混合类型提升**：Int+UInt→Int，BigInt 参与→BigInt，Float 参与→Float

### BinExpr 位运算
13. **非整数位运算**：`Err(ConstructError::Expr)`
14. **UInt 结果为负**：降级为 `Value::Int`

### BinExpr 移位
15. **移位量 > 63**：`Err(ConstructError::Expr)`
16. **移位量非整数**：`Err(ConstructError::Expr)`

### BinExpr 比较
17. **Eq/Ne 不同类型**：`false`/`true`（类型严格，不数值比较）
18. **Lt/Gt/Le/Ge 浮点**：正确 f64 比较（已修复截断 bug）

### BinExpr 逻辑
19. **非短路求值**：两个子表达式均求值
20. **Python 真值规则**：非零/非空为 true

### UniExpr
21. **Neg 非数值**：`Err(ConstructError::Expr)`
22. **Neg(UInt)**：返回 `Value::Int`（可能为负）
23. **Neg(i64::MIN)**：理论 panic（遗留，见 D2）
24. **BitNot 非整数**：`Err(ConstructError::Expr)`

### FuncPath
25. **len 非集合类型**：`Err(ConstructError::Expr)`
26. **sum 非列表**：`Err(ConstructError::Expr)`
27. **sum 空列表**：返回 `Value::Int(0)`
28. **sum 溢出**：`Err(ConstructError::Expr)`（checked_add）
29. **sum 元素非整数**：`Err(ConstructError::Expr)`
30. **min/max 空列表**：`Err(ConstructError::Expr)`
31. **abs 非数值**：`Err(ConstructError::Expr)`
32. **abs(i64::MIN)**：理论 panic（遗留，见 D2）
33. **abs(UInt)**：原样返回
34. **未知函数名**：`Err(ConstructError::Expr)`

### CondExpr
35. **条件非 Bool**：经 `value_to_bool` 转换（Python 真值规则）
36. **条件为 None/0/空集合**：走 else 分支

### ListPath
37. **裸模式无 `list_` 键**：`Err(ConstructError::Expr)`
38. **值非 List**：`Err(ConstructError::Expr)`
39. **空列表**：任何索引 → `Err(ConstructError::Expr)`（out of range）
40. **正索引越界**：`Err(ConstructError::Expr)`
41. **负索引越界**（如 `list_[-5]` on len=1）：`Err(ConstructError::Expr)`
42. **负索引解析**：`len + index`（Python 风格）

### IntoExpr
43. **usize → ConstExpr(UInt)**
44. **i64 → ConstExpr(Int)**
45. **u64 → ConstExpr(UInt)**
46. **Path → Box<Path>**
47. **ListPath → Box<ListPath>**
48. **Box<dyn Evaluate> → 自身**（无额外包装）
