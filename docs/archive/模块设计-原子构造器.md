# 模块设计：原子构造器（Phase 2）

## 模块位置

| 文件 | 内容 |
|------|------|
| `construct-rs/src/binary.rs` | 二进制工具函数（integer2bytes, bytes2integer, integer2bits, bits2integer 等） |
| `construct-rs/src/constructs/mod.rs` | 构造器模块注册和导出 |
| `construct-rs/src/constructs/bytes.rs` | Bytes, GreedyBytes |
| `construct-rs/src/constructs/format_field.rs` | FormatField |
| `construct-rs/src/constructs/bytes_integer.rs` | BytesInteger, BitsInteger |
| `construct-rs/src/constructs/varint.rs` | VarInt, ZigZag |
| `construct-rs/src/constructs/flag.rs` | Flag |
| `construct-rs/src/constructs/const_.rs` | Const |
| `construct-rs/src/constructs/meta.rs` | Pass, Terminated, Tell, Seek, Error |

## 职责

实现所有原子级构造器，这些是最基础的数据读写单元，直接与字节流交互，不包含任何子构造器（Const 除外，它使用 Subconstruct 包装）。

## 依赖决策

### 1. byteorder crate（feature = "byteorder"）

**决策：Phase 2 不使用 byteorder crate。手写字节序转换。**

理由：
- 标准库已提供 `from_be_bytes`/`from_le_bytes`/`to_be_bytes`/`to_le_bytes` 等方法
- 仅 FormatField 需要固定宽度数值序列化，Rust 标准库完全够用
- 减少必需依赖数量，与 Python 版本零依赖理念一致
- byteorder feature gate 保留在 Cargo.toml 中但不在核心路径使用

### 2. num-bigint crate（feature = "bigint"）

**决策：>8 字节大整数通过 `num-bigint` feature gate 支持。**

- `BytesInteger` 默认支持 1-8 字节（使用 `Value::Int`/`Value::UInt`/`Value::BigInt`）
- 启用 `bigint` feature 后支持任意字节数（使用 `num_bigint::BigInt`/`num_bigint::BigUint`）
- `VarInt` 使用 `Value::UInt`/`Value::BigInt` 即可，因为 VarInt 解码出的值可能非常大（如 `2**100`）

### 3. 表达式/上下文 lambda

**决策：Phase 2 中，需要动态长度参数的构造器（Bytes, BytesInteger, BitsInteger, Seek）暂时只接受固定 `usize`/`i64` 值。表达式 lambda 支持推迟到 Phase 5（表达式系统）完成后。**

理由：
- 当前 `Context` 不支持 lambda 求值
- Phase 2 专注于原子构造器本身的 parse/build/sizeof 逻辑正确性
- 后续通过泛型或 enum 参数扩展为支持 lambda

## 详细设计

### 1. 二进制工具模块（`binary.rs`）

对应 Python `construct/construct/lib/binary.py`。

```rust
/// 将整数转为大端字节序列。
/// `width` 为目标字节数。有符号整数使用二进制补码表示。
///
/// # Errors
/// - `width == 0` → Generic "width must be positive"
/// - 值超出 `[min, max]` 范围 → Generic "number does not fit width"
pub fn integer2bytes(value: i128, width: usize, signed: bool) -> Result<Vec<u8>>;

/// 将大端字节序列转为整数。
///
/// # Errors
/// - 空输入 → Generic "byte-string cannot be empty"
pub fn bytes2integer(data: &[u8], signed: bool) -> Result<i128>;

/// 将整数转为位串（每字节为 0x00 或 0x01，大端位序）。
/// `width` 为位数。
///
/// # Errors
/// - `width == 0` → Generic "width must be positive"
/// - 值超出范围 → Generic "number out of range"
pub fn integer2bits(value: i128, width: usize, signed: bool) -> Result<Vec<u8>>;

/// 将位串（每字节 0x00/0x01）转为整数。
///
/// # Errors
/// - 空输入 → Generic "bit-string cannot be empty"
pub fn bits2integer(data: &[u8], signed: bool) -> Result<i128>;

/// 反转字节序（endian swap）。
pub fn swapbytes(data: &[u8]) -> Vec<u8>;

/// 在位串中按字节组交换位置（用于 BitsInteger 的 swapped 模式）。
/// 长度必须是 8 的倍数。
///
/// # Errors
/// - 长度非 8 的倍数 → Generic "little-endianness only defined for multiples of 8"
pub fn swapbytesinbits(data: &[u8]) -> Result<Vec<u8>>;

/// 将字节串转换为位串（每个字节展开为 8 个 0x00/0x01 字节）。
pub fn bytes2bits(data: &[u8]) -> Vec<u8>;

/// 将位串转换为字节串（每 8 个位合并为一个字节）。
///
/// # Errors
/// - 长度非 8 的倍数 → Generic "data length must be a multiple of 8"
pub fn bits2bytes(data: &[u8]) -> Result<Vec<u8>>;
```

**Value 类型映射规则**：

| 字节数 | signed=false | signed=true |
|--------|-------------|-------------|
| 1 | `Value::UInt(u8)` | `Value::Int(i8 as i64)` |
| 2 | `Value::UInt(u16)` | `Value::Int(i16 as i64)` |
| 4 | `Value::UInt(u32)` | `Value::Int(i32 as i64)` |
| 8 | `Value::UInt(u64)` | `Value::Int(i64)` |
| 其他 | `Value::BigInt(i128)` | `Value::BigInt(i128)` |

**说明**：
- `bytes2integer` 返回 `i128`，由调用方根据长度和签名映射到合适的 `Value` 变体
- 1-8 字节使用 `Value::UInt` 或 `Value::Int`
- 其他长度使用 `Value::BigInt`

### 2. Bytes 构造器（`constructs/bytes.rs`）

#### 2.1 Bytes

```rust
/// 读取/写入固定长度字节的构造器。
///
/// 对应 Python `Bytes(length)`。
///
/// - parse: 从流中读取 `length` 字节 → `Value::Bytes`
/// - build: 将 `Value::Bytes`（或整数展开为字节）写入流
/// - sizeof: 返回 `length`
pub struct Bytes {
    /// 要读写的字节数。
    pub length: usize,
}

impl Bytes {
    pub fn new(length: usize) -> Self;
}

impl Construct for Bytes {
    fn parse(&self, stream: &mut dyn Stream, _ctx: &mut Context) -> Result<Value>;
    fn build(&self, data: &Value, stream: &mut dyn Stream, _ctx: &mut Context) -> Result<()>;
    fn sizeof(&self, _ctx: &Context) -> Result<usize>;
}
```

**parse 行为**：
1. `stream.read_bytes(self.length)` → `Value::Bytes(data)`

**build 行为**（对齐 Python）：
1. 如果 `data` 是 `Value::Bytes`，直接写入（长度必须等于 `self.length`）
2. 如果 `data` 是整数类型（`Int`/`UInt`/`BigInt`），调用 `integer2bytes(obj, length, signed=false)` 展开
3. 其他类型 → `ConstructError::TypeMismatch`

**sizeof 行为**：返回 `Ok(self.length)`。

#### 2.2 GreedyBytes

```rust
/// 读取流中所有剩余字节的构造器。
///
/// 对应 Python `GreedyBytes`（单例）。
///
/// - parse: 读取到流末尾 → `Value::Bytes`
/// - build: 写入 `Value::Bytes`
/// - sizeof: 返回 `Sizeof` 错误（大小不确定）
pub struct GreedyBytes;

impl GreedyBytes {
    pub fn new() -> Self;
}

impl Construct for GreedyBytes { ... }
```

**parse 行为**：
1. 通过 `ByteStream::remaining_bytes()` 或流 `size() - tell()` 获取剩余字节
2. 读取所有剩余字节 → `Value::Bytes`

**build 行为**：
1. 取 `data.as_bytes()?`，写入流

**sizeof 行为**：返回 `Err(ConstructError::Sizeof { reason: "GreedyBytes has undefined size" })`

> **Stream 扩展需求**：需要为 `Stream` trait 添加 `read_remaining(&mut self) -> Result<Vec<u8>>` 方法，或在 `ByteStream` 上提供此功能。当前 `ByteStream` 已有 `remaining_bytes()` 方法，但 `Stream` trait 没有对应的接口。设计为：在 `Stream` trait 中添加 `read_remaining` 默认方法（基于 `size() - tell()` + `read_bytes`），`ByteStream` 可以覆写以优化。

### 3. FormatField 构造器（`constructs/format_field.rs`）

```rust
/// 字节序枚举。
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Endianness {
    /// 大端（Python `>`）
    Big,
    /// 小端（Python `<`）
    Little,
    /// 本机字节序（Python `=`）
    Native,
}

/// 数值格式类型。
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum FormatKind {
    /// `b` — signed 8-bit
    I8,
    /// `B` — unsigned 8-bit
    U8,
    /// `h` — signed 16-bit
    I16,
    /// `H` — unsigned 16-bit
    U16,
    /// `i`/`l` — signed 32-bit
    I32,
    /// `I`/`L` — unsigned 32-bit
    U32,
    /// `q` — signed 64-bit
    I64,
    /// `Q` — unsigned 64-bit
    U64,
    /// `e` — IEEE 754 half-precision (16-bit)
    F16,
    /// `f` — IEEE 754 single-precision (32-bit)
    F32,
    /// `d` — IEEE 754 double-precision (64-bit)
    F64,
}

/// 基于 Rust 原生数值类型的定宽数值字段构造器。
///
/// 对应 Python `FormatField(endianity, format)`。
///
/// 支持所有 Python FormatField 支持的格式字符（除 `?` 布尔，由 Flag 处理）。
pub struct FormatField {
    pub endian: Endianness,
    pub kind: FormatKind,
}

impl FormatField {
    pub fn new(endian: Endianness, kind: FormatKind) -> Self;

    /// 返回此格式占用的字节数。
    pub fn byte_size(&self) -> usize;
}

impl Construct for FormatField { ... }
```

**parse 行为**：
1. `stream.read_bytes(self.byte_size())` 读取原始字节
2. 根据 endian + kind 解包为 `Value`

**build 行为**：
1. 根据 data 类型检查（整数或浮点）
2. 根据 endian + kind 打包为字节
3. 写入流

**sizeof 行为**：返回 `Ok(self.byte_size())`。

**各格式对应的 Value 变体**：

| FormatKind | 字节数 | parse 返回 | build 接受 |
|-----------|--------|-----------|-----------|
| I8 | 1 | `Value::Int(i8 as i64)` | 任意整数 |
| U8 | 1 | `Value::UInt(u8 as u64)` | 任意整数 |
| I16 | 2 | `Value::Int(i16 as i64)` | 任意整数 |
| U16 | 2 | `Value::UInt(u16 as u64)` | 任意整数 |
| I32 | 4 | `Value::Int(i32 as i64)` | 任意整数 |
| U32 | 4 | `Value::UInt(u32 as u64)` | 任意整数 |
| I64 | 8 | `Value::Int(i64)` | 任意整数 |
| U64 | 8 | `Value::UInt(u64)` | 任意整数 |
| F16 | 2 | `Value::Float(f32)` | 数值 |
| F32 | 4 | `Value::Float(f32 as f64)` | 数值 |
| F64 | 8 | `Value::Float(f64)` | 数值 |

**半精度浮点（F16）实现**：使用 `half` crate 或手写 f16↔f32 转换。决策：手写转换（约 30 行代码），避免引入新依赖。转换算法使用位操作：提取符号位、指数、尾数，重新组装为 f32 的 IEEE 754 表示。

#### 3.1 便捷常量


### 4. BytesInteger 构造器（`constructs/bytes_integer.rs`）

#### 4.1 BytesInteger

```rust
/// 任意字节数的整数构造器。
///
/// 对应 Python `BytesInteger(length, signed=False, swapped=False)`。
///
/// - parse: 读取 `length` 字节 → 整数 `Value`
/// - build: 整数 `Value` → 写入 `length` 字节
/// - sizeof: 返回 `length`
pub struct BytesInteger {
    /// 字节数。
    pub length: usize,
    /// 是否有符号（二进制补码）。
    pub signed: bool,
    /// 是否交换字节序（小端）。
    pub swapped: bool,
}

impl BytesInteger {
    pub fn new(length: usize, signed: bool, swapped: bool) -> Self;
}

impl Construct for BytesInteger { ... }
```

**parse 行为**（对齐 Python）：
1. 检查 `length > 0`，否则 `IntegerError`
2. `stream.read_bytes(length)`
3. 如果 `swapped`，反转字节序（`swapbytes`）
4. 调用 `bytes2integer(data, signed)`
5. 根据长度和 signed 映射到合适的 `Value` 变体

**build 行为**：
1. 检查 data 是否为整数类型
2. 检查 `length > 0`
3. 调用 `integer2bytes(obj, length, signed)` 得到字节
4. 如果 `swapped`，反转字节序
5. 写入流

**sizeof 行为**：返回 `Ok(self.length)`。

**Value 类型映射**（与 binary.rs 中相同规则）：

| length | signed=false | signed=true |
|--------|-------------|-------------|
| 1 | `Value::UInt` | `Value::Int` |
| 2 | `Value::UInt` | `Value::Int` |
| 4 | `Value::UInt` | `Value::Int` |
| 8 | `Value::UInt` | `Value::Int` |
| 其他 | `Value::BigInt` | `Value::BigInt` |

#### 4.2 便捷常量（24-bit 整数）

```rust
pub const INT24UB: BytesInteger = BytesInteger { length: 3, signed: false, swapped: false };
pub const INT24UL: BytesInteger = BytesInteger { length: 3, signed: false, swapped: true };
pub const INT24SB: BytesInteger = BytesInteger { length: 3, signed: true, swapped: false };
pub const INT24SL: BytesInteger = BytesInteger { length: 3, signed: true, swapped: true };
// Native endian需要运行时判断，用函数代替
pub fn int24un() -> BytesInteger;
pub fn int24sn() -> BytesInteger;
```

#### 4.3 BitsInteger

```rust
/// 任意位数的整数构造器。
///
/// 对应 Python `BitsInteger(length, signed=False, swapped=False)`。
///
/// **必须在 Bitwise 上下文中使用**（位流操作）。
///
/// - parse: 读取 `length` 个位（每字节为 0x00 或 0x01）→ 整数 `Value`
/// - build: 整数 `Value` → 写入 `length` 个位
/// - sizeof: 返回 `length`（以位为单位的字节数）
pub struct BitsInteger {
    /// 位数。
    pub length: usize,
    /// 是否有符号。
    pub signed: bool,
    /// 是否交换字节序（仅当 length 是 8 的倍数时有效）。
    pub swapped: bool,
}

impl BitsInteger {
    pub fn new(length: usize, signed: bool, swapped: bool) -> Self;
}

impl Construct for BitsInteger { ... }
```

**parse 行为**（对齐 Python）：
1. 检查 `length > 0`
2. `stream.read_bytes(length)` — 在位流中，每个"字节"代表一个位（0x00 或 0x01）
3. 如果 `swapped`，调用 `swapbytesinbits(data)`
4. 调用 `bits2integer(data, signed)` → 映射到 `Value`

**build 行为**：
1. 检查 data 是否为整数类型
2. 检查 `length > 0`
3. 调用 `integer2bits(obj, length, signed)` 得到位串
4. 如果 `swapped`，调用 `swapbytesinbits(data)`
5. 写入流

**sizeof 行为**：返回 `Ok(self.length)`。

#### 4.4 位级便捷常量

```rust
/// 1-bit integer（必须在 Bitwise 上下文中使用）
pub const BIT: BitsInteger = BitsInteger { length: 1, signed: false, swapped: false };
/// 4-bit integer
pub const NIBBLE: BitsInteger = BitsInteger { length: 4, signed: false, swapped: false };
/// 8-bit integer
pub const OCTET: BitsInteger = BitsInteger { length: 8, signed: false, swapped: false };
```

### 5. VarInt / ZigZag 构造器（`constructs/varint.rs`）

#### 5.1 VarInt

```rust
/// LEB128 无符号变长整数编解码。
///
/// 对应 Python `VarInt`（单例）。
///
/// - parse: 读取 LEB128 编码字节 → `Value::UInt` 或 `Value::BigInt`
/// - build: 将非负整数编码为 LEB128 写入流
/// - sizeof: 返回 `Sizeof` 错误（大小不确定）
pub struct VarInt;

impl VarInt {
    pub fn new() -> Self;
}

impl Construct for VarInt { ... }
```

**parse 行为**（对齐 Python）：
1. 循环读取单字节，取低 7 位追加到累加器
2. 如果高位置 1（`b & 0x80 != 0`），继续读取
3. 将所有 7 位块从最低有效位到最高有效位组合为整数
4. 结果值映射到 `Value::UInt`（≤ u64::MAX）或 `Value::BigInt`（> u64::MAX）

**build 行为**：
1. 检查 data 是否为整数类型
2. 检查值 ≥ 0，否则 `ConstructError::Generic("VarInt cannot build from negative number")`
3. LEB128 编码：反复取低 7 位，若还有更高位则设置高位标记
4. 写入所有编码字节

**sizeof 行为**：返回 `Err(ConstructError::Sizeof { reason: "VarInt has variable size" })`

#### 5.2 ZigZag

```rust
/// ZigZag 编码的有符号整数（基于 VarInt）。
///
/// 对应 Python `ZigZag`（单例）。
///
/// - parse: 读取 VarInt → ZigZag 解码 → `Value::Int` 或 `Value::BigInt`
/// - build: ZigZag 编码 → VarInt 写入流
/// - sizeof: 返回 `Sizeof` 错误
pub struct ZigZag;

impl ZigZag {
    pub fn new() -> Self;
}

impl Construct for ZigZag { ... }
```

**ZigZag 编解码规则**（对齐 Python）：
- 编码（build）：`n >= 0 → 2*n`，`n < 0 → 2*|n| - 1`
- 解码（parse）：`x & 1 == 0 → x/2`，`x & 1 == 1 → -(x/2 + 1)`

**parse 行为**：
1. 调用 `VarInt.parse()` 得到无符号整数
2. 应用 ZigZag 解码
3. 映射到 `Value::Int`（如果值在 i64 范围内）或 `Value::BigInt`

**build 行为**：
1. 检查 data 是否为整数类型
2. 应用 ZigZag 编码
3. 调用 `VarInt.build()` 写入

**sizeof 行为**：返回 `Err(ConstructError::Sizeof { reason: "ZigZag has variable size" })`

### 6. Flag 构造器（`constructs/flag.rs`）

```rust
/// 单字节（或单位）布尔值构造器。
///
/// 对应 Python `Flag`。
///
/// - parse: 读取 1 字节，非零为 true → `Value::Bool`
/// - build: `Value::Bool` → 写入 0x00 或 0x01
/// - sizeof: 返回 1
pub struct Flag;

impl Flag {
    pub fn new() -> Self;
}

impl Construct for Flag { ... }
```

**parse 行为**：
1. `stream.read_bytes(1)` 读取 1 字节
2. `data != b"\x00"` → `Value::Bool(true/false)`

**build 行为**：
1. 取 `data.as_bool()?`
2. `true` → 写入 `b"\x01"`，`false` → 写入 `b"\x00"`

**sizeof 行为**：返回 `Ok(1)`。

### 7. Const 构造器（`constructs/const_.rs`）

```rust
/// 常量校验构造器。
///
/// 对应 Python `Const(value, subcon=None)`。
///
/// - parse: 通过 subcon 解析，校验结果等于 value
/// - build: 忽略传入值，使用 value 通过 subcon 构建
/// - sizeof: 返回 subcon 的大小
pub struct Const {
    /// 预期的常量值。
    pub value: Value,
    /// 用于解析/构建的子构造器。
    pub subcon: Box<dyn Construct>,
}

impl Const {
    /// 创建字节常量：`Const::new_bytes(b"IHDR")`
    /// 自动创建 `Bytes(len)` 作为 subcon
    pub fn new_bytes(value: Vec<u8>) -> Self;

    /// 创建数值常量：`Const::new_value(Value::UInt(255), Box::new(Int32UL))`
    pub fn new_value(value: Value, subcon: Box<dyn Construct>) -> Self;
}

impl Construct for Const { ... }
```

**parse 行为**（对齐 Python）：
1. 调用 `self.subcon.parse(stream, ctx)` 得到 `obj`
2. 比较 `obj == self.value`，不匹配则 `ConstructError::Const`
3. 返回 `obj`

**build 行为**：
1. 如果 `data` 是 `Value::None` 或等于 `self.value`，使用 `self.value` 构建
2. 否则 `ConstructError::Const`
3. 调用 `self.subcon.build(&self.value, stream, ctx)`

**sizeof 行为**：`self.subcon.sizeof(ctx)`

> **设计说明**：Python 的 `Const` 继承自 `Subconstruct`，但 Rust 中我们不继承 `Subconstruct`，而是直接包含 `subcon` 字段。这是因为 Const 的行为与 Subconstruct 的完全委托语义不同（Const 需要在 parse 中校验、在 build 中忽略传入值）。

### 8. Pass / Terminated / Tell / Seek / Error 构造器（`constructs/meta.rs`）

#### 8.1 Pass

```rust
/// 无操作构造器。
///
/// 对应 Python `Pass`（单例）。
///
/// - parse: 返回 `Value::None`
/// - build: 不写入任何数据
/// - sizeof: 返回 0
pub struct Pass;

impl Construct for Pass { ... }
```

#### 8.2 Terminated

```rust
/// 验证已到达流末尾的构造器。
///
/// 对应 Python `Terminated`（单例）。
///
/// - parse: 检查流是否在 EOF，否则 `ConstructError::Terminated`
/// - build: 不写入任何数据
/// - sizeof: 返回 `Sizeof` 错误
pub struct Terminated;

impl Construct for Terminated { ... }
```

**parse 行为**：
1. 尝试 `stream.read_bytes(1)`
2. 如果成功（还有数据），返回 `ConstructError::Terminated { remaining: ... }`
3. 如果失败（EOF），返回 `Value::None`

> **设计说明**：Python 使用 `stream.read(1)` 来检测是否还有数据。在 Rust 中，我们使用 `stream.is_eof()` 来检查。但如果 `is_eof()` 返回 false，还需要计算 remaining bytes。替代方案：使用 `stream.size() - stream.tell()` 计算 remaining。

**实际 parse 逻辑**：
1. 检查 `stream.is_eof()?`
2. 如果不在 EOF，计算 `remaining = stream.size()? - stream.tell()?`，返回 `ConstructError::Terminated { path, remaining: remaining as usize }`
3. 如果在 EOF，返回 `Ok(Value::None)`

**build 行为**：直接返回 `Ok(())`（对齐 Python `_build` 返回 `obj` 但不写入）。

**sizeof 行为**：返回 `Err(ConstructError::Sizeof { reason: "Terminated has undefined size" })`

#### 8.3 Tell

```rust
/// 返回当前流位置的构造器。
///
/// 对应 Python `Tell`（单例）。
///
/// - parse: 返回当前流位置 → `Value::UInt`
/// - build: 返回当前流位置 → `Value::UInt`
/// - sizeof: 返回 0
pub struct Tell;

impl Construct for Tell { ... }
```

**parse/build 行为**：`stream.tell()` → `Value::UInt(pos)`

#### 8.4 Seek

```rust
/// 跳转到指定流位置的构造器。
///
/// 对应 Python `Seek(at, whence=0)`。
///
/// - parse: seek 到指定位置，返回新位置 → `Value::UInt`
/// - build: seek 到指定位置，返回新位置 → `Value::UInt`
/// - sizeof: 返回 `Sizeof` 错误
pub struct Seek {
    /// 目标位置偏移量。
    pub at: i64,
    /// 偏移基准：0=开头, 1=当前位置, 2=末尾。
    pub whence: SeekWhence,
}

/// 偏移基准枚举。
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum SeekWhence {
    /// 从流开头计算偏移（Python whence=0）
    Start,
    /// 从当前位置计算偏移（Python whence=1）
    Current,
    /// 从流末尾计算偏移（Python whence=2）
    End,
}

impl Seek {
    pub fn new(at: i64) -> Self;
    pub fn with_whence(at: i64, whence: SeekWhence) -> Self;
}

impl Construct for Seek { ... }
```

> **Stream 扩展需求**：当前 `Stream` trait 的 `seek` 方法只支持绝对位置（`u64`）。需要扩展为支持 whence 参数。两种方案：
>
> **方案 A**（推荐）：在 `Stream` trait 中新增 `seek_from(&mut self, offset: i64, whence: SeekFrom) -> Result<u64>`，使用 `std::io::SeekFrom`。
>
> **方案 B**：在 `Seek` 构造器内部根据 whence 计算 `u64` 绝对位置，然后调用现有的 `seek(u64)`。
>
> 选择方案 A，因为它更精确地匹配 Python 的 `stream.seek(offset, whence)` 行为。

**parse/build 行为**：
1. 调用 `stream.seek_from(self.at, whence)` → `Value::UInt(new_pos)`

#### 8.5 Error

```rust
/// 无条件抛出错误的构造器。
///
/// 对应 Python `Error`（单例）。
///
/// - parse: 总是返回 `ConstructError::Check`（"Error field was activated during parsing"）
/// - build: 总是返回 `ConstructError::Check`（"Error field was activated during building"）
/// - sizeof: 总是返回 `ConstructError::Sizeof`
pub struct Error;

impl Construct for Error { ... }
```

> **设计说明**：Python 的 `Error` 抛出 `ExplicitError`。Rust 中没有 `ExplicitError` 变体，使用 `ConstructError::Check` 代替，因为语义相近（都是主动触发的错误）。如果后续需要区分，可以新增 `ConstructError::Explicit` 变体。

## Stream trait 扩展

Phase 2 需要以下 `Stream` trait 扩展：

### 1. read_remaining

```rust
/// 读取从当前位置到流末尾的所有字节。
fn read_remaining(&mut self) -> Result<Vec<u8>>;
```

默认实现：`size() - tell()` + `read_bytes()`。`ByteStream` 覆写为直接切片。

### 2. seek_from

```rust
use std::io::SeekFrom;

/// 按指定基准和偏移量定位流。
fn seek_from(&mut self, pos: SeekFrom) -> Result<u64>;
```

`ByteStream` 实现使用 `std::io::Cursor::seek()`。

### ByteStream 新增方法

```rust
impl ByteStream {
    /// 使用 std::io::Seek 实现 whence-aware seeking
    pub fn seek_from(&mut self, pos: SeekFrom) -> Result<u64>;
}
```

## 错误处理方案

| 场景 | 错误类型 |
|------|---------|
| 流读取不足 | `ConstructError::Stream` |
| 格式字段解包失败 | `ConstructError::FormatField` |
| 整数溢出/范围错误 | `ConstructError::Generic`（"value X out of range"） |
| Const 校验失败 | `ConstructError::Const` |
| 流未结束（Terminated） | `ConstructError::Terminated` |
| VarInt 负数 | `ConstructError::Generic`（"VarInt cannot build from negative number"） |
| 类型不匹配 | `ConstructError::TypeMismatch` |
| 大小无法确定 | `ConstructError::Sizeof` |
| 无条件错误（Error） | `ConstructError::Check` |

> **关于 IntegerError**：Python 有专门的 `IntegerError` 异常。当前 Rust `ConstructError` 中没有 `Integer` 变体。使用 `ConstructError::Generic` 并在 message 中说明具体原因。如果后续需要更精细的错误匹配，可以新增 `Integer` 变体。

## 边界条件清单

### Bytes
1. **length = 0**：parse 返回空 `Value::Bytes(vec![])`，build 接受空 bytes
2. **流不足**：parse 时流剩余 < length → `ConstructError::Stream`
3. **build 数据长度不匹配**：`Value::Bytes` 长度 ≠ length → `ConstructError::Stream`
4. **build 整数展开**：整数太大无法填入 length 字节 → `ConstructError::Generic`

### GreedyBytes
5. **空流**：parse 返回 `Value::Bytes(vec![])`
6. **build 非 bytes 类型**：`ConstructError::TypeMismatch`

### FormatField
7. **流不足**：parse 时 → `ConstructError::Stream`
8. **值超范围**：build 时整数超出格式范围 → `ConstructError::FormatField`
9. **类型不匹配**：build 时传入非数值 → `ConstructError::TypeMismatch`
10. **F16 特殊**：半精度浮点精度有限

### BytesInteger
11. **length = 0**：→ `ConstructError::Generic("length must be positive")`
12. **值超范围**：有符号值超出给定字节数能表示的范围 → `ConstructError::Generic`
13. **非整数输入**：build 时传入 `Value::String` → `ConstructError::TypeMismatch`

### BitsInteger
14. **length = 0**：→ `ConstructError::Generic("length must be positive")`
15. **swapped + length 非 8 倍数**：→ `ConstructError::Generic("little-endianness only defined for multiples of 8")`
16. **值超范围**：值超出给定位数能表示的范围 → `ConstructError::Generic`

### VarInt
17. **值 = 0**：编码为单字节 `0x00`
18. **负数**：build 时 → `ConstructError::Generic("VarInt cannot build from negative number")`
19. **超大值**：如 `2^100`，编码为多字节 → `Value::BigInt`
20. **流中途结束**：parse 时流耗尽但高位标记仍为 1 → `ConstructError::Stream`

### ZigZag
21. **负数**：正确编码（ZigZag 专门设计处理负数）
22. **0**：编码为 `0x00`
23. **-1**：编码为 `0x01`

### Flag
24. **0x00** → `false`
25. **任意非零值** → `true`（包括 0x02, 0xFF 等）
26. **非 Bool 类型 build**：`ConstructError::TypeMismatch`

### Const
27. **parse 匹配**：返回解析值
28. **parse 不匹配**：`ConstructError::Const`
29. **build None**：使用 `self.value` 构建（对齐 Python `flagbuildnone`）
30. **build 错误值**：值不是 None 也不是 self.value → `ConstructError::Const`

### Pass
31. **无边界条件**：总是成功

### Terminated
32. **流在 EOF**：parse 返回 `Value::None`
33. **流不在 EOF**：`ConstructError::Terminated` 并报告剩余字节数

### Tell
34. **空流**：返回位置 0
35. **无边界条件**：总是成功

### Seek
36. **负偏移 + whence=Start**：需要在 `seek_from` 中处理
37. **偏移超出流大小**：Cursor 允许 seek 超出末尾

### Error
38. **总是失败**：parse/build/sizeof 均返回错误

## 模块文件组织方案

