# 模块设计：适配器与控制流（Phase 4）

## 模块位置

| 文件 | 内容 |
|------|------|
| `construct-rs/src/constructs/adapters.rs` | Adapter, SymmetricAdapter, ExprAdapter, Validator, ExprValidator |
| `construct-rs/src/constructs/enum_.rs` | Enum, FlagsEnum, Mapping |
| `construct-rs/src/constructs/hex.rs` | Hex, HexDump |
| `construct-rs/src/constructs/control_flow.rs` | IfThenElse, Switch, Check, StopIf |
| `construct-rs/src/constructs/computed.rs` | Computed, Rebuild, Default, Index, Padded, Aligned, FixedSized, NamedTuple, TimestampAdapter |

## 职责

实现所有适配器（值转换/验证）、枚举映射、显示包装、控制流（条件分支/断言/终止信号）、以及计算/重建/默认值/索引/填充/对齐/定长/命名元组/时间戳等辅助构造器。

## 详细设计

### 1. Adapter + SymmetricAdapter + ExprAdapter（`constructs/adapters.rs`）

```rust
// ---- 闭包类型别名 ----

/// decode 函数：inner parse 后对值做转换。对应 Python `Adapter._decode(obj, context, path)`。
pub type DecodeFunc = Box<dyn Fn(&Value, &Context) -> Result<Value>>;

/// encode 函数：build 前对用户值做转换。对应 Python `Adapter._encode(obj, context, path)`。
pub type EncodeFunc = Box<dyn Fn(&Value, &Context) -> Result<Value>>;

/// 对称转换函数：decode/encode 使用同一函数。
pub type SymmetricFunc = Box<dyn Fn(&Value, &Context) -> Result<Value>>;

/// 双向适配器。
///
/// - parse: inner.parse → decode(value)
/// - build: encode(value) → inner.build
/// - sizeof: 委托 inner
pub struct Adapter {
    pub subcon: Box<dyn Construct>,
    pub decode: DecodeFunc,
    pub encode: EncodeFunc,
}

impl Adapter {
    pub fn new(subcon: Box<dyn Construct>, decode: DecodeFunc, encode: EncodeFunc) -> Self;
}

/// 对称适配器：parse 和 build 使用同一函数。
pub struct SymmetricAdapter {
    pub subcon: Box<dyn Construct>,
    pub func: SymmetricFunc,
}

impl SymmetricAdapter {
    pub fn new(subcon: Box<dyn Construct>, func: SymmetricFunc) -> Self;
}

/// ExprAdapter：Adapter 的语义别名，表示闭包来源于表达式系统（Phase 5）。
/// 功能与 Adapter 完全一致。
pub struct ExprAdapter {
    pub subcon: Box<dyn Construct>,
    pub decode: DecodeFunc,
    pub encode: EncodeFunc,
}

impl ExprAdapter {
    pub fn new(subcon: Box<dyn Construct>, decode: DecodeFunc, encode: EncodeFunc) -> Self;
}
```

### 3. Enum + FlagsEnum + Mapping（`constructs/enum_.rs`）

```rust
/// 整数 ↔ 字符串双向枚举映射。
///
/// 对应 Python `Enum(subcon, **mapping)`。
///
/// - parse: inner.parse → 整数 → decmap 查找 → String 或原始整数
/// - build: String → mapping 查找 → 整数 → inner.build；整数直接传递
pub struct Enum {
    pub subcon: Box<dyn Construct>,
    pub mapping: IndexMap<String, u64>,   // 编码：label → value
    pub decmap: IndexMap<u64, String>,    // 解码：value → label（自动构建）
}

impl Enum {
    pub fn new(subcon: Box<dyn Construct>, mapping: IndexMap<String, u64>) -> Self;
}

/// 位标志枚举：整数 → Container<Bool>。
///
/// 对应 Python `FlagsEnum(subcon, **flags)`。
pub struct FlagsEnum {
    pub subcon: Box<dyn Construct>,
    pub flags: IndexMap<String, u64>,     // flag name → bit value
}

impl FlagsEnum {
    pub fn new(subcon: Box<dyn Construct>, flags: IndexMap<String, u64>) -> Self;
}

/// 通用双向值映射。
///
/// 对应 Python `Mapping(subcon, mapping)`。
/// 使用 `Vec<(Value, Value)>` 而非 HashMap，因为 `Value` 包含 `f64`，无法实现 `Hash + Eq`。
pub struct Mapping {
    pub subcon: Box<dyn Construct>,
    pub mapping: Vec<(Value, Value)>,     // 编码：(build_key, build_value)
    pub decmapping: Vec<(Value, Value)>,  // 解码：(parse_value, return_key)（自动构建）
}

impl Mapping {
    pub fn new(subcon: Box<dyn Construct>, mapping: Vec<(Value, Value)>) -> Self;
}
```

**FlagsEnum build 特殊行为**：跳过以 `_` 开头的键（对齐 Python 的内部键过滤，如 `_io`、`_index` 等）。

### 6. Switch（`constructs/control_flow.rs`）


## 边界条件清单

### Adapter
1. **decode 返回错误**：parse → 传播该错误
2. **encode 返回错误**：build → 传播该错误
3. **inner parse 失败**：→ 传播 inner 错误
4. **嵌套 Adapter**：外层 decode 接收内层 decode 结果（组合正确）

### SymmetricAdapter
5. **同一函数双向**：parse 和 build 使用相同 func
6. **func 返回错误**：parse/build 均传播

### Validator
7. **验证通过**：值原样传递（不被修改）
8. **验证失败**：→ `ConstructError::Validation`
9. **build 时验证先于 inner.build**：值不会被写入流

### Enum
10. **parse 已映射值**：→ `Value::String`
11. **parse 未映射值**：→ 原始整数（默认映射行为）
12. **build 字符串标签**：→ 查找 mapping → 整数
13. **build 未知字符串**：→ `ConstructError::Mapping`
14. **build 整数**：直接传递（pass-through）
15. **流不足**：→ inner parse 错误传播

### FlagsEnum
16. **所有标志位设置**：全部 true
17. **无标志位设置**：全部 false
18. **未定义的额外位**：忽略（不影响已定义标志）
19. **build 跳过 `_` 前缀键**：如 `_flagsenum`
20. **build 未知标志名**：→ `ConstructError::Mapping`
21. **build 非 Container 输入**：→ `ConstructError::TypeMismatch`

### Mapping
22. **parse 已映射值**：→ 对应返回值
23. **parse 未映射值**：→ `ConstructError::Mapping`
24. **build 已映射键**：→ 查找并传递给 inner
25. **build 未映射键**：→ `ConstructError::Mapping`
26. **空 mapping**：parse/build 总是失败

### Hex / HexDump
27. **透传**：parse/build/sizeof 完全委托 inner
28. **无 Display 覆盖**：Rust 中无法实现 Python 的 `__str__` 效果

### IfThenElse
29. **cond = true**：使用 then_constr
30. **cond = false**：使用 else_constr
31. **flagbuildnone**：两个分支均为 true 时返回 true

### Switch
32. **键匹配某个 case**：使用对应子构造器
33. **键不匹配任何 case + default=Some**：使用 default
34. **键不匹配任何 case + default=None**：使用 Pass（不消费流）
35. **keyfunc 返回错误**：传播错误
36. **flagbuildnone**：所有 cases + default 均为 true 时返回 true

### Check
37. **条件通过**：parse → `Value::None`，build → `Ok(())`
38. **条件失败**：→ `ConstructError::Check`
39. **不读写流**

### StopIf
40. **cond = true**：parse/build → `ConstructError::StopField`
41. **cond = false**：parse → `Value::None`，build → `Ok(())`
42. **sizeof**：→ `ConstructError::Sizeof`

### Computed
43. **func 返回错误**：传播
44. **不消费流**：parse 后流位置不变
45. **sizeof**：→ `Ok(0)`

### Rebuild
46. **build 忽略输入**：始终使用 func(ctx) 结果
47. **flagbuildnone**：true

### Default
48. **build None**：使用 `self.value`
49. **build 非 None**：使用输入值

### Index
50. **上下文有 `_index`**：返回该值
51. **上下文无 `_index`**：返回 `Value::None`

### Padded
52. **inner 消费 > length**：→ `ConstructError::Padding`
53. **strict=true 且填充字节不匹配**：→ `ConstructError::Padding`
54. **sizeof**：→ `Ok(length)`

### Aligned
55. **modulus < 2**：→ `ConstructError::Padding`
56. **已对齐**：pad = 0，不额外填充
57. **sizeof**：round_up(inner_sizeof, modulus)

### FixedSized
58. **parse**：读取 length 字节到子流，子构造器从子流解析
59. **build 超长**：→ `ConstructError::Padding`
60. **build 不足**：填充 0x00 至 length
61. **sizeof**：→ `Ok(length)`

### NamedTuple
62. **inner 返回 List**：按位置映射字段名
63. **inner 返回 Container**：按名称提取值
64. **列表长度 ≠ 字段名数量**：→ `ConstructError::Array`
65. **非 List/Container 输入**：→ `ConstructError::TypeMismatch`

### TimestampAdapter
66. **Seconds**：nanos = 0
67. **Milliseconds/Micros/Nanos**：拆分 secs 和 nanos
68. **build 缺少 secs/nanos 字段**：→ `ConstructError::FieldMissing`

## 设计决策记录

### 设计质疑回复：Adapter 闭包组合 vs Python 虚继承

**质疑来源**：Python 的 `Adapter` 是抽象基类，用户通过继承并重写 `_decode`/`_encode` 方法创建适配器。Rust 使用 `Box<dyn Fn>` 闭包注入。

**回应**：**确认设计正确**

**说明**：

Python 的 Adapter 模式依赖虚方法表分派（virtual method dispatch）：
```python
class MyAdapter(Adapter):
    def _decode(self, obj, context, path):
        return transform(obj)
    def _encode(self, obj, context, path):
        return inverse(obj)
```

Rust 没有继承，但闭包提供了同等的运行时多态能力：
```rust
let adapter = Adapter::new(
    subcon,
    Box::new(|obj, ctx| Ok(transform(obj))),
    Box::new(|obj, ctx| Ok(inverse(obj))),
);
```

**选择闭包而非 trait object 的理由**：

1. **零样板代码**：Python 需要定义新类 + 两个方法签名 + `super().__init__`；Rust 闭包内联定义，一行搞定。
2. **组合优于继承**：闭包可以捕获外部变量（如配置参数），比继承更灵活。
3. **性能**：`Box<dyn Fn>` 是单次堆分配 + 间接调用，与 Python 虚方法开销相当甚至更低。
4. **所有权明确**：Rust 闭包拥有捕获的变量，不存在 Python 的 `self.subcon` 共享引用歧义。
5. **对称性保持**：闭包注入不影响 parse/build 对称性——decode 用于 parse 方向，encode 用于 build 方向，与 Python `_decode`/`_encode` 完全对应。
6. **ExprAdapter/ExprValidator 语义别名**：Phase 5 表达式系统生成的闭包可用 ExprAdapter/ExprValidator 包装，编译期无额外开销，仅作为语义标记。

**风险评估**：无。闭包模式是 Rust 生态中替代策略模式/模板方法模式的标准做法（如 `Iterator::map`、`std::thread::spawn` 均使用闭包）。

### 决策 2：Enum 使用 `IndexMap<String, u64>` 而非 `HashMap`

`IndexMap` 保持插入顺序（与 Python `dict` 行为一致），且 O(1) 查找。`decmap`（反向映射）在构造时自动从 `mapping` 构建。

### 决策 3：Mapping 使用 `Vec<(Value, Value)>` 而非 `HashMap`

`Value` 枚举包含 `f64`，无法安全实现 `Hash + Eq`（`f64::NaN != f64::NaN`）。因此 Mapping 使用线性扫描的 `Vec`。对于典型的枚举映射（几十个条目），线性扫描性能完全够用。

### 决策 4：Switch cases 使用 `Vec<(Value, Box<dyn Construct>)>` 而非 `HashMap`

同上原因——`Value` 无法实现 `Hash`。使用有序 Vec + 线性扫描 + `PartialEq` 匹配。首个匹配的 case 胜出，语义与 Python 的 `dict` 查找等价（但保持插入顺序）。

### 决策 5：Hex/HexDump 为透传适配器

Python 的 `Hex`/`HexDump` 通过返回特殊的包装对象（`HexDisplayedInteger` 等）覆盖 `__str__`/`__repr__`。Rust 无法为 `Value` 实现 `Display` trait（外部类型规则），且不值得引入 newtype 仅为显示目的。因此这两个构造器在 Rust 中为语义标记，parse/build/sizeof 完全透传。若需要十六进制显示，用户可在应用层格式化 `Value`。

### 决策 6：FlagsEnum build 跳过 `_` 前缀键

对齐 Python 的行为——Container 中可能包含内部键（如 `_io`、`_index`、`_flagsenum`），这些不应参与标志位计算。

### 决策 7：Check 接收 `&Context` 而非 `&Value`

Python `Check(checkfunc)` 的 checkfunc 只接收 context 参数（不接收值），用于验证上下文状态（如跨字段一致性检查）。Rust 与此对齐：`CheckFunc = Box<dyn Fn(&Context) -> Result<()>>`。

注意：这与 `Validator` 不同——Validator 的 check 函数接收 `(&Value, &Context)`，验证的是值本身。

### 决策 8：Computed/Rebuild/Default/Index 的 flagbuildnone 均为 true

这四个构造器在 build 时不需要用户提供值：
- Computed：完全从上下文计算，忽略输入
- Rebuild：从上下文计算，忽略输入
- Default：输入为 None 时使用默认值
- Index：从上下文读取 `_index`

因此它们的 `flagbuildnone()` 返回 `true`，使 Struct 在 build 时不会因为缺少对应字段值而报错。
