## 1. 概述

### 1.1 模块位置

| 文件 | 内容 |
|------|------|
| `construct-rs/src/constructs/stream_ops.rs` | 全部流操作与隧道构造器 |

### 1.2 职责

实现流级别的数据变换与隧道（tunneling）构造器：在 parse/build 过程中操作底层字节流的位置、
创建子流、进行字节/位级别转换、压缩/解压、校验和验证等。这些构造器不直接解析具体的字段语义，
而是**改变数据流入/流出子构造器的方式**。

### 1.3 构造器清单

本模块实现了以下 14 个构造器，按功能分组：

| 分组 | 构造器 | 用途 |
|------|--------|------|
| 位级流 | `Bitwise`, `Bytewise` | 字节流 ↔ 位流转换 |
| 流定位 | `Pointer`, `Peek` | 绝对位置读写、不推进解析 |
| 原始拷贝 | `RawCopy` | 同时返回原始字节和解析值 |
| 前缀帧 | `Prefixed` | 长度前缀帧 |
| 字节变换 | `Transformed`, `Restreamed` | 固定/可变大小字节变换 |
| 压缩 | `Compressed`（feature-gated） | zlib/deflate 压缩隧道 |
| 校验和 | `Checksum` | 哈希校验字段 |
| 字节/位序交换 | `ByteSwapped`, `BitsSwapped` | 反转字节序/位序 |
| 递归绑定 | `LazyBound` | 运行时绑定子构造器 |

## 2. 类型定义

### 2.1 Bitwise

```rust
/// 将字节流包装为位级流，子构造器在位流上下文中操作。
///
/// 位流表示：每个 bit 表示为 1 个字节（0x00 或 0x01），
/// 因此 N 字节的输入扩展为 N×8 字节的位流。
///
/// 对应 Python `Bitwise(subcon)`。
pub struct Bitwise {
    pub subcon: Box<dyn Construct>,
}

impl Bitwise {
    pub fn new(subcon: Box<dyn Construct>) -> Self;
}
```

### 2.2 Bytewise

```rust
/// 在位流上下文中恢复字节级访问。
///
/// 读取位流，每 8 个 bit 合并为 1 字节，传给子构造器。
/// 对应 Python `Bytewise(subcon)`。
```

### 2.3 Pointer

```rust
/// 在流的绝对位置读写数据，操作完成后恢复原流位置。
///
/// `offset >= 0`：从流开头计算。
/// `offset < 0`：从流末尾计算。
///
/// 对应 Python `Pointer(offset, subcon)`。
///
/// **已知差异**：Python 支持 `stream`（外部流）和 `relativeOffset` 参数，

pub struct Pointer {
    pub offset: i64,
    pub subcon: Box<dyn Construct>,
}

impl Pointer {
    pub fn new(offset: i64, subcon: Box<dyn Construct>) -> Self;
}
```

### 2.6 Prefixed

```rust

///

```

### 2.7 Transformed

```rust
/// 固定大小字节变换。
///
/// parse：读取 `decode_amount` 字节（或全部剩余）→ decode 变换 → 子流解析。
/// build：构建子构造器 → encode 变换 → 验证 `encode_amount`（若指定）→ 写入。
/// sizeof：当 `decode_amount == encode_amount` 时返回该值，否则 `Sizeof` 错误。
///
/// 对应 Python `Transformed(subcon, decodefunc, decodeamount, encodefunc, encodeamount)`。
pub type TransformFunc = Box<dyn Fn(&[u8]) -> Result<Vec<u8>>>;

pub struct Transformed {
    pub subcon: Box<dyn Construct>,
    pub decode: TransformFunc,
    pub decode_amount: Option<usize>,
    pub encode: TransformFunc,
    pub encode_amount: Option<usize>,
}

impl Transformed {
    pub fn new(
        subcon: Box<dyn Construct>,
        decode: TransformFunc,
        decode_amount: Option<usize>,
        encode: TransformFunc,
        encode_amount: Option<usize>,
    ) -> Self;
}
```

## 4. 行为规格

### 4.1 比特流转换（Bitwise / Bytewise）

**位流表示方式**：每个 bit 表示为 1 字节（`0x00` = 0，`0x01` = 1），大端位序（MSB→LSB）。
1 字节 `0xFF` 扩展为 `[1,1,1,1,1,1,1,1]`（8 字节）。

| 操作 | Bitwise | Bytewise |
|------|---------|---------|
| **parse** | `read_remaining()` → `bytes2bits()` → 子流 parse | `read_remaining()` → `bits2bytes()` → 子流 parse |
| **build** | 子流 build → `bits2bytes()` → 写主流 | 子流 build → `bytes2bits()` → 写主流 |
| **sizeof** | `(subcon_sizeof + 7) / 8`（向上取整） | `subcon_sizeof * 8` |

**已知简化**：`Bitwise` 和 `Bytewise` 的 parse 使用 `read_remaining()` 消费外层流的全部剩余字节，
而非 Python `RestreamedBytesIO` 的按需读取。这意味着 Bitwise/Bytewise 之后不能跟随其他顺序构造器。
对大多数使用场景（Bitwise 包装整个结构体）无影响。

> **sizeof 差异**：Python Bitwise 返回 `size // 8`（整除），Rust 返回 `(size + 7) / 8`（向上取整）。
> 对于 8 的倍数结果相同；对于非 8 的倍数，Rust 更合理（Python 此场景本身也无法正常工作）。

### 4.2 指针跳转（Pointer）

**流位置保存/恢复机制**：

```
parse:
  1. fallback = stream.tell()         // 保存当前位置
  2. offset >= 0 → stream.seek(offset as u64)   // 从开头
     offset <  0 → stream.seek_from(End(offset)) // 从末尾
  3. result = subcon.parse(stream, ctx)          // 在目标位置解析
  4. stream.seek(fallback)                       // 恢复原位置
  5. return result

build: 同理，subcon.build 后恢复
sizeof: 始终返回 0（Pointer 本身不消费顺序字节）
```

**错误处理**：即使 subcon 的 parse/build 失败，seek 恢复仍会执行（通过 `and_then` / `and` 组合）。

**负偏移语义**：`Pointer(-2, Bytes(1))` 解析长度为 12 的数据时，从末尾倒数 2 字节（位置 10）读取。

### 4.3 偷看（Peek）

```
parse:
  1. fallback = stream.tell()
  2. result = subcon.parse(stream, ctx)   // 尝试解析（可能失败）
  3. stream.seek(fallback)                // 无论成败都恢复
  4. match result:
       Ok(v) → Ok(v)
       Err(Check | StopField) → Err(e)    // 致命错误：重新抛出
       Err(_) → Ok(Value::None)           // 非致命错误：返回 None

build: 无操作（Ok(())）
sizeof: 始终返回 0
flagbuildnone: true（允许 None 值构建）
```

> **与 Python 的微小差异**：Python Peek 捕获 `ExplicitError` 重新抛出、捕获 `ConstructError`（含 StopField）
> 返回 None。Rust 重新抛出 `Check` 和 `StopField`，吞噬其他错误。实际使用中 Peek 主要用于 Union 内部，
> 此差异几乎不影响。

### 4.4 原始拷贝（RawCopy）

```
parse:
  1. offset1 = stream.tell()
  2. obj = subcon.parse(stream, ctx)
  3. offset2 = stream.tell()
  4. length = offset2 - offset1
  5. stream.seek(offset1); data = stream.read_bytes(length)   // 回读原始字节
  6. return Container{ data, value: obj, offset1, offset2, length }

build:
  1. if container["data"] exists → 直接写入原始字节
  2. else if container["value"] exists → subcon.build(value)
  3. else → ConstructError::Generic

sizeof: subcon.sizeof()
```

**Container 键名**：`data`、`value`、`offset1`、`offset2`、`length` — 与 Python 完全一致。

### 4.5 前缀长度（Prefixed）

```
parse:
  1. length = length_field.parse(stream, ctx) as usize
  2. if include_length: length -= length_field.sizeof(ctx)
  3. data = stream.read_bytes(length)
  4. sub_stream = ByteStream::new_read(&data)
  5. return subcon.parse(sub_stream, ctx)

build:
  1. sub_stream = ByteStream::new_write()
  2. subcon.build(data, sub_stream, ctx)
  3. built_data = sub_stream.into_bytes()
  4. length = built_data.len()
  5. if include_length: length += length_field.sizeof(ctx)
  6. length_field.build(UInt(length), stream, ctx)
  7. stream.write_bytes(&built_data)

sizeof: length_field.sizeof(ctx) + subcon.sizeof(ctx)
```

### 4.6 固定大小字节变换（Transformed）

```
parse:
  1. data = match decode_amount {
       Some(n) => stream.read_bytes(n),
       None    => stream.read_remaining(),
     }
  2. decoded = decode(data)?
  3. sub_stream = ByteStream::new_read(&decoded)
  4. return subcon.parse(sub_stream, ctx)

build:
  1. subcon.build(data, sub_stream, ctx) → built
  2. encoded = encode(built)?
  3. if let Some(expected) = encode_amount:
       if encoded.len() != expected → ConstructError::Generic
  4. stream.write_bytes(&encoded)

sizeof:
  match (decode_amount, encode_amount):
    (Some(da), Some(ea)) if da == ea → Ok(ea)
    _ → Err(Sizeof)
```

### 4.7 分块流式变换（Restreamed）

```
parse:
  1. raw = stream.read_remaining()
  2. if decoder_unit == 0 → Err(Generic)
  3. decoded = raw.chunks(decoder_unit).flat_map(decoder).collect()
  4. sub_stream = ByteStream::new_read(&decoded)
  5. return subcon.parse(sub_stream, ctx)

build:
  1. subcon.build(data, sub_stream, ctx) → built
  2. if encoder_unit == 0 → Err(Generic)
  3. for chunk in built.chunks(encoder_unit):
       stream.write_bytes(&encoder(chunk)?)

sizeof:
  if let Some(computer) = size_computer:
    Ok(computer(subcon.sizeof(ctx)?))
  else → Err(Sizeof)
```

> **已知简化**：Rust 实现先读取全部数据再分块处理，而非 Python `RestreamedBytesIO` 的逐块按需流式读取。
> 功能等价，但不适用于流式处理的极端场景。

### 4.8 压缩/解压（Compressed）

```
parse:
  1. data = stream.read_remaining()
  2. decoded = match algorithm {
       Zlib   => ZlibDecoder::new(data).read_to_end(),
       Deflate => DeflateDecoder::new(data).read_to_end(),
     }
  3. sub_stream = ByteStream::new_read(&decoded)
  4. return subcon.parse(sub_stream, ctx)

build:
  1. subcon.build(data, sub_stream, ctx) → built
  2. encoded = match algorithm {
       Zlib   => ZlibEncoder::new(built, default).read_to_end(),
       Deflate => DeflateEncoder::new(built, default).read_to_end(),
     }
  3. stream.write_bytes(&encoded)

sizeof: 始终 Err(Sizeof) — "Compressed has undefined size"
```

**支持的算法**：`Zlib`（header + deflate + checksum）、`Deflate`（raw deflate，无 header/checksum）。
均使用 `flate2` crate 的 `read` 模块。

### 4.9 校验和（Checksum）

```
parse:
  1. parsed = checksum_field.parse(stream, ctx)
  2. raw = bytes_func(ctx)?
  3. expected = hash_func(raw)
  4. parsed_bytes = parsed.as_bytes().unwrap_or(&[])
  5. if parsed_bytes != expected → Err(Check)
  6. return parsed

build:
  1. raw = bytes_func(ctx)?
  2. checksum = hash_func(raw)
  3. checksum_field.build(Bytes(checksum), stream, ctx)

sizeof: checksum_field.sizeof(ctx)
flagbuildnone: true
```

**哈希算法选择**：Checksum 本身不绑定任何具体哈希算法。`hash_func` 是一个 `Fn(&[u8]) -> Vec<u8>` 闭包，
由调用方提供具体实现（如 CRC32、SHA256、简单求和等）。这与 Python 的设计一致——Python 的 `hashfunc`
也是用户提供的函数（通常使用 `hashlib`）。

### 4.10 字节序交换（ByteSwapped）

```
parse:
  1. size = subcon.sizeof(ctx)?       // 必须有固定大小
  2. data = stream.read_bytes(size)
  3. swapped = binary::swapbytes(data) // 反转字节顺序
  4. sub_stream parse

build: subcon.build → swapbytes → write
sizeof: subcon.sizeof(ctx)
```

### 4.11 位序交换（BitsSwapped）

```
parse (fixed):
  1. size = subcon.sizeof(ctx)?
  2. data = stream.read_bytes(size)
  3. swapped = swapbitsinbytes(data)
  4. sub_stream parse

parse (variable):
  1. data = stream.read_remaining()
  2. swapped = swapbitsinbytes(data)
  3. sub_stream parse

build: subcon.build → swapbitsinbytes → write
sizeof: subcon.sizeof(ctx)
```

`swapbitsinbytes` 反转每个字节内的 8 个 bit：bit0↔bit7, bit1↔bit6, ...
- `0xAA` (10101010) → `0x55` (01010101)
- `0x00` / `0xFF` 不变（对称）

### 4.12 递归绑定（LazyBound）

```
parse:   subcon = subcon_func(); subcon.parse(stream, ctx)
build:   subcon = subcon_func(); subcon.build(data, stream, ctx)
sizeof:  subcon = subcon_func(); subcon.sizeof(ctx)
```

无自身状态，纯委托。每次操作都重新调用工厂函数获取子构造器实例。

## 5. 与 Python 原版对照

### 5.1 完整 API 映射表

| Python 类/函数 | Rust 类型/方法 | 行为一致性 |
|---------------|---------------|-----------|
| `Bitwise(subcon)` | `Bitwise::new(subcon)` | ✅ 一致（sizeof 向上取整差异见 §4.1） |
| `Bytewise(subcon)` | `Bytewise::new(subcon)` | ✅ 一致 |
| `Pointer(offset, subcon)` | `Pointer::new(offset, subcon)` | ⚠️ 部分（缺 stream/relativeOffset/表达式 offset） |

| `Prefixed(lengthfield, subcon, includelength)` | `Prefixed::new(...).with_include_length(...)` | ✅ 一致 |
| `Transformed(subcon, dec, decamt, enc, encamt)` | `Transformed::new(subcon, dec, decamt, enc, encamt)` | ✅ 一致 |
| `Restreamed(subcon, dec, decunit, enc, encunit, sizecomp)` | `Restreamed::new(...)` | ✅ 功能一致（简化为非流式） |
| `Compressed(subcon, encoding)` | `Compressed::new(subcon, algorithm)` | ⚠️ 部分（仅 zlib/deflate，无 gzip/bzip2/lzma） |
| `Checksum(field, hashfunc, bytesfunc)` | `Checksum::new(field, hash_func, bytes_func)` | ✅ 一致 |
| `ByteSwapped(subcon)` | `ByteSwapped::new(subcon)` | ✅ 一致 |
| `BitsSwapped(subcon)` | `BitsSwapped::new_fixed/new_variable(subcon)` | ✅ 一致 |
| `LazyBound(subconfunc)` | `LazyBound::new(subcon_func)` | ✅ 一致 |

### 5.2 Python 宏实现 vs Rust 独立结构

Python 中 `Bitwise`、`Bytewise`、`ByteSwapped`、`BitsSwapped` 都是**函数/宏**，
内部返回 `Transformed` 或 `Restreamed` 实例：

| Python 宏 | Python 内部实现 | Rust 实现 |
|-----------|----------------|-----------|
| `Bitwise(subcon)` | 固定大小 → `Transformed(subcon, bytes2bits, n//8, bits2bytes, n//8)`<br>可变大小 → `Restreamed(subcon, bytes2bits, 1, bits2bytes, 8, n//8)` | 独立 `Bitwise` 结构体，直接调用 `binary::bytes2bits/bits2bytes` |
| `Bytewise(subcon)` | 固定 → `Transformed(subcon, bits2bytes, n*8, bytes2bits, n*8)`<br>可变 → `Restreamed(subcon, bits2bytes, 8, bytes2bits, 1, n*8)` | 独立 `Bytewise` 结构体 |
| `ByteSwapped(subcon)` | `Transformed(subcon, swapbytes, n, swapbytes, n)` | 独立 `ByteSwapped` 结构体，直接调用 `binary::swapbytes` |
| `BitsSwapped(subcon)` | 固定 → `Transformed(subcon, swapbitsinbytes, n, ...)`<br>可变 → `Restreamed(subcon, swapbitsinbytes, 1, ...)` | 独立 `BitsSwapped` 结构体，内部 `swapbitsinbytes` 函数 |

**设计理由**：Rust 选择独立结构体而非委托给 `Transformed`/`Restreamed`，因为：
1. Rust 中无法像 Python 那样在构造函数中 try/catch `sizeof` 来自动选择 Transformed/Restreamed
2. 独立结构体行为更清晰，文档注释更直接
3. 性能更好（减少一层间接调用）
4. `BitsSwapped` 通过 `new_fixed`/`new_variable` 显式区分两种模式，避免运行时判断

### 5.3 Compressed 与 Tunnel 基类

Python `Compressed` 继承自 `Tunnel` 基类：

```python
class Tunnel(Subconstruct):
    def _parse(self, stream, context, path):
        data = stream_read_entire(stream)
        data = self._decode(data, context, path)
        return self.subcon.parse(data)

class Compressed(Tunnel):
    def _decode(self, data, context, path):
        return self.lib.decompress(data)
```

Rust 中没有 `Tunnel` trait/结构体，`Compressed` 直接实现 `Construct` trait，内部完成 decode/encode 逻辑。
功能等价，但减少了抽象层。

### 5.4 错误类型映射

| 场景 | Python 异常 | Rust 错误 | 状态 |
|------|------------|----------|------|
| RawCopy build 缺少 data/value 键 | `RawCopyError` | `ConstructError::Generic` | ⚠️ 类型不精确 |
| Checksum 校验失败 | `ChecksumError` | `ConstructError::Check` | ✅ 功能一致 |
| Pointer 流不可寻址 | `StreamError` | `ConstructError::Stream` | ✅ 一致 |
| Peek 解析失败 | 返回 None | `Value::None` | ✅ 一致 |
| Transformed encode 长度不匹配 | `StreamError` | `ConstructError::Generic` | ⚠️ 类型不精确 |
| Compressed sizeof | `SizeofError` | `ConstructError::Sizeof` | ✅ 一致 |
| Restreamed sizeof 无 computer | `SizeofError` | `ConstructError::Sizeof` | ✅ 一致 |
| Restreamed unit=0 | 无显式检查 | `ConstructError::Generic` | ✅ Rust 更严格 |

> **说明**：个别错误类型不够精确（RawCopy/Transformed 使用 Generic 而非专用类型），
> 不影响功能正确性。如后续需要更精细的错误匹配，可新增 `ConstructError` 变体。

## 6. 设计决策记录

### 决策 1：Compressed 使用 flate2 feature gate

**决策**：`Compressed` 构造器通过 `#[cfg(feature = "compression")]` 条件编译，
`flate2` 作为 optional dependency，由 `compression` feature 控制。

**Cargo.toml 配置**：
```toml
[features]
compression = ["dep:flate2"]

[dependencies.flate2]
version = "1"
optional = true
```

**理由**：
1. **与 Python 零依赖理念对齐**：Python construct 的 Compressed 仅在使用时才 `import zlib/gzip`，
   核心库无强制压缩依赖。Rust 通过 feature gate 实现相同效果——不启用 compression 时，
   `Compressed`/`CompressionAlgorithm` 类型完全不存在，无编译开销。
2. **flate2 是 Rust 生态中最成熟的 zlib 绑定**，基于系统 zlib 或 miniz_oxide 纯 Rust 实现。
3. **测试要求**：`cargo test --features compression` 运行压缩相关 4 个测试；
   默认 `cargo test` 不包含。
4. **后续扩展**：gzip/bzip2/lzma 可通过新增 feature gate + 对应 crate 扩展，
   不影响现有 API（仅需给 `CompressionAlgorithm` 增加变体）。

**当前支持的算法**：
- `CompressionAlgorithm::Zlib`：zlib 格式（2 字节 header + deflate + 4 字节 Adler-32 checksum）
- `CompressionAlgorithm::Deflate`：raw deflate（无 header/checksum）

**未支持（可后续扩展）**：
- gzip（flate2 的 `GzipEncoder`/`GzipDecoder` 已可用，仅需增加变体）
- bzip2（需 `bzip2` crate）
- lzma（需 `xz2` 或 `lzma-rs` crate）

### 决策 2：Bitwise 的比特流表示方式

**决策**：位流中每个 bit 表示为 1 个字节（`0x00` 或 `0x01`），大端位序（MSB→LSB）。
即 `0xFF` → `[0x01, 0x01, 0x01, 0x01, 0x01, 0x01, 0x01, 0x01]`（8 字节）。

**理由**：
1. **与 Python 完全一致**：Python 的位流文档明确说明"8 times as many bytes, each byte is
   \\x00 or \\x01"。这是 construct 库的核心设计决策，Rust 必须保持一致以保证行为等价。
2. **实现简洁**：`binary::bytes2bits()` 和 `binary::bits2bytes()` 函数处理转换，
   Bitwise/Bytewise 无需理解 bit 打包细节。
3. **与 BitsInteger/Bits 等位级构造器兼容**：这些构造器已经在位流上下文中设计为读写 0x00/0x01 字节。

**位序说明**：
- 默认 MSB→LSB（bit-level big-endian）：字节 `0b10000000` 的最高位先处理。
- 如需反转位序（LSB→MSB），使用 `BitsSwapped(Bitwise(...))` 包装。

**示例**：
```
Bitwise(Bytes(8)).parse(b"\xff")
→ bytes2bits([0xff]) = [1,1,1,1,1,1,1,1]
→ Bytes(8) 读取 8 个 "bit-as-byte"
→ Value::Bytes([1,1,1,1,1,1,1,1])
```

### 决策 3：Pointer 的流位置保存/恢复机制

**决策**：使用 `stream.tell()` 保存位置 → seek 到目标 → 操作 → `stream.seek(fallback)` 恢复。
即使子构造器操作失败，恢复操作仍会执行。

**实现**：
```rust
fn parse(&self, stream, ctx) -> Result<Value> {
    let fallback = stream.tell()?;
    if self.offset >= 0 {
        stream.seek(self.offset as u64)?;
    } else {
        stream.seek_from(SeekFrom::End(self.offset))?;
    }
    let parse_result = self.subcon.parse(stream, ctx);
    let seek_result = stream.seek(fallback);   // 始终执行
    parse_result.and_then(|v| seek_result.map(|_| v))
}
```

**关键设计点**：

1. **正/负偏移区分**：
   - `offset >= 0`：使用 `stream.seek(offset as u64)`，从流开头（SEEK_SET）
   - `offset < 0`：使用 `stream.seek_from(SeekFrom::End(offset))`，从流末尾（SEEK_END）
   - 与 Python `stream_seek(stream, offset, 2 if offset < 0 else 0)` 语义一致

2. **失败安全**：
   - parse 用 `and_then`：子构造器 parse 成功后才执行 seek 恢复，但 seek 结果不影响返回值
   - build 用 `and`：子构造器 build 和 seek 恢复都需成功
   - 两种方式都保证 seek 恢复一定会被执行

3. **未实现的 Python 功能**：
   - `stream` 参数（使用外部流而非原始流）— 需表达式系统支持
   - `relativeOffset`（相对当前位置偏移）— 需增加字段，可在后续补充
   - 表达式 offset（context lambda）— 等 Phase 5 表达式系统集成后扩展

4. **sizeof 始终返回 0**：Pointer 在顺序流中不消费任何字节（它跳到其他位置操作）。
   这与 Python 完全一致。

---

### 决策 4：Checksum 的哈希算法选择

**决策**：Checksum 不绑定任何具体哈希算法。哈希函数通过 `hash_func: Box<dyn Fn(&[u8]) -> Vec<u8>>`
闭包由调用方注入。

**设计模式**：依赖注入（Dependency Injection）。

**理由**：
1. **与 Python 设计一致**：Python `Checksum(checksumfield, hashfunc, bytesfunc)` 中 `hashfunc` 也是
   用户提供的函数（通常 `lambda data: hashlib.sha256(data).digest()`）。Checksum 本身是算法无关的。
2. **避免引入哈希库依赖**：如果硬编码特定算法（如 SHA-256），需要引入 `sha2` crate 作为核心依赖，
   违背零依赖理念。闭包方案让用户自行选择是否引入哈希库。
3. **灵活性**：支持任意 `&[u8] → Vec<u8>` 变换——CRC32、MD5、SHA 系列、简单求和、自定义算法均可。
4. **与 RawCopy 配合**：典型用法是 `RawCopy` 提供原始字节，`Checksum` 计算哈希：

```rust
// 示例：SHA-256 校验和
d = Struct(
    "body" / RawCopy(...),
    "hash" / Checksum(
        Bytes(32),
        Box::new(|data| sha2::Sha256::digest(data).to_vec()),
        Box::new(|ctx| Ok(ctx.get("body").and_then(|c| c.as_container())
            .and_then(|c| c.get("data")).and_then(|v| v.as_bytes().map(|s| s.to_vec()))
            .unwrap_or_default())),
    ),
)
```

**函数类型设计**：
- `ChecksumFunc = Box<dyn Fn(&[u8]) -> Vec<u8>>`：纯函数，输入字节 → 输出哈希字节。不可失败。
- `ChecksumBytesFunc = Box<dyn Fn(&Context) -> Result<Vec<u8>>>`：从上下文提取待校验字节，可失败
  （如上下文中缺少必要字段）。

---

### 决策 5：Bitwise/Bytewise 使用 read_remaining 简化

**决策**：`Bitwise` 和 `Bytewise` 的 parse 使用 `stream.read_remaining()` 消费外层流的全部剩余字节，
而非 Python 的 `RestreamedBytesIO` 按需读取机制。

**影响**：
- Bitwise/Bytewise 必须是流中的**最后一个**字段（或包裹整个结构体）
- 不能在 `Bitwise(...) + Bytes(2)` 这样的序列中使用

**理由**：
1. Python `RestreamedBytesIO` 的按需读取在 Rust 中实现复杂，需自定义 `Stream` trait 实现
2. 实际使用中 Bitwise 几乎总是包裹整个结构体（如 `Bitwise(Struct(...))`），简化方案覆盖主流场景
3. 如需精确控制，用户可先用 `Prefixed` 或 `Bytes(n)` 限定范围，再传入 Bitwise

**文档已明确标注**：代码注释和设计文档中均说明此限制。

---

### 决策 6：BitsSwapped 双模式构造器

**决策**：`BitsSwapped` 提供 `new_fixed()` 和 `new_variable()` 两个构造函数，而非像 Python 那样
在构造时 try/catch `sizeof` 自动选择。

**理由**：
1. Rust 中无法在构造函数中对 `Box<dyn Construct>` 调用 `sizeof` 并 try/catch——
   因为 `sizeof` 接受 `&Context`，而构造时尚无 Context。
2. 显式比隐式更好：`new_fixed` / `new_variable` 明确表达了使用意图，避免运行时意外行为。
3. 两种模式的 parse/build 实现几乎相同（仅读取数据量的方式不同），维护成本低。

---

### 决策 7：Transformed/Restreamed 作为公开 API（而非仅内部辅助）

**决策**：`Transformed` 和 `Restreamed` 作为公开结构体导出，用户可直接使用。

**理由**：
1. Python 中它们也是公开类，用户可自定义字节变换（加密、混淆、编码转换等）
2. `ByteSwapped`、`BitsSwapped` 等构造器在 Rust 中是独立结构体（不委托 Transformed），
   但 Transformed 仍有独立的用户价值
3. `TransformFunc = Box<dyn Fn(&[u8]) -> Result<Vec<u8>>>` 类型别名公开导出，方便用户构造闭包

## 边界条件清单

### Bitwise / Bytewise
1. **空输入**：`Bitwise` parse 空流 → `bytes2bits([])` = `[]` → 子构造器在空位流中 parse
2. **非 8 倍数位**：`Bitwise(Bytes(12))` → sizeof 返回 2（向上取整），Python 返回 1（但此场景 Python 也无法正常工作）
3. **build 后位流非 8 倍数**：`bits2bytes()` 返回 `Generic` 错误

### Pointer
4. **offset = 0**：从流开头解析
5. **负偏移**：从末尾倒数，如 `Pointer(-2, ...)` 在 12 字节流中读位置 10
6. **子构造器失败**：seek 恢复仍执行，返回子构造器的错误
7. **offset 超出流范围**：seek 可能成功（Cursor 允许 seek 超出末尾），后续 read 失败

### Peek
8. **解析成功**：返回值，但流不推进
9. **解析失败（非致命）**：返回 `Value::None`，流不推进
10. **解析失败（Check/StopField）**：重新抛出错误，流不推进
11. **build**：始终 no-op

### RawCopy
12. **build 缺少 data 和 value**：`ConstructError::Generic`
13. **build 有 data 键**：直接写入，忽略 value
14. **build 有 value 键**：委托 subcon.build
15. **subcon parse 消费 0 字节**：data = `vec![]`, length = 0

### Prefixed
16. **length = 0**：空子流，subcon 在空流中 parse
17. **include_length = true**：读取的 length 减去 length_field 自身大小
18. **build 时 include_length**：写入的 length 加上 length_field 自身大小

### Transformed
19. **decode_amount = None**：读取全部剩余字节
20. **encode_amount 不匹配**：`ConstructError::Generic`
21. **sizeof：decode_amount ≠ encode_amount**：`ConstructError::Sizeof`

### Restreamed
22. **decoder_unit = 0**：`ConstructError::Generic`（防御性检查）
23. **encoder_unit = 0**：`ConstructError::Generic`
24. **数据长度非 unit 倍数**：最后一块可能不足 unit，decoder/encoder 闭包需自行处理
25. **sizeof 无 size_computer**：`ConstructError::Sizeof`

### Compressed
26. **空数据**：压缩/解压空字节序列（zlib/deflate 支持空数据）
27. **解压失败（数据损坏）**：`ConstructError::Generic`（flate2 错误包装）
28. **sizeof**：始终 `ConstructError::Sizeof`

### Checksum
29. **checksum_field 返回非 Bytes 类型**：`as_bytes().unwrap_or(&[])` → 空切片，与哈希比较必定失败
30. **校验通过**：返回解析的校验值
31. **校验失败**：`ConstructError::Check`，消息包含 read/computed 的 hex 表示
32. **bytes_func 失败**：错误传播

### ByteSwapped
33. **单字节**：swapbytes 不变
34. **subcon 无固定大小**：`sizeof` 失败 → parse 失败

### BitsSwapped
35. **0x00 / 0xFF**：swapbitsinbytes 不变
36. **variable 模式空流**：返回空

### LazyBound
37. **无边界条件**：纯委托，子构造器的边界条件由其自身决定
