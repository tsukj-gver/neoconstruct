**⚠️ 发现差异：linenumbers 子 Struct 字段不完整**

Python `pe32coff.py` line 227-235 的 linenumbers 内部 Struct 有 **7 个字段**：
```python
"_type" / Int32ul,
"_linenumber" / Int16ul,
"is_symboltableindex" / Computed(this._linenumber == 0),     # ← 缺失
"is_linenumber" / Computed(this._linenumber > 0),             # ← 缺失
"symboltableindex" / If(this.is_symboltableindex, Computed(this._type)),  # ← 缺失
"linenumber" / If(this.is_linenumber, Computed(this._linenumber)),        # ← 缺失
"virtualaddress" / If(this.is_linenumber, Computed(this._type)),          # ← 缺失
```

Rust `pe32coff.rs` line 444-448 的 linenumbers 内部 Struct 仅有 **2 个字段**：
```rust
.field("_type", Box::new(INT32UL))
.field("_linenumber", Box::new(INT16UL)),
```

**影响分析**：
- 二进制 I/O 行为：✅ 无影响（缺失的 5 个字段均为 Computed/If+Computed，不消耗流字节）
- 解析输出丰富度：❌ Rust 输出的 linenumbers Container 缺少 5 个派生字段
- 判定：**功能覆盖部分缺失**（非行为不一致），不影响二进制解析正确性

**已知差异（设计决策）**：
- PE plusfield 通过 IfThenElse 运行时选择 32/64 位（非编译期参数），与 Python 的 `this.signature == "PE32plus"` 逻辑一致。✅
- `Renamed`（`* "docstring"`）和 `docs * Struct(...)` 文档前缀被跳过（仅元数据，不影响 I/O）。✅

### 问题清单（按严重性排序）

#### 问题 #1 [Medium] — UTIndex build 对 i64::MIN 溢出

- **文件**：`construct-rs/src/gallery/ut_index.rs` line 146-148
- **现象**：`to_write = -to_write` 当 `obj == i64::MIN`（-9223372036854775808）时，`-i64::MIN` 超出 i64 范围（2^63 不可表示）
- **debug 模式**：arithmetic overflow → **panic**（违反红线"禁止 panic"）
- **release 模式**：wrap 回 i64::MIN（仍为负），后续算法产生**静默错误输出**
- **影响范围**：仅当传入 `Value::Int(i64::MIN)` 时触发。UTIndex 最大可表示值为 2^35-1 ≈ 34 亿，i64::MIN 远超此范围，实际数据中不可能出现。
- **建议修复**：
  ```rust
  // 方案 A：checked_neg
  to_write = to_write.checked_neg().ok_or_else(|| ConstructError::Generic {
      path: String::new(),
      message: format!("UTIndex: value {} exceeds representable range", obj),
  })?;
  // 方案 B：unsigned_abs（推荐，简洁）
  let magnitude = obj.unsigned_abs();
  ```
- **严重性评估**：Medium — 理论上的红线违反，但触发条件极端不可达（值需为 i64::MIN，而 UTIndex 最大支持 2^35-1）。fix 是一行改动。**建议修复但不阻断验收**。

#### 问题 #2 [Minor] — PE linenumbers 缺少 5 个 Computed/If 派生字段

- **文件**：`construct-rs/src/gallery/pe32coff.rs` line 444-448
- **现象**：Python `pe32coff.py` line 227-235 的 linenumbers 内部 Struct 有 7 个字段，Rust 仅实现 2 个
- **缺失字段**：`is_symboltableindex`、`is_linenumber`、`symboltableindex`、`linenumber`、`virtualaddress`
- **影响**：不影响二进制 I/O（缺失字段全是 Computed/If+Computed，不消耗流字节），但解析输出比 Python 少 5 个派生字段
- **严重性评估**：Minor — 输出丰富度缺口，非行为不一致。REF 已标记为"建议补全（非驳回项）"。REV 同意此评估。

#### 问题 #3 [Minor] — check_enum_field 每次调用分配 Vec\<String\>

- **文件**：`construct-rs/src/gallery/elf.rs` line 571-578，`pe32coff.rs` line 459-464
- **现象**：`check_enum_field`/`compute_sections_count` 内部 `path.iter().map(|s| s.to_string()).collect::<Vec<String>>()` 每次调用堆分配
- **影响**：ELF 解析时每个 IfThenElse 条件检查都触发分配。性能不佳但不影响正确性。
- **根因**：`Context::get_path` 签名要求 `&[String]`，DEV 被迫转换
- **严重性评估**：Minor — 性能问题，不影响正确性。可在后续 Phase 9 性能优化中解决（改进 get_path API 接受 `&[&str]`）。
