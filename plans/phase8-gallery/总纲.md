# Phase 8: Gallery 格式解析器

## 阶段目标

使用已实现的所有构造器，编写真实二进制格式的解析器，验证库的实用性和正确性。移植 Python 版本 gallery 中的格式定义。

## 前置依赖

- Phase 1-7 完成（所有构造器可用）

## 子任务清单

### 8.1 ELF 格式解析器

- [ ] 移植 `gallery/elf.py` 为 Rust 版本
- [ ] 定义 ELF header、section header、program header 等 Struct
- [ ] 使用真实 ELF 文件测试解析
- [ ] 验证：解析结果与 Python 版本一致

**参考源码**：`construct/gallery/elf.py`

### 8.2 PE/COFF 格式解析器

- [ ] 移植 `gallery/pe32coff.py` 为 Rust 版本
- [ ] 定义 PE header、section table、optional header 等
- [ ] 使用真实 PE 文件测试解析
- [ ] 验证：解析结果与 Python 版本一致

**参考源码**：`construct/gallery/pe32coff.py`

### 8.3 ut_index 格式解析器

- [ ] 移植 `gallery/ut_index.py`
- [ ] 验证解析正确性

**参考源码**：`construct/gallery/ut_index.py`

### 8.4 额外格式（可选）

根据时间和需求，可选择性移植 deprecated_gallery 中的格式：
- [ ] BMP 图片格式
- [ ] PNG 图片格式
- [ ] GIF 图片格式
- [ ] ext2 文件系统
- [ ] FAT16 文件系统
- [ ] MBR 分区表
- [ ] IP 网络协议栈

**参考源码**：`construct/deprecated_gallery/`

### 8.5 跨语言对比测试

- [ ] 建立测试数据集（真实文件的二进制数据）
- [ ] 对每个格式，运行 Python 版本和 Rust 版本解析同一数据
- [ ] 对比解析结果，确认一致
- [ ] 验证：所有格式解析结果与 Python 版本完全一致

## 阶段出口标准 (Exit Criteria)

1. **至少 2 个格式**：ELF 和 PE/COFF 完整移植
2. **解析正确**：与 Python 版本对比结果一致
3. **构建正确**：解析后再构建，生成与原始数据相同的二进制
4. **代码质量**：gallery 代码清晰，有注释说明格式定义
5. **测试覆盖**：有对应的集成测试

## 预估工期

~1 周

## 风险与注意事项

- 某些格式可能使用了尚未实现的构造器，需要补充
- 真实文件的边界情况可能暴露构造器的 bug
- gallery 中的格式定义可能依赖 Python 特有的行为
