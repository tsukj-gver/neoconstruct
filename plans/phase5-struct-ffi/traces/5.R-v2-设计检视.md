## 二、P0-2 修正检视：候选 C profiling（L-02 教训）✅ 解决

### 2.1 profiling 数据是否基于实测

`phase5_candidate_c_profiling.py` + `_result.md` 实测数据（Python 3.14.2，NUMBER=200000 × REPEAT=7 × WARMUP=50000，min(repeat)）：

| 字段数 | rs_ns (ns/op) | Δ vs 0 字段 | per-field 边际 |
|-------:|--------------:|-----------:|--------------:|
| 0 | 189.43 | — | — |
| 1 | 219.92 | +30.49 | 30.49 |
| 2 | 246.57 | +57.14 | 28.57 |

| 4 | 293.16 | +103.73 | 25.93 |
| 5 | 318.26 | +128.84 | 25.77 |

**实测性判定**：per-field 边际成本（28.64ns/field，1-3 字段平均）是**直接测量值**，非理论推算。这满足 L-02 教训"瓶颈识别有量化数据支撑"。注：未使用 cargo asm（汇编级 profiling），但 micro-benchmark 端到端测量足以反推 per-field 边际成本，方法学合理。

### 2.2 收益修正（6-15ns → 0-15ns）合理性

profiling 反推方法（差分法）：

```
per-field 边际（实测）= 28.64 ns/field
已知固定项（不可优化）= Int8ub parse ~10-15ns + PyDict_SetItem 13.5ns = 23.5-28.5 ns/field
循环结构开销（可优化）= 28.64 - 28.5 ~ 28.64 - 23.5 = 0.14 ~ 5.14 ns/field
3 字段总可优化空间 = 0.43 ~ 15.43 ns（中位 7.93ns）
```

修正后：设计 §7.1 候选 C 收益从 6-15ns 下调为 **0-15ns**（下界从 6ns 下调至 0ns）。

**合理性判定**：
- 下界下调（6→0ns）**保守且诚实**——profiling 显示 LTO=fat 下编译器已大幅优化循环，循环开销可能仅 0.14ns/field
- 上界维持（15ns）保留了固定项取下界时的极端情况
- **关键**：设计 §12.2 item 4 明确"不再将候选 C 视为达标关键——候选 A 是绝对主力"，正确反映了 profiling 结论

**差分法的固有局限**：固定项（Int8ub parse / PyDict_SetItem）本身是 phase3 分析的估算值（非本次实测），循环开销估算继承了固定项的不确定性（区间宽度 5ns = 固定项区间宽度 5ns）。但这是无侵入式测量的最佳方法，且设计要求 5.6 Controlled A/B Test 直接测量候选 C 实际收益（§10.3 item 7），将消除此不确定性。**满足 L-02**。

### 2.3 候选 C 价值降低对 B1 达标概率的影响

§7.2 中位估算修正：

| 估算项 | v1（原） | v2（修正） | 变化原因 |
|--------|---------|-----------|---------|
| 候选 A 收益 | 30-50ns（估算） | **~60ns**（Controlled A/B 实测） | 实测超预期 |
| 候选 C 收益 | 6-15ns（理论） | **0-15ns**（profiling 反推） | 下界下调 |
| B1 rs_ns 中位 | 386 - 45 = ~341ns → 9.16x | 386 - 60 - 20 = ~306ns → **~10.2x** | 候选 A 实测主导 |
| 候选 C 角色 | 达标关键之一 | **可选叠加**（§12.2 item 4） | 不再关键 |

**影响判定**：候选 C 价值降低已被候选 A 实测超预期（~60ns vs 估算 30-50ns）**完全补偿**。B1 中位估算从 9.88x 上调至 ~10.2x。即使候选 C 收益为 0ns，A + B-conservative 仍达 ~9.7x（接近 10x）。候选 C 价值降低**不影响 B1 达标概率评估的合理性**。

**P0-2 修正结论：✅ 解决**。候选 C 收益从理论估算改为实测反推，收益区间诚实下调，L-02 教训满足。

```rust
for field in &self.fields {
    let value = match field.node.parse(py, stream, ctx, path) {
        Ok(v) => v,
        Err(ConstructError::StopField { .. }) => break,
        Err(mut e) => {
            e.push_path_segment(field.name.rust_name());
            return Err(e);
        }
    };
    match field.mode {
        FieldMode::Rw | FieldMode::Ro => {
            dict_bound.set_item(field.name.py_name().bind(py), value.bind(py))?;

        FieldMode::Wo => { drop(value); }
    }
}
```

**P1-5 修正结论：✅ 解决**。fast-path 核心实现完整，语义等价性可由 BC-C2 Round-trip 测试验证。

- 绝对加速比需重建基线："5.6 集成测试需用当前测量环境重新建立 B1 基线，不可直接引用 Phase 1 的 386ns" ✅ L-09 对策执行

**风险判定**：设计正确应用 L-09 教训（标注差异 + 要求重建基线 + 用 Controlled A/B Test 验证相对收益）。**不构成驳回理由**。
