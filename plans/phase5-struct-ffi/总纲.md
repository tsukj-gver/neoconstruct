# Phase 5：Struct + FFI 入口优化

## 目标

降低 FFI 入口开销，使小字段 Struct 场景加速比从当前 7-10x 提升到 **≥10x**。

## 背景

Phase 4 收尾时识别的待办（用户决策 2026-07-28）：

| 场景 | 当前性能 | 根因 | 目标 |
|------|---------|------|------|
| Phase 1 B1（3 字段 Struct parse） | 7.6x | FFI 入口开销稀释（小工作量） | ~12x |
| Phase 4 StopIf B1（StopIf(x==0) parse） | 9.63x | 同上 + Always-true 路径无优化空间 | ~15x |
| Phase 4 StopIf B1（StopIf(True) parse） | 9.93x | Always-true 路径无优化空间 | ~15x |
| Phase 4 E01（Array(0 Index) parse） | 9.51x（VET 复测） | 零工作量 + 测量环境漂移（L-09） | 待复审 |
| 4.x p_err_overflow | 2.72x | Python baseline 5.6µs 短导致固有边界 | 结构性限制，不强制 ≥10x |

**根因共性**：Rust 侧正常路径 ~200ns（§0 一次 FFI 约束），FFI 入口（pyo3 函数调用开销）固定开销占大头——对 3 字段 Struct 这种小工作量场景，FFI 入口开销占比过高，导致加速比 <10x。

## 功能范围

待 ARCH 分析报告确定。预期方向（基于 Phase 4 收尾讨论）：

1. **FFI 入口批量化**：减少 pyo3 函数调用次数（如多字段一次跨 FFI 而非每字段一次）
2. **Struct parse/build 入口重构**：复用 Phase 2.5 Context-Vec 思路（已在 Struct 大字段场景验证 ≥10x）
3. **pyo3 调用层次优化**：减少 Python→Rust 调用栈深度
4. **小字段 fast-path**：对 ≤3 字段 Struct 走专用路径

> **PM 边界**：以上方向待 ARCH 详细设计验证。PM 不预设技术方案。

## PM 决策（基于 ARCH 分析报告，2026-07-29）

### 决策 1：B1 硬目标 ≥10x（12x 为软目标）

ARCH 论证 B1 ≥12x 在当前架构不可达（A+B+C 上界 100ns < 126ns 缺口）。
- **硬目标**：B1 ≥10x（与 Phase 4 StopIf/RepeatUntil 一致）
- **软目标**：12x（如能达到更优，但不强制）
- **依据**：L-02 教训——不接受理论估算替代实证；ARCH 基于实测数据反推

### 决策 2：接受 unsafe raw FFI 热路径首次使用（候选 B）

- Phase 4.x 错误路径已有 raw FFI 先例（a_err_eof 11.34x）
- 本候选是**首次热路径**使用——VET 必须严格审查每处 unsafe 的 SAFETY 注释
- 性能验证用 Controlled A/B Test（L-09 教训）

### 决策 3：候选 D（单字段特化）作为 5.5 条件触发

- 仅当 5.2-5.4 实施后 StopIf S01/S03 仍 <10x 时启用
- 高风险（新增 Node 变体）高收益（仅单字段场景）
- 不强制实施——是后备方案

### 决策 4：5.6a 基线重建优先（基于 REV v2 P2-1 关键发现）

REV v2 发现 ARCH micro-benchmark 测得当前 B1 parse ~265ns（vs perf-scenarios.csv Phase 1 记录的 386ns）。如属实，3123/265≈11.78x，B1 可能已接近 ≥10x。

- **5.6a 提前执行**（在 5.2 实施前）：用 Controlled A/B Test 同会话重建 B1 当前基线
- **基于基线结果决策**：
  - 如 B1 已 ≥10x → Phase 5 范围缩小至仅 StopIf S01/S03 优化
  - 如 B1 仍 <10x → 继续 5.2-5.4 实施
- **L-09 教训**：不可跨时段对比（Phase 1 的 386ns vs 当前 265ns 差异需 Controlled A/B Test 排除环境漂移）

### 决策 5：FFI 优化 DEFERRED（基于 5.6a 基线重建实测数据）

5.6a 同会话 Controlled A/B Test 实测（3 轮均值 ± stddev）：
- **B1-modbus 11.64x ± 0.07**（≥10x + 1.64x 余量）
- B1-int3 12.12x ± 0.13
- B2/B3/B4 全部 ≥10x
- **StopIf S01 12.29x ± 0.12** / **S03 12.32x ± 0.05**（原 9.63x/9.93x 已自然达标）

**Phase 5 硬目标（全场景 ≥10x）在 5.2 实施前已自然达成**——Phase 2.5 Context-Vec + Phase 3-4 累积优化的附带收益。

PM 决策：
1. **取消 5.2-5.5**（FFI 入口优化 DEFERRED）——性能优化目标是达标而非刷分；B1 11.64x 有 1.64x 余量
2. **候选 B（unsafe raw FFI）的 ABI3 风险在目标已达成时不再值得承担**（L-02 教训）
3. **仅执行 5.6b**（CSV 更新 + L1-L4 全门禁验证）——固化基线重建数据
4. **FFI 优化设计文档保留**——未来如需进一步优化（如 Phase 6+），ARCH 的 A+B+C 设计 + ABI3 spike 仍可复用

> **教训**：Phase 5 立项时（Phase 4 收尾）基于 Phase 1 历史 B1=7.6x，未预见 Phase 2.5/3/4 累积优化会使 B1 自然达标。**L-02 教训验证**：理论估算（Phase 5 总纲原预估 B1 需优化到 ~12x）替代了实证数据（未在立项时重测 B1 当前性能）。iter10 后如遇类似"优化类 phase"立项，应先做基线重建再决定范围。

## S-PERF 出口标准

### 硬约束（继承 Phase 4）

1. **≥10x 全路径全场景**（无局部门禁、无兜底路径豁免）
2. **场景矩阵覆盖**：每构造器 ≥10 测量点（5 场景 × parse/build）
3. **逐项开销分析**：Python 端 + Rust 端，不允许拍脑袋估算
