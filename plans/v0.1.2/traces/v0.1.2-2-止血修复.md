# v0.1.2-2 [B1/B2/B3 单点止血修复] 过程记录

> 止血定位：框架级方案（v0.1.2-1，ARCH 并行进行中）落地后统一收敛。
> 修复小而准，不做大重构。

## 1. 根因定位

### B1/B4：值提供型字段实例化值 None → 表达式消费 build 失败

- **位置**：`neoconstruct/python/neoconstruct/_mixin.py` `_apply_dataclass_field_config`
  （修复前 L1005-1023 的字段配置循环）
- **机制**：v0.1.1 起值提供型 subcon（Const/Default/Rebuild/Computed/Padding）
  统一隐式 `default=None` + `kw_only=True`。Const/Default 的值语义是
  **值恒定/可静态得知**，实例化后应为描述符携带的值而非 None——None 流入
  build ctx 后表达式 `x+1` 求值报
  `expression field "<index 0>" has wrong type, expected integer`。
- **修复语义**（对照原版 2.10.70 锚点 `anchor_construct.py` C1-C7/D1-D6）：
  - Const → 隐式 default = `subcon.value`（常量值，int/bytes 均可）
  - Default → value 为 int 常量 → default=value；value 为表达式 → None（build 求值）
  - Rebuild/Computed/Padding → None 不变（build 由节点层补值/忽略）
  - 用户显式传错值给 Const（`P(x=9)`）→ 节点层 ConstError 校验保留

### B1f（B1 同族）：rfield(Const) 被表达式消费 → build 报 compute_ro_value 不支持

- **位置**：`neoconstruct/src/nodes/mod.rs` `Node::compute_ro_value`
  （修复前 L535-595 的 match，Const/Padding 落入兜底 Err 分支，
  错误信息自己都标注 "or Const/ContextParam (future)"）
- **机制**：RO 字段 build 走 compute_ro_value 自动补值，Tell/Computed/
  Rebuild/Default 等有分支，Const/Padding 没有 → `rfield(Const(1,Byte)) +
  Bytes(x+1)` build 直接报 Generic error。`rfield(Padding(2))` 同症
  （README/docstring 宣称用法，v0.1.2 前不可用）。
- **修复**：加两个分支——`Node::Const(c) => c.value().clone_ref(py)`（返回
  常量值，随后 ConstNode.build 收到 obj==value 校验通过）；
  `Node::Padding(_) => py.None()`（与 StopIf/Check 同模式，PaddingNode.build
  忽略 obj 写 pattern）。

### B2：BinExpr 嵌套包装器"静默错读"——调查结论：**HEAD 上不可复现，报错为显式 StreamError 且行为对齐原版**

系统排查过程（探针：`experiments/v0.1.2-probe/`）：

1. `probe_current.py` / `probe_b2_search.py` / `probe_b2_parse.py`：
   `field(Prefixed(Int8ub, Bytes(x+1)))` 的 build/parse/roundtrip、x=Const
   变体、两层 Prefixed、Const(97) 后置字段错位检查——**全部正常**。
2. `matrix_b2.py` 组合矩阵（消费者 × 包装器 × 形态，详见 §3）——**80/80 全绿**。
3. `probe_pypi_wheel.py`（PyPI 0.1.1 wheel 环境）：`V1.parse(b"\x01\x61\x62")`
   报 `stream read less than specified amount, expected 97, found 1`——
   **报错原文复现**。机制：Prefixed 长度字段读到数据字节 'a'(97) → 试图读
   97 字节只剩 1 → 显式 StreamError。这是**数据与 schema 不匹配的正确报错**
   （数据里没有长度字节），非静默错读；同数据形态在原版 construct 2.10.70
   下行为一致（`Prefixed` 同样读 97 报错）。
4. 原版锚点验证（`anchor_construct.py` E3/E4，.venv-pc 实测）：
   原版等价写法（长度前缀 + 字段引用 x 加 1 的 Bytes）parse
   `b"\x01\x02ab"` → `Container(x=1, y=b'ab')`、build → `b'\x01\x02ab'`
   ——与 HEAD 完全一致。
5. **防御排查**（任务要求"表达式程序缺失且非常量 → 必须编译期报错"）：
   grep 全部表达式消费点，20 处（Bytes/PaddedString/Array/StopIf/IfThenElse/
   Switch/RepeatUntil/Rebuild/Seek/Pointer/Default/Check/Aligned/Checksum）
   在 expr_programs 缺失/键缺失时**全部编译期 CompilationError**，无运行期
   回退路径（v0.1.1-3 的递归收集已覆盖 BinExpr——收集器对 _ExprRef 与
   _FieldDescriptor 一视同仁，`_compile_expr_param_value` L610）。

**结论**：B2 的修复实质 = v0.1.1-3 已完成（BinExpr 随字段引用一并修复）。
本任务交付 = 矩阵全绿证明 + 防御面排查确认 + 报错语义澄清（用户数据缺
长度字节；若用户意图是"无独立长度字节"应使用 `Bytes(x+1)` 而非
`Prefixed(Int8ub, ...)`）。**建议 v0.1.2-3 用户面矩阵测试集纳入
`expected 97` 数据不匹配负例**，锁定该报错为正确行为。

### B3：wo 表达式长度字段强制哑值

- **位置**：同 B1（`_apply_dataclass_field_config`）
- **机制**：`wfield(Bytes(x+1))` 的 subcon 非值提供型 → 落入"必填
  positional"分支 → 实例化 `W(x=1)` 报 missing argument。v0.1.1-3 修了
  `wfield(Padding)`（值忽略型），表达式长度字段漏了。
- **修复**：新增分支——wo 模式且 subcon 图中存在待编译字段表达式
  （新 helper `_subcon_contains_field_expr` 递归检测，协议与
  `_collect_exprs_from_node` 一致）→ 隐式 `default=None + kw_only=True`。
- **build None 语义**：`W(x=1).build()` 时 y=None 传给 BytesNode →
  `expected bytes object for Bytes field, received non-bytes value of type
  NoneType`。**保持节点层报错**（对齐原版缺键 KeyError 的诚实行为；
  wo+Bytes 的 None→哑零字节语义涉及 RW 面变化，超止血范围）。

## 5. 已知边界（遗留 v0.1.2-1 框架方案收敛）

1. **嵌套值提供型**：`field(Prefixed(Int8ub, Computed(x+1)))` 的字段仍需
   显式传 c（值提供型判断不递归——顶层 subcon 是 PrefixedDescriptor）。
   测试已锁定现状并在 docstring 标注（test_prefixed_computed_add）。
2. **wo+Bytes None build 报错**：`W(x=1).build()` 报 bytes 类型错（诚实
   报错，对齐原版）。哑零字节语义（Padding 式）超止血范围。
3. **B4 context= 注入**：`context=` 参数仍为"有壳无芯"（v0.1.1 P4 遗留，
   spike B4a 确认现状），按任务说明由 v0.1.2-1 框架方案处理。
