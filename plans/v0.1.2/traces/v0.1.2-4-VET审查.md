## 6. DEV 两项设计质疑的 VET 意见（供 PM 转 ARCH）

**① 延迟桩路径 init_defaults 回退（expr 非空→Optional / 其余 Required）**
- 实现复核：回退逻辑保守正确。但需澄清一个细节：`@dataclass` 的 `__init__` 在首次配置（桩安装
  时）固化，`_retry_compile` 成功后的再 setattr **不改变 init 签名**——因此延迟类的 Value 档
  默认值（Const 标量/常量折叠）**终身退化为必填**，并非仅"延迟窗口期"；DEV 报告"延迟窗口期
  实例化"表述略乐观（代码行为与意图一致，docstring 已注明"init 签名由首次配置确定"）。
- VET 倾向：可接受（触发场景=前向引用+值提供型字段，极罕见；无静默错值风险）。备选方案供
  ARCH 参考统一回退为 Optional（全字段可省、缺值错误后移 build）——与框架"错误时机=值使用点"
  哲学一致且方向安全（放宽）。两种均不阻塞，请 ARCH 定夺并回填设计。

**② Instance 分支 getattr 失败保持 Generic**
- VET 实测补充：真实 dataclass 场景下该 Generic 路径**几乎不可达**——RO 字段 init=False 且带
  类级 `default=None`，getattr 返回 None → 走 BuildValueMissing（实测 rfield(Int8ub) 缺属性抛
  FieldValueMissingError 而非 Generic）。Generic 仅在裸对象（非 dataclass、无类级默认）缺属性
  时触发（Rust 单测 mock 场景）。
- VET 意见：保守按设计字面实现正确；用户面行为实际已统一为 FieldValueMissingError。若 ARCH
  希望语义完全统一，可改为 AttributeError→BuildValueMissing（与 F1 泛化方向一致），其他错误
  保持 Generic。低影响，不阻塞。
