# v0.1.2-8 过程记录：三项红灯缺陷修复

> 输入：v0.1.2-7b2 红灯清单 #1/#2（xfail-strict 锁定）+ v0.1.2-7b1 观察项②。
> 修复后 xfail 标记移除、用例转绿；全部为最小侵入修复，无设计偏离。

## 1. 修复 #1：Probe 归 Control（红灯 1，round-trip 断裂）

- 根因：`ValueKind::classify`（struct_node.rs）Control 匹配表缺 ProbeNode，
  落入 `_ => Instance` 兜底 → `rfield(Probe())` build 期实例值 None ≡ 缺值
  → FieldValueMissingError。
- 修复：匹配表加 `Node::Probe(_) => ValueKind::Control`。ProbeNode 语义核实
  （probe.rs）：parse 返回 None、build 忽略 obj 不写字节——Control 的
  "显式值透传/缺省哑值 None、build no-op" 契约完全吻合。
- 同步：三处文档注释（ValueKind 模块表格 / Control 变体 / classify 规则）补
  Probe。
- 效果：Probe 字段实例化默认从 Required 变 Optional（随其他 Control 类一致），
  round-trip 字节稳定。

## 2. 修复 #2：ProcessRotateLeft build group<1 先校验（红灯 2，panic 红线）

- 根因：build 分支在参数校验前执行 `(-amount).rem_euclid(group*8)`，group=0
  时除零 panic（PanicException 逃逸到 Python 层，违反 AGENTS §3 禁 panic 红线）。
- 修复：build 分支在取负前校验 `group < 1` → 返回 Rotation
  `"group size must be at least 1 to be valid"`——与 parse 侧 rotate_left 的
  group 校验**同型对称**（同变体、同消息、path 同源）。
- 新增 Rust 单测 `build_group_zero_raises`（对称于既有 parse_group_zero_raises，
  断言 Rotation + "group" 语义词）。

## 3. 修复 #3：编译期 PaddingError 注入字段名 path（7b1 观察项②）

- 根因：`BitPaddingNode::new` 编译期构造 Padding 错误时 `path: String::new()`
  （注释声称"由上层 with_field_context 附加字段名上下文"，但该函数实际只处理
  Compilation 变体）→ Python 侧 str 形如 "Error in path \n..."（空 path 形态）。
- 修复：`with_field_context`（compile.rs，编译期错误字段上下文注入点）新增
  分支——Padding 错误携带**空 path** 时注入字段名（非空 path 的运行期错误
  原样透传，既有 pass-through 单测不变）。
- 效果：`Padding(4, pattern=2)` 编译期报错 path == 出错字段名，str 形如
  "Error in path pad\nbit-domain padding pattern must be..."。
- 测试：errors 用例 `test_bit_padding_invalid_pattern_raises_padding_error`
  补 path 断言（"pad" in path）；compile.rs 补单测（空 path 注入 + 非空 path
  不覆盖双断言）。
