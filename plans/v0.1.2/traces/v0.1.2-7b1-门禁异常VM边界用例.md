# v0.1.2-7b1 开发记录：G2 parity 门禁修复 + G3 异常分类学 + G4 VM 算术边界

## 1. G2：RepeatUntil parity 门禁空洞修复

### 1.1 根因复现

- 现象：`test_array_parity.py` R1-R3 共 12 skip（4 测试函数 × 3 case），
  skip 原因 "impl error - parity 子进程失败 impl=rs"。
- 复现（`experiments/repeatuntil-parity-error-probe/probe_lambda_reject.py`）：
  rs 侧 case 定义使用 Python lambda 作为 RepeatUntil 终止条件，
  `RepeatUntilDescriptor.__init__` 按设计抛
  `CompilationError: RepeatUntil terminator must be a field expression ... not a
  Python callable`（有绿灯测试 `test_repeat_until_descriptor.py::test_callable_lambda_rejected`
  锁定该拒绝行为，错误消息指引复杂终止逻辑走用户面 Adapter）。
- **定性：测试基建问题（case 定义与当前 API 漂移），非库缺陷**。PyCallable
  路径是被有意移除的设计（表达式系统不接 lambda）。

### 1.2 修复方案（双端探针验证后实施）

| case | 修复前（漂移） | 修复后 |
|------|----------------|--------|
| R1 | rs: `RepeatUntil(lambda x,lst,ctx: x>5, Int8ub)` | rs: `e=rfield(Element())` + `RepeatUntil(e > 5, Int8ub)`；py 不变 |
| R2 | rs: 依赖 list 内容的 lambda（VM 无 list 访问能力，永不可表达） | 双端重定义为"哨兵来自前序字段"：rs `RepeatUntil(e == stop, Int8ub)`+stop 字段；py `lambda x,lst,ctx: x == ctx.stop`+stop 字段 |
| R3 | 双端谓词 `x != -1`（首元素即真即停，与 case 自身描述"哨兵 -1"矛盾——既有 case 定义缺陷） | 双端改为 `== -1`（在哨兵处停止）：items=[1,2,3,-1]，字节 `010203ff` |

- 探针双端验证：`probe_fixed_cases.py`（rs：Element/跨字段/负常量三条路径
  parse/build/roundtrip 全对）、`probe_r2_py_side.py` / `probe_r3_py_side.py`
  （py 侧等价形态）。R2 重定义比原 PyCallable 语义更有价值（覆盖终止条件
  跨字段引用），且两 impl 均原生可表达。
- 容错 fixture（`_check_impl_error`）保留——真正的基础设施故障仍以 skip 呈现；
  更新"工程处理"注释为历史处理记录。

### 1.3 结果

- `test_array_parity.py`：109 passed / 0 skip（原 97 passed + 12 skip）。
- parity 全目录：397 passed + 8 skipped（RC2/RC3/RB1/AC1 文档化不对称，非本任务范围）。
- **12 个 parity 断言恢复为正常门禁**。

### 2.1 无正触发路径的类（5 个，层次断言锁定 + 文件内说明）

| 类 | 现状（实测+docstring 佐证） |
|----|------------------------------|
| ExplicitError | 用户回调 raise 的 Python 异常经内核 From<PyErr> 统一转 Generic（仅特判 CancelParsing），Select/Peek 识别不了原始类型→被吞。_errors.py 已声明的文档化已知差异；另写现状锁定用例（修复后应转断言传播） |
| IndexFieldError | Index 缺上下文返回 None（宽松模式），保留供严格模式 |
| StopFieldError | 内部哨兵，实测 Array/Struct 内均被捕获不逃逸（探针 B：Array(2,Inner) 含 StopIf 正常产出） |
| SizeofError | 用户面无 sizeof 调用入口（`hasattr(P, "sizeof") == False` 实测） |
| UnresolvedReferenceError | 仅 struct_ref resolve_schema 运行时产生；编译期无 "unresolved" 生产者→延迟桩无法经用户面自然创建（探针仅能以手动置 `_construct_compiled=None` 模拟验证错误形态） |

**以上非红灯缺陷**（无 panic、语义有 docstring 依据），供 PM 知悉；
若认为需要用户面正例（如 sizeof API、Explicit 穿透修复），建议另立任务。

## 3. G4：表达式 VM 算术边界（tests/unit/test_expression_arithmetic.py，15 例）

探针（`probe_errors_c_vm.py`）→ 实现（expr.rs 注释佐证）→ 用例：

| 边界 | 实测形态 | 用例数 |
|------|----------|--------|
| `n // 0` / `n % 0` | ExprDivByZero → Python 基类 ConstructError（"expression division/modulo by zero"，path=root.c） | 2 |
| `Bytes(n // 0)` 消费者 | GenericConstructError 内嵌除零原因 | 1 |
| i64 溢出：`(2**63-1)+1`、`-(i64::MIN)`、`(2**63-1)**2` | 回绕（wrapping，expr.rs 文档化：任意精度与性能目标冲突） | 3 |
| 移位：`<<63`、`<<64`、`>>64` | `<<63`=i64 位模式 MIN；`>=64` 移位量按 64 掩码（wrapping_shl/shr） | 3 |
| 负移位 `<< -1` | GenericConstructError "negative shift count"（显式检查 b<0） | 1 |
| `Bytes(2**62*2)` 溢出为负 | FieldLengthError "evaluated to negative"（消费者负值防御） | 1 |
| `Bytes(n*2)` 超流长 | StreamError（正常流错误路径） | 1 |
| floor 语义 `-7//2`、`-7%2` | -4 / 1（真 Python floor 语义，非截断） | 2 |
| 比较链 `(x>3)+10` | 11/10（比较返回 0/1 整型） | 1 |

**全部显式异常或文档化回绕，零 panic——无红灯缺陷**。
