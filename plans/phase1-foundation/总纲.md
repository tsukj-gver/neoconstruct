# Phase 1: 基础架构

## 阶段目标

建立 Rust 项目的骨架和核心基础设施，包括项目结构、核心 trait 定义、错误体系、值类型系统、Context 容器和流抽象。本阶段是所有后续阶段的基石。

## 前置依赖

- 无（项目起始阶段）

## 子任务清单

### 1.1 项目初始化（trivial）

- [x] 创建 Rust 项目 (`cargo init --lib construct-rs`)
- [x] 配置 `Cargo.toml`：最小依赖（`thiserror`），可选依赖（`byteorder`, `num-bigint`, `flate2`）
- [x] 设定 MSRV（Minimum Supported Rust Version）为 1.70+
- [x] 创建 `src/` 目录结构骨架（空 mod.rs 文件）
- [x] 配置 `clippy` 和 `rustfmt`
- [x] 验证：`cargo build`, `cargo clippy`, `cargo fmt --check` 通过

**参考**：`docs/总设计文档.md` → 项目结构

### 1.2 错误体系设计

- [x] 定义 `ConstructError` 枚举及 ~15 个核心子类型（覆盖本阶段需要的错误）
  - `FormatFieldError` — 格式字段解析/构建失败
  - `StreamError` — 流读写错误
  - `SizeofError` — 大小计算失败
  - `ValidationError` — 值校验失败
  - `ConstError` — 常量不匹配
  - `ArrayError` — 数组操作错误
  - `IndexError` — 索引越界
  - `PaddingError` — 填充错误
  - `CheckError` — 检查失败
  - `TerminatedError` — 终止符错误
  - `StringError` — 字符串编解码错误
  - `MappingError` — 映射查找失败
  - `ExprError` — 表达式求值错误
  - `UnionError` — Union 操作错误
  - `SwitchError` — Switch 分支错误
- [x] 所有错误携带 `path: String` 字段用于错误追踪
- [x] 实现 `std::fmt::Display` 和 `std::error::Error`
- [x] 验证：编译通过，错误可正确创建和格式化

**参考**：`docs/模块设计-错误体系.md`

### 1.3 值类型系统 (Value)

- [x] 定义 `Value` 枚举类型，替代 Python 的动态类型
  - `None`, `Bool(bool)`, `Int(i64)`, `UInt(u64)`, `BigInt(i128)`
  - `Float(f64)`, `Bytes(Vec<u8>)`, `String(String)`
  - `List(Vec<Value>)`, `Container(IndexMap<String, Value>)`
- [x] 为 `Value` 实现类型转换方法（`as_int()`, `as_bytes()` 等）
- [x] 实现 `From` trait 用于常见类型转换
- [x] 实现 `PartialEq`, `Clone`, `Debug`, `Display`
- [x] 验证：Value 可以正确创建、转换和比较

**参考**：`docs/模块设计-值类型系统.md`

### 1.4 Context 容器

- [x] 实现 `insert`, `get`, `get_or_error` 方法
- [x] 实现上下文作用域（进入/退出嵌套时自动创建/恢复子上下文）
- [x] 验证：Context 嵌套读写正确，父子隔离正确

**参考**：`docs/模块设计-Context容器.md`

### 1.5 流抽象

- [x] 定义 `Stream` trait（基于 `std::io::Read` + `Write` + `Seek`）
- [x] 实现 `ByteStream`：包装 `Vec<u8>` 或 `Cursor<Vec<u8>>`
- [x] 实现辅助函数：`stream_read`, `stream_write`, `stream_seek`, `stream_tell`, `stream_size`, `stream_iseof`
- [x] 所有流操作统一错误处理（返回 `ConstructError::Stream`）
- [x] 验证：可以正确读写字节流，seek/tell 正常工作

**参考**：`docs/模块设计-流抽象.md`

### 1.6 Construct 核心 trait

- [x] 定义 `Construct` trait：
  ```rust
  pub trait Construct {
      fn parse(&self, stream: &mut dyn Stream, ctx: &mut Context) -> Result<Value>;
      fn build(&self, data: &Value, stream: &mut dyn Stream, ctx: &mut Context) -> Result<()>;
      fn sizeof(&self, ctx: &Context) -> Result<usize>;
  }
  ```
- [x] 为 `Construct` 提供 `parse_stream` / `build_stream` 便捷方法（接受泛型流）
- [x] 实现 `Renamed` 包装器（字段命名），operator 重载用方法实现
- [x] 验证：trait 编译通过，可以创建简单的自定义 Construct 实现

**参考**：`docs/模块设计-Core Trait.md`

## 阶段出口标准 (Exit Criteria)

1. **编译通过**：`cargo build` 零 error，`cargo clippy` 零 warning
2. **测试通过**：`cargo test` 全部 PASS，覆盖率 > 80%
3. **代码规范**：`cargo fmt --check` 通过
4. **功能完整**：
   - `Construct` trait 可被实现和使用
   - `Value` 支持所有列出的类型变体
   - `Context` 支持嵌套和父子引用
   - `Stream` 支持读写和定位
   - 错误体系覆盖本阶段所有错误场景
5. **文档完整**：所有 pub 项有 `///` 文档注释
6. **无外部依赖**（除 `thiserror`）

## 预估工期

~2 周

## 风险与注意事项

- `Value` 枚举的变体可能在后续阶段需要扩展，需预留扩展空间
- `Construct` trait 的签名（参数可变性、生命周期）需仔细设计，避免后期大规模重构
- 流抽象需要兼顾位级操作的需求（Phase 6 会扩展）
