### [设计质疑] 偏离说明

**`with_path_prefix` 签名：`&self` → `self`**

- 设计文档：`pub fn with_path_prefix(&self, prefix: &str) -> Self`
- 实际实现：`pub fn with_path_prefix(self, prefix: &str) -> Self`
- 原因：`Stream` 变体的 `io::Error` 与 `StringEncoding` 变体的 `FromUtf8Error` 均未实现 `Clone`。设计提示的 `source.kind().into()` 仅适用于 `io::Error`（且会丢失原始错误详情），对 `FromUtf8Error` 完全无法在 `&self` 下重建。按值消费可原样移动 source 字段，完整保留底层错误。该方法语义为"错误传播时丰富"，调用方不会再使用原错误，按值消费符合惯用 Rust 模式。
- 影响：属小问题（参数传递方式微调），不影响错误类型本身。等待 PM/ARCH 确认。

### 行为一致性：✅ 一致

#### 错误信息格式

Python 错误格式：`"Error in path {path}\n{message}"`（ConstructError.__init__ 第 17-22 行）
Rust 错误格式：`"{variant_name} at {path}: {details}"`（各变体 #[error] 属性）

两者均包含：① 错误类型描述 ② 路径信息 ③ 错误详情。格式差异是语言惯例差异（Python 换行 vs Rust 单行），信息完整度一致。

#### 路径分隔符差异（非阻塞性）

- Python 使用 `" -> "` 分隔符（core.py 第 2772 行 `path += " -> %s" % (self.name,)`），初始路径为 `"(parsing)"`/`"(building)"`/`"(sizeof)"`
- Rust 使用 `"."` 分隔符（error.rs 第 20-25 行 `join_path`），设计文档示例使用 `" > "`

三者不一致，但功能等效。Rust 的 `"."` 分隔符更符合 Rust 生态惯例。此为 [设计质疑] 点，建议 PM/ARCH 确认是否需要统一为 `" > "` 或保持现状。

#### 路径追踪机制

| 功能 | Python 行为 | Rust 行为 | 一致性 |
|------|-----------|----------|--------|
| 初始路径 | `"(parsing)"` 等 | 由调用方设定 | ✅ 功能等效 |
| 路径拼接 | Renamed 类 `path += " -> name"` | `with_path_prefix` 拼接 `"prefix.path"` | ✅ 功能等效 |
| 空路径处理 | `path=None` 时不加前缀 | `join_path` 中 `path.is_empty()` 时仅用 prefix | ✅ 一致 |

#### source 链传播

| 错误变体 | Python 行为 | Rust 行为 | 一致性 |

| `Stream` / `StreamError` | 捕获 Exception 并转为 StreamError | `#[source] io::Error` | ✅ Rust 更精确（仅 I/O 错误） |
| `StringEncoding` / `StringError` | 捕获 UnicodeError 并转为 StringError | `#[source] FromUtf8Error` | ✅ 仅处理 UTF-8，其他编码错误可后续扩展 |
