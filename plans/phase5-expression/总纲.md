# Phase 5: 表达式系统

## 阶段目标

实现延迟求值表达式系统，使构造器参数可以在运行时根据上下文动态计算。这是 construct 库的核心特性之一，允许字段大小和条件依赖于先前解析的值。

## 前置依赖

- Phase 1 完成（Value, Context 就绪）
- Phase 2-4 完成（构造器需要表达式来引用上下文值）

## 子任务清单

### 5.1 Path 路径引用系统

- [ ] 实现 `Path` 结构体：表示对上下文字段的引用路径
  - 支持路径拼接：`this.header.length` → 多级路径
  - 支持 `this`（当前上下文）和 `obj_`（构建对象）两种根
  - 支持 `list_`（列表元素引用）
- [ ] 实现 `Path::evaluate(&self, ctx: &Context) -> Result<Value>`
  - 沿路径逐级查找 Context/Value 中的值
- [ ] 验证：多级路径查找正确，缺失路径返回错误

**参考源码**：`construct/construct/expr.py` → `Path` class

### 5.2 表达式节点

- [ ] 实现 `BinExpr`：二元运算表达式
  - 支持运算：`+`, `-`, `*`, `/`, `%`, `<<`, `>>`, `&`, `|`, `^`
  - 支持比较：`==`, `!=`, `<`, `>`, `<=`, `>=`
  - 支持逻辑：`&&`, `||`
- [ ] 实现 `UniExpr`：一元运算表达式
  - 支持：`-`, `!`, `~`
- [ ] 所有表达式实现 `Evaluate` trait：`fn evaluate(&self, ctx: &Context) -> Result<Value>`
- [ ] 运算符重载：为 `Path` 和表达式实现 `Add`, `Sub`, `Mul` 等 trait
- [ ] 验证：各种运算表达式求值正确

**参考源码**：`construct/construct/expr.py` → `BinExpr`, `UniExpr`

### 5.3 内置函数

- [ ] 实现 `FuncPath`：包装内置函数为表达式
  - `len_` → `Value::List` 的长度
  - `sum_` → 列表求和
  - `min_`, `max_` → 列表最小/最大值
  - `abs_` → 绝对值
  - `this_` → 路径求值的包装
- [ ] 验证：内置函数在表达式上下文中正确求值

**参考源码**：`construct/construct/expr.py` → `FuncPath`

### 5.4 表达式与构造器集成

- [ ] 定义 `IntoExpr` trait：允许参数接受整数、闭包或表达式
  ```rust
  pub trait IntoExpr {
       fn into_expr(self) -> Box<dyn Evaluate>;
  }
  ```
  - `impl IntoExpr for usize`
  - `impl IntoExpr for Box<dyn Evaluate>`
  - `impl IntoExpr for Path`
- [ ] 修改 Phase 2-4 中的构造器参数类型，使用 `IntoExpr` 替代硬编码整数
  - `Bytes::new(length: impl IntoExpr)`
  - `Array::new(count: impl IntoExpr, inner: Box<dyn Construct>)`
  - `If::new(cond: impl IntoExpr, ...)`
- [ ] 验证：构造器参数支持动态表达式

### 5.5 三元条件表达式

- [ ] 实现 `ExprCond` / 三元表达式：`condition ? then : else`
- [ ] 支持 `this.x > 0` 这种条件表达式直接作为 `If` 的参数
- [ ] 验证：条件表达式在上下文中正确求值

### 5.6 单元测试

- [ ] 测试 `Path` 多级路径解析
- [ ] 测试二元/一元表达式运算
- [ ] 测试内置函数
- [ ] 测试表达式与构造器的集成场景
  - `Struct` 中字段大小依赖前序字段
  - `If` 条件依赖上下文值
  - `Array` 长度依赖上下文值
- [ ] 验证：`cargo test` 全部通过

## 阶段出口标准 (Exit Criteria)

1. **编译通过**：`cargo build` / `cargo clippy` 无问题
2. **测试通过**：`cargo test` 全部 PASS
3. **功能完整**：
   - `this` 路径引用在 parse 和 build 上下文中正确工作
   - `obj_` 路径引用在 build 上下文中正确工作
   - 二元/一元表达式运算正确
   - 内置函数正确
   - 构造器参数支持动态表达式
4. **与 Python 版本兼容**：表达式语法和语义与 `this`/`obj_` 一致
5. **性能合理**：表达式求值无显著性能瓶颈

## 预估工期

~1 周

## 风险与注意事项

- 表达式系统的运算符重载在 Rust 中不如 Python 灵活，可能需要使用方法链
- `this` 和 `obj_` 在 Rust 中无法像 Python 那样作为全局单例使用，需要设计导入机制
- 表达式求值的性能可能成为瓶颈，后续 Phase 9 需要优化
- `IntoExpr` trait 的设计需要兼顾易用性和类型安全
- 修改 Phase 2-4 已有构造器的参数类型是侵入性变更，需谨慎处理
