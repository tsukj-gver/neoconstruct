### 修复 2：7.1 parity 测试 case 缺陷

**缺陷 A**：所有 9 个 case 的 `extract` lambda 返回 `{'v': o.v}`（dict），但 py 侧 parse 返回裸值。
helper 模板 py 分支 `dict(parsed_obj) if hasattr(parsed_obj, 'items') else parsed_obj`：
IfThenElse/Switch/Select/FocusedSeq 的 parse 返回裸 int/None，py 侧即裸值。
rs 侧 extract 必须返回裸值对齐。修正：`lambda o: {'v': o.v}` → `lambda o: o.v`（9 处 replaceAll）。

**缺陷 B**：F1 case 用 `FocusedSeq("num", Bytes(3), Renamed("num", Int8ub))`。
Python/construct-rs 的 FocusedSeq 对非 focus 字段 build 时传 None（源码
`sc._build(obj if sc.name == parsebuildfrom else None, ...)`），裸 `Bytes(3).build(None)` 两端均失败。
实测 py 侧 `FocusedSeq.build(0xFF)` 同样抛 StringError。
修正：`Bytes(3)` → `Pass`（build(None) 成功），保留 focus 提取核心语义；
匿名消费字节的场景留 Phase 7.3 集成测试补充。

**性质判定**：A/B 均为 7.1 DEV 的测试 case 设计缺陷，非 compile.rs dispatch 或 Node 实现 bug。
rs 的 FocusedSeq build 行为与 Python 完全 parity（非 focus 传 None）。
