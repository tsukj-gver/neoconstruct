### 偏离设计文档

1. **eval_at / eval_offset 签名**：移除未使用的 `path: &mut Path` 参数。
   原因：函数体内仅用错误自带的 path（push_path_segment 修改错误本身，不读取 path 参数）。
   移除后避免 unused variable 警告。属于实现细节调整，不影响接口。

2. **BuildStream bit API 同步 pos**：设计 §3.1.3 说 "bit API 不感知 pos"，但若不同步
   会导致连续 bit 写入触发 `debug_assert!(pos == buf.len())`。本实现选择在 bit API
   的每次 `buf.push / buf.resize` 后同步 `self.pos = self.buf.len()`，使连续 bit 写入
   始终满足 `pos == buf.len()`，仅"先 seek 再 bit 写"会触发守卫（与设计意图一致）。

3. **Phase 7.1 WIP 处理**：发现 Phase 7.1 的 compile.rs dispatch 调用了未实现的
   `build_if_then_else_node` / `build_switch_node` / `build_focused_seq_node`，
   且 SelectDescriptor 使用了 pyo3 0.22 不存在的 `try_iter` API，导致构建失败。
   DEV 临时将这些 dispatch 改为返回 Compilation 错误（"Phase 7.1 not yet implemented"），
   并删除了 3 个 broken function bodies（其节点定义 if_then_else.rs / switch.rs /
   focused_seq.rs 保留）。Phase 7.1 ACCEPTED 时由其 DEV 恢复。
   **[设计质疑]**：Phase 7.1 留下了 incomplete & broken 代码状态，建议 PM 通知 Phase 7.1
   DEV 修复。

### 需要PM注意的事项

1. **Phase 7.1 状态**：当前 Phase 7.1 (Conditional) 在 compile.rs 中是 broken 状态。
   本 Phase 7.2 DEV 已最小化影响（节点定义保留，仅 dispatch 暂时返回错误）。
   建议检查 Phase 7.1 进度，确认是否需要 ARCH/DEV 重新分派修复。

2. **stream 参数（换流）不支持**：PointerDescriptor 的 `stream` 参数非 None 时编译期
   拒绝（已知限制）。这与 Python construct 的 Pointer 行为有差异（Python 允许换流）。
   设计文档 §3.3 已记录此限制。

3. **Sequence / Tuple 未实现**：设计文档 §10.1 的 parity 测试模板使用 Sequence，
   但 construct-rs 尚未实现 Sequence/Tuple 顶层容器。本实施用 Struct + 单字段包装
   替代，所有场景都能正常工作。
