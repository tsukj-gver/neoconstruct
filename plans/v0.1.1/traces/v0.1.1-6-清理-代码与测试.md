# v0.1.1-6 清理：代码与测试（DEV 交付）

## 1. fallback 新设计说明

旧实现：`_VENV_ROOT = Path(r"C:\Users\<dev-user>\...\opencode")` + `crs_venv_313` /
`crs_venv_new` 等开发机 venv 名（tests 侧另有历史 8.ENV 注释段）。换机即失效，
且泄露开发环境信息。

新 fallback 链（conftest.py 为准，全部文件同步）：

```
1. 环境变量 CRS_PYTHON / PC_PYTHON（路径存在时优先——CI / 换机覆盖用）
2. 项目内 venv（基于文件位置的相对定位，兼容 Windows `Scripts/python.exe`
   与 POSIX `bin/python` 两种布局）：
   - construct-rs/.venv    （construct-rs 扩展）
   - construct-rs/.venv-pc （原版参考 construct==2.10.70）
3. sys.executable（最后手段，保留原行为）
```

- 措辞参照 README「测试环境变量」小节，**不提任何具体用户路径**。
- conftest.py / _system_helpers.py 用 `_venv_python(venv_name)` helper；
  parity 测试文件用 `_resolve_venv_python(env_var, venv_name)`（保持各文件
  standalone 结构，最小改动）；bench 脚本 `_resolve_venv(env_var, venv_dir)`
  第二参数语义从「python.exe 全路径」改为「venv 根目录」（内部探测布局）。
- conftest.py L43-49 的 8.ENV 历史环境注释段（crs_venv/crs_venv_new/
  crs_venv_313/Python 3.14 abi3 等开发机细节）整段删除，替换为现行约定
  三行说明。bench_phase8.py 的同主题 8.ENV 注释块、bench_opt_shared_retest.py
  docstring 中 `crs_venv_313` 引用一并清除。
