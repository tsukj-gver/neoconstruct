## 1. 复现结果

### 1.1 BUG-1：Switch 在 Prefixed 包装下无法引用根节点字段

最小用例（用户原始写法，`bug1_prefixed_switch.py`）：

```python
@dataclass
class P(StructMixin):
    typ: int = field(Int8ub)
    br: Any = field(Prefixed(Int8ub, Switch(typ, {1: Int8ub, 2: Bytes(2)})))
```

**失败阶段：编译期（`__init_subclass__`），非 parse/build 期。**

Traceback 关键行：

```
File "...\python\construct\_mixin.py", line 1056, in __init_subclass__
    _compile_schema_for_class(cls)
File "...\python\construct\_mixin.py", line 879, in _compile_schema_for_class
    cls._construct_compiled = _compile_schema(
construct._errors.CompilationError: field 'br': Switch keyfunc is not a constant
but no expression program was provided (field index 1). For complex expressions
like 'this.x + 1', use Computed(this.x + 1) to pre-compute, then Switch(this.key, ...).
```

- 实际：class 定义即抛 `CompilationError`，parse/build 无从执行
- 预期（原版 construct 2.10.70 实测基线）：`Prefixed(Int8ub, Switch(this.typ, {...}))` parse/build 完全正常——
  - `d.parse(b"\x01\x01\x7f")` → `Container(typ=1, br=127)`
  - `d.build({"typ": 2, "br": b"AB"})` → `b"\x02\x02AB"`
- 对照实验：去掉 Prefixed 包装的裸 `field(Switch(typ, {...}))` 在 construct-rs 中 parse/build 均正常 → 问题特定于「包装后」

### 1.2 BUG-2：Const / Default 作为 field 时 `P()` 报 missing arguments

用户原始写法 `field(Const(5))`（不带 subcon）实际在**描述符构造期**即失败（`bug2_const_default.py`）：

```
File "...\python\construct\_descriptors.py", line 2275, in Const
    return ConstDescriptor(value, subcon=subcon)
File "...\python\construct\_descriptors.py", line 2231, in __init__
    raise CompilationError(
construct._errors.CompilationError: Const requires explicit subcon when value
is not bytes, e.g. Const(255, Int32ub)
```

注：原版 2.10.70 对 `Const(5)` 同样失败（`StringError given non-bytes value 5`），此处行为对齐，非 BUG（见 P5）。

带 subcon 后到达用户报告的 TypeError（`bug2_matrix.py`）：

| 用例 | 实际 | 预期 |
|------|------|------|
| `field(Const(5, Int8ub))` → `PC()` | `TypeError: PC.__init__() missing 1 required positional argument: 'v'` | 正常实例化；build 用常量 5 |
| `field(Default(Int8ub, 9))` → `PD()` | `TypeError: ... missing 1 required positional argument: 'v'` | 正常实例化；build 用默认 9 |
| `PC(v=None).build()` | **`b'\x05'`（正常）** | — |
| `PD(v=None).build()` | **`b'\t'`（正常）** | — |
| `PC.parse(b'\x05')` / `PC(v=5).build()` | 正常 | — |

**关键事实：Rust 节点层已完整支持「值提供」语义（build 接受 None），仅 dataclass `__init__` 层强制要求实参**——BUG-2 是纯 Python 面的实例化摩擦问题。

原版对照：`Struct("v"/Const(5,Int8ub),"n"/Int8ub).build({"n":1})` → `b'\x05\x01'`；`Default` 同理 `b'\t\x01'`（build 时缺 key 自动补值）。

## 2. 根因定位

### 2.1 BUG-1 → Python 面表达式收集不递归（主因）+ Rust 面查表失败（报错点）

机制链条：

1. **`_mixin.py:583-627` `_extract_and_compile_exprs(subcon, ...)`**：只读取字段**顶层** subcon 的 `_expr_params` 属性（L605 `getattr(subcon, "_expr_params", None)`），**不递归进入包装器描述符的 `.subcon` / `.cases` / `.subcons` 等子槽位**。
2. **`_mixin.py:649-651` `_compile_expressions`**：对每个字段只调用一次上述函数 → `Prefixed(Int8ub, Switch(typ, ...))` 的 `PrefixedDescriptor._expr_params` 是**空 dict**（`_descriptors.py:2128`，注释声称「subcon 由递归处理」——实际没有任何递归收集逻辑），内层 Switch 的 `{"key": typ}` 被完全遗漏。
3. **`compile.rs:2213-2223` `build_switch_node`**：Rust 侧节点递归构建本身正常（`build_prefixed_node` L2994-3019 会递归编译 subcon，并**沿用同一 field_index** 下传），Switch 发现 keyfunc 非 int/bool 常量后查 `expr_programs[field_index]` → 该位置为 `None` → 抛出用户看到的 CompilationError（L2217-2222）。同类错误点：Bytes L347-352、Array L1813、IfThenElse L2089、Computed L429-441、RepeatUntil L2493、Rebuild L2656、Default L3311、Check L3361、Aligned L3511、Checksum L3777。

**运行时机制无问题**（证据见 §4.4）：context 按字段索引取值（GetInt(field_index)），Prefixed/PrefixedArray 的 parse/build 将 ctx 原样传递给子节点，嵌套消费者引用外层字段在运行时天然可见——只缺编译期的表达式程序。

### 2.2 BUG-2 → `_apply_dataclass_field_config` 不按 subcon 语义推导 default

- **`_mixin.py:807-820`**（`_apply_dataclass_field_config`，函数起于 L781）：字段获得 dataclass default 的唯一条件是 `desc.default is not _MISSING`（即用户显式传了 `field(..., default=...)`）。分支：
  - `mode == "ro"` → `dataclasses.field(init=False, default=None)`（rfield 路径，正常）
  - RW/WO 有 default → `dataclasses.field(kw_only=True, default=...)`
  - RW/WO 无 default → 裸 `dataclasses.field()`（**必填 positional 参数**）
- `field()`/`wfield()`（`_mixin.py:250-301`）对 subcon 类型不做任何区分：`Const`/`Default`/`Rebuild`/`Computed`/`Padding` 这些「build 时可自动获得值」的构造器同样落入「必填」分支 → BUG-2。
- `_descriptors.py` 中**没有** default 生成逻辑（任务指示的搜索目标 `_descriptors.py` 中 field() 不在此文件）；default 生成全部在 `_mixin.py` 上述函数。

### 4.4 修复假设验证（monkeypatch 实验，不改库代码）

对 `_mixin._extract_and_compile_exprs` 打补丁：遇到 `PrefixedDescriptor`/`PrefixedArrayDescriptor` 时递归读取内层 subcon 的 `_expr_params` 并并入该字段的 expr dict（`fix_hypothesis.py`）。**全部组合即刻恢复正常**：

| 用例 | 结果 |
|---|---|
| `Prefixed × Switch` parse（typ=1/2 两分支） | `P(typ=1, br=127)` / `P(typ=2, br=b'AB')` ✓ |
| `Prefixed × Switch` build | `b'\x01\x01\x7f'` / `b'\x02\x02AB'` ✓ |
| `Prefixed × Computed(typ)` parse/build | `P2(typ=1, br=1)` / `b'\x01\x00'` ✓ |
| `Prefixed × If(typ == 1, ...)` parse（true/false） | `P3(typ=1, br=127)` / `P3(typ=0, br=None)` ✓ |
| `Prefixed × Bytes(typ)` parse/build | `P4(typ=2, br=b'AB')` / `b'\x02\x02XY'` ✓ |
| `PrefixedArray × Switch` parse/build | `P5(typ=1, br=[5, 6])` / `b'\x01\x02\x05\x06'` ✓ |

**结论**：Rust 运行时（ctx 传递 + GetInt 字段索引解析）对嵌套消费者已完全支持，缺口纯粹在 Python 侧编译期的表达式收集——P1 的修复是 Python 面小改，无需动 Rust 内核。

**修复时须注意的两个设计点**：
1. **参数名冲突**：expr_programs 按 `field_index → {param_name: ops}` 组织。同一字段下嵌套多个同类消费者（如 `Union(None, Switch(a,...), Switch(b,...))` 两个 "key"）会互相覆盖。需要路径感知的键（如 `"subcon.key"`）或每节点独立注入——建议 ARCH 在 v0.1.1-3 前给出键格式决策（trivial 级，但影响 Rust 侧读取代码）。
2. **递归范围**：完整修复需遍历所有容器槽位（`.subcon`、`.subcons` 列表、`.cases` dict values、`.default`、`.lengthfield`、`.thensubcon`/`.elsesubcon`），而非仅 Prefixed 一层；前向引用检查（`_check_forward_reference`）对嵌套 ops 同样适用，语义不变。
