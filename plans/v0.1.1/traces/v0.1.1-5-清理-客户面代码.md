### 3.3 switch.rs「复杂表达式编译期拒绝」失真（3 处）

P10 已锁定 `Switch(typ + 1)` 顶层可用（v0.1.1-2 补测试），docstring 仍声称「复杂表达式（`this.x + 1`）编译期拒绝（引导用 Computed 预计算）」。改写为：「keyfunc 支持 int/bool 常量与字段名表达式（含算术，如 `n + 1`）；不接收 Python callable/lambda（ADR-014）」。

### 3.4 compile.rs:2246-2248 错误文案残留（P6 修补遗漏）

Switch keyfunc 编译失败文案仍带对比警示尾句（`'this.xxx' syntax does not exist…`），删除（无测试锚定该文案，已复扫确认）。

### 3.5 compile.rs:431-433 ComputedDescriptor 常量注释

原文「常量（非 FieldRef/ExprRef）不编译」——DF1 后 int 常量编译为 Const ExprOp。改为「不可编译常量（bytes/str 等；int 常量会编译为 Const）」。

### 3.6 Sequence 示例为不可用原版语法

`Sequence("count"/Byte, "data"/Bytes(lambda this: this.count))` 三重不可用：lambda（ADR-014 拒绝）、`"/"` 运算符（全库无 `__rtruediv__`，实测 TypeError）、序列内交叉引用（实测 NameError）。改为实测通过的关键字形式 `Sequence(count=Byte, data=GreedyBytes)`。

### 3.7 Renamed/FocusedSeq「`/` 运算符」失真（4 处）

Renamed docstring「通常通过 `"/"` 运算符创建」+「仅用于 FocusedSeq」、FocusedSeq 参数说明 2 处 + 示例 `"num" / Byte`——`__rtruediv__` 全库无定义，实测 `'num' / c.Byte` → TypeError。改为 `Renamed("num", Byte)` 直接构造；作用域改为「FocusedSeq / Sequence」（build_sequence_node 实际处理 Renamed，实测 Sequence(Renamed(...)) 通过）。

### 3.8 SequenceDescriptor subconskw「供后续字段引用」

序列内交叉引用实测 NameError（名字仅写入 child_ctx，不进 field_index_map）。改为「以 Renamed 包装，名字写入 child_ctx」。
