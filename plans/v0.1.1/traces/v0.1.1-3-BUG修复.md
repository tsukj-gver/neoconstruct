## 2. 设计偏离点

1. **[权限受阻] README.md 与 SKILL.md 未修改**：任务分派列出二者为可写，但环境
   编辑权限白名单（与 AGENTS.md §2 DEV 可写范围一致）不含根 README.md 与
   `.opencode/skills/**`，Edit 工具被硬拒。DEV 不绕过权限护栏，P4/P9 文档标注的
   **成品草案见 §5**，请 PM 安置（自行应用或授权后重派）。
2. **[设计质疑-轻] RU terminator 改读 `.terminator` 原始属性**（而非通用
   `_expr_params`）：设计 §2.4 建议"接收已编译 ops"，实现中进一步发现 RU 的
   `_expr_params` 在首次 finalize 后被替换为含 `element_field_idx`(int)/
   `index_field_indices`(list) 的注入产物——延迟重编译路径若重读该 dict 会对
   int/list 值误编译（index_field_indices 会在前向引用检查处 TypeError）。
   `.terminator` 从不被 `set_compiled_expr_params` 触碰，读取幂等。行为等价且更稳。
3. **[实现选择] 节点守卫扩展**：设计 §2.1 值守卫为"None/bool/int/float/str/bytes
   跳过"；实现额外跳过 `_FieldDescriptor`/`_ExprRef` 实例与类对象（后者设计 §2.2
   明确"嵌套 StructMixin 不遍历"，前者防 `_FieldDescriptor.default` 用户任意值经
   "default" 槽位误入遍历）。与设计意图一致，属细化非偏离。
4. **[连带订正] PrefixedArray 两处 docstring**：设计 §3.4 清单只列 Prefixed/Rebuild/
   Bitwise 族；PrefixedArray 的"不支持含表达式"声明被本次转绿的测试直接反驳，
   一并订正（ArrayDescriptor L565 与 RepeatUntil L1093 的同类声明**未订正**——
   对应组合无测试锚定，遵循设计"未实测不宣称"原则，留待后续批次）。
5. **[发现-非偏离] Union 运行时 ctx 隔离**：`UnionNode.parse` 走 `Context::new_child`
   （与 FocusedSeq 同的 context nesting），故 Union 内表达式（即使单 Switch）引用
   外层字段在运行时报 `expression field "<index N>" missing in context`。修复前该
   组合编译期即失败，无既有可用行为被破坏（889 全绿佐证）；失败点从编译期移到
   运行期。属 P4 族作用域边界，建议 PM 记 follow-up（Union 语义或文档标注）。
6. **[预存债务-记录] compile.rs 注释失真**：L582-584/L1421/L1751-1757/L1866 等注释
   仍称"Python 侧 _extract_and_compile_exprs 不递归 inner"，修复后不再成立。设计
   §1.4 将 Rust 注释清理列为超范围可选项，本任务按指令仅改两处文案，未动。
   另：`cargo clippy --all-targets -- -D warnings` 有 10 个**预存** lint（test 代码，
   checksum.rs/probe.rs/flags_enum.rs 等，非本次触碰文件）；任务门禁
   `cargo clippy --release` 为 0 warning 通过。建议单独立清理任务。

(b) **新增「已知限制」章节**（建议置于「功能覆盖」之后）：

```markdown
## 已知限制

- **跨层引用**：嵌套 `StructMixin` 子类的类体在 Python 类体作用域求值，无法引用
  外层字段名（报 `NameError`）——construct-rs 不支持跨层字段引用，与原版 construct
  的嵌套 `this` 语义同样隔离。变通：把所需字段提升到同一层，或在外层用
  `Computed(...)` 预计算，或 parse 后在 Python 层做属性运算。
  注意：`field(..., context=...)` 参数当前未实现（保留位），请勿依赖。
- v0.1.1 起 `Switch` / `If` / `IfThenElse` / `Computed` / `Bytes(len)` / `Array(count)`
  等表达式消费者**可嵌套于包装器内**（`Prefixed` / `PrefixedArray` / `Bitwise` /
  `Hex` / `Select` 等），表达式引用同 Struct 前序字段。例外：`Union` 内的表达式
  引用外层字段暂不可用（Union 解析使用隔离 context，属已知边界）。
- 值提供型构造器（`Const` / `Default` / `Rebuild` / `Computed` / `Padding`）作为
  `field()`/`wfield()` 时，v0.1.1 起自动获得隐式 `default=None` + `kw_only=True`
  （实例化不再强制实参；build 由节点层补值）。mypy/pyright strict 下与 `int` 注解
  会有告警，可显式传 `default=` 或注解写 `int | None`。
```

(c) **测试环境变量协议**（建议置于「质量门禁」章节末尾）：

```markdown
### 测试环境变量

parity / system 测试需要两个 Python 解释器，通过环境变量指定：

| 变量 | 指向 | 用途 |
|------|------|------|
| `PC_PYTHON` | 安装了 `construct==2.10.70` 的 venv 的 python.exe | parity 测试的原版参考实现 |
| `CRS_PYTHON` | 安装了 construct-rs 扩展的 venv 的 python.exe | system 测试的 construct-rs 实现 |

未设置时回退 `sys.executable`（仅当该解释器已装对应包时可用）。换机运行测试前
必须设置，否则 system parity 会因找不到原版 construct 而失败（P8 教训）。
```

### 5.2 `.opencode/skills/construct-rs-usage/SKILL.md`

§4.7「嵌套 Struct + 跨层引用」已知限制段（约 L832-834）追加（≤8 行增量）：

```markdown
**已知限制**：`Computed` / `Switch` 的表达式**不能跨层引用子 BitStruct/Struct 字段**。
表达式只能引用同 Struct 内的兄弟字段（siblings）。此外，嵌套 `StructMixin` 子类的
类体也无法引用外层字段名（Python 类体作用域，报 `NameError`）——跨层引用整体
不支持，请在同层预计算（`Computed`）或 parse 后在 Python 层运算。
`field(..., context=...)` 参数当前未实现（保留位），请勿依赖。
```
