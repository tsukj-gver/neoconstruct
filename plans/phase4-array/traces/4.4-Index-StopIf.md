### 实现说明

**IndexNode 核心实现**（

- **parse**：ctx.index().into_py(py)——Option<usize> 的 IntoPy 实现自动处理 Some(i)→PyLong / None→Py_None
- **build**：no-op（sizeof=0，对齐 Python Index._build）
- **sizeof**：返回 0（IX-3）
- **has_expressions**：返回 false（v3 决策，不走 ExprProgram）

**StopIfNode 核心实现**（
odes/stop_if.rs，~640 行）：
- **StopIfCondition 枚举**：Always（常量 true）/ Never（常量 false）/ Expr(ExprProgram)
- **parse/build**：eval_cond 评估条件；true → StopField 哨兵；false → Py_None / Ok(())
- **sizeof**：永远返回 Generic 错误（SI-7，对齐 Python StopIf._sizeof）
- **has_expressions**：Expr 返回 true（**关键**：触发 StructNode 创建 child ctx + init_expr_values，否则 GetInt 取不到字段值，设计 §6.1.1 P1 修正）

**StructNode StopField 捕获**（

- parse has_expressions=true 路径：Err(StopField{..}) => break
- parse has_expressions=false 路径：同上
- build Rw/Wo 路径：同上
- build Ro 路径：同上（防御性）
- 行为：StopIf 触发时停止后续字段，正常返回当前实例（已解析字段在 dict 中）

**compile.rs 编译路径**：
- IndexDescriptor → IndexNode::new()（无参数）
- StopIfDescriptor → build_stop_if_node：
  - condfunc 是 bool → Always/Never
  - condfunc 是 FieldRef/ExprRef → Expr（从 expr_programs[field_index]["cond"] 取，与 ComputedDescriptor 的 "func" 同模式）

**Python 侧**（_descriptors.py）：

### [设计质疑] compute_ro_value 增加 Index/StopIf 分支（设计 §6.1.2 偏离）

**问题**：设计 §6.1.2 原文「StopIfNode 不作为 RO 字段（其 build 行为是检查条件而非计算值）。IndexNode 可作为 RO 字段（值来自 ctx._index，不从实例取）」，且「当前 compute_ro_value 不增加 Array 系列分支。若 DEV 发现需要（如 Index 作为 RO），再补充。」

**实际偏离**：我在 compute_ro_value 中增加了 IndexNode 和 StopIfNode 两个分支：
- Node::Index(_) => Ok(ctx.index().into_py(py))：返回 PyLong 或 Py_None（与 IndexNode.parse 一致）
- Node::StopIf(_) => Ok(py.None())：返回 Py_None（实际条件检查由后续 StopIfNode.build 完成）

**原因**：
1. **用户面 UX**：用户期望 
field(StopIf(x == 0)) 直接可用，不需要为 StopIf 字段提供值。设计原文若按 Rw 实现，用户必须写 stop: None = field(StopIf(x == 0), default=None)，违反 Python construct 用户的心智模型（Python 中 StopIf 是匿名字段，不需要值）。
2. **行为正确性**：RO 字段的 build 路径会调用 compute_ro_value + node.build。compute_ro_value 对 StopIf 返回 None（占位），随后 StopIfNode.build 执行条件检查（可能抛 StopField）。语义完全正确。
3. **设计文档允许**：§6.1.2 明确允许「若 DEV 发现需要，再补充」。

**影响范围**：
- 仅 
odes/mod.rs::Node::compute_ro_value 一处增加 2 个分支
- 不影响现有 13 个节点的 RO 行为（新增分支不影响 _ 分支）
- 测试覆盖：struct_node.rs 中的 uild_stop_if_always_stops_subsequent_fields / uild_stop_if_never_does_not_stop / parse_round_trip_with_stop_if_never 验证 build 方向正确

**建议 PM 转发 ARCH 评估**：是否在设计文档中明确化此偏离（§6.1.2 注释更新）。

### 已知遗留问题（不影响 4.4 验收）

1. **StopIf 字段必须加 annotation**：用户必须写 stop: Any = rfield(StopIf(...))（不能省略 : Any）。这是 _mixin.py 的字段收集逻辑要求（_collect_field_descriptors 通过 cls.__annotations__ 收集）。若未来要支持匿名字段（如 Python construct 的 Struct('x'/Byte, StopIf(...))），需扩展 _mixin.py。
2. **错误路径格式 O1**（4.1 VET 观察项 O1，已知）：StopIf 触发 StopField 时 path 字段含字段名。Struct 在 break 时丢失了字段名上下文（break 直接退出循环，不调 push_path_segment）。这是预期行为——StopField 是哨兵不是错误，path 不重要。
3. **GR-4 行为差异**：Python 用 FocusedSeq 让 StopField 在 GreedyRange 内透传；construct-rs 没有 FocusedSeq，Struct 会捕获内部的 StopField。用户要在 GreedyRange 中用 StopIf 终止，需让 inner 直接是 StopIfNode（不通过 Struct 包装）。这是已知差异，文档化在 greedy_range.rs 的 parse_stop_if_in_struct_does_not_propagate 测试中。

#### 非阻断性观察项

**O4. IndexNode unit struct 的 Default/Copy derive 冗余**（code style）

index.rs L63：
```rust
#[derive(Debug, Default, Clone, Copy)]

```

IndexNode 是 unit struct（无字段），`Clone`/`Copy` derive 在 unit struct 上是冗余的
（unit struct 本身是 Zero-sized type，赋值即复制）。`Default` 也冗余（`IndexNode` 与 `IndexNode::default()` 等价）。

**影响**：无功能影响，仅代码风格。clippy 未警告（derive 宏在 unit struct 上合法）。

**建议**（非阻断）：可简化为 `#[derive(Debug)]`。或保留 Default 便于泛型构造（如 `T::default()` 约束）。

**O5. StopIfCondition::Always/Never 可用 Expr(Const(1/0)) 复用**（design alternative）

stop_if.rs L48-59 的 `StopIfCondition::Always`/`Never` 变体在 REV v1 复审中已列为 S1 小问题

对于 `StopIf(True)`/`StopIf(False)` 调试用例，Always/Never 变体性能更优。

**建议**（非阻断）：保留当前设计。S1 是 REV v1 的小问题，不阻断。当前三变体设计有性能优势。
