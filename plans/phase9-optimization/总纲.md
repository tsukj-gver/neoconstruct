# Phase 9: 性能优化与基准测试

## 阶段目标

对库进行性能优化，建立基准测试体系，与 Python 版本进行性能对比，确保 Rust 版本有显著性能提升。

## 前置依赖

- Phase 1-8 完成

## 子任务清单

### 9.1 基准测试框架搭建

- [ ] 使用 `criterion` crate 建立基准测试
- [ ] 为核心构造器编写基准：
  - 原子构造器：Bytes, FormatField, VarInt
  - 复合构造器：Struct, Array
  - 适配器：Enum, If, Switch
  - 流操作：Bitwise, Pointer, Compressed
- [ ] 为 gallery 格式编写基准：ELF, PE/COFF
- [ ] 建立基准数据集（不同大小的二进制数据）
- [ ] 验证：基准测试可运行，输出可复现

### 9.2 零拷贝优化

- [ ] 分析当前实现中的数据拷贝热点
- [ ] 对 `Value::Bytes` 使用 `Cow<[u8]>` 或 `&[u8]` 切片
- [ ] 对只读场景（parse）尽量使用引用而非 `Vec<u8>` 克隆
- [ ] 对 `Struct` / `Sequence` 解析结果避免不必要的容器构建
- [ ] 验证：优化后基准测试有改善

### 9.3 trait 对象优化

- [ ] 分析 `Box<dyn Construct>` 的虚函数调用开销
- [ ] 对热点路径考虑使用泛型单态化替代 trait 对象
- [ ] 评估 `enum_dispatch` 或类似方案的可能性
- [ ] 对 `Struct` 的字段列表考虑使用数组而非 `Vec`
- [ ] 验证：热路径性能提升

### 9.4 内存分配优化

- [ ] 分析 `Value` 和 `Container` 的内存分配模式
- [ ] 考虑使用 `Vec::with_capacity` 预分配
- [ ] 考虑使用 `SmallVec` 或 `TinyVec` 替代 `Vec`（小数据场景）
- [ ] 对 `Context` 使用 `FxHashMap` 或 `AHashMap` 替代 `BTreeMap`
- [ ] 验证：内存分配次数减少

### 9.5 编译优化（高级，可选）

- [ ] 设计编译期优化方案（对应 Python 版本的 `compile()` 方法）
- [ ] 评估使用 Rust 宏实现声明式 DSL 的可行性
- [ ] 评估使用 `proc-macro` 生成特化代码的可行性
- [ ] 实现简单的编译优化原型
- [ ] 验证：编译优化版本性能提升

### 9.6 与 Python 版本性能对比

- [ ] 在相同数据集上运行 Python 版本基准测试
- [ ] 对比 Rust 版本和 Python 版本的性能
- [ ] 生成性能对比报告
- [ ] 目标：Rust 版本解析速度至少是 Python 版本的 10x
- [ ] 验证：性能对比报告完整

### 9.7 最终质量检查

- [ ] `cargo clippy` 零 warning
- [ ] `cargo fmt --check` 通过
- [ ] `cargo test` 全部通过
- [ ] `cargo bench` 基准结果合理
- [ ] 文档注释覆盖所有 pub 项
- [ ] `cargo doc` 生成的文档完整可用
- [ ] 验证：所有质量检查通过

## 阶段出口标准 (Exit Criteria)

1. **基准测试完整**：覆盖所有主要构造器和 gallery 格式
2. **性能达标**：Rust 版本解析速度至少是 Python 版本的 10x
3. **内存合理**：无内存泄漏，无过多分配
4. **代码质量**：clippy/fmt/test 全部通过
5. **文档完整**：`cargo doc` 生成的文档覆盖所有公开 API

## 预估工期

~1 周

## 风险与注意事项

- 过早优化可能浪费时间，需基于基准测试数据驱动
- 零拷贝优化可能增加 API 复杂度（生命周期参数）
- trait 对象 → 泛型的重构可能影响 API 兼容性
- 编译优化是高级功能，可酌情延后
