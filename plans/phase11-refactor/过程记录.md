### 偏离设计文档的地方

1. **添加 `Dynamic(Box<dyn Construct>)` variant（第 71 个 variant）**：设计文档列出 70 个 variant（含 cfg-gated Compressed），实际添加了 `Dynamic(Box<dyn Construct>)` 作为逃生舱。原因：测试中的 mock 类型（`StopConstruct`、`IndexCapture`、`StopAfter`、`U16Big` 等）不在 CombinedConstruct 枚举中，无法 `.into()` 转换。`Dynamic` variant 通过 `dynamic()` 辅助函数包装任意 `impl Construct` 类型，保持测试可用性。该 variant 使用动态分发，仅用于非枚举类型，不影响常见路径的零开销特性。

2. **`Select` 字段类型改为 `Vec<CombinedConstruct>`（非 `Vec<Box<CombinedConstruct>>`）**：设计文档未明确，但 `Vec<CombinedConstruct>` 更自然（CombinedConstruct 本身已是枚举，无需额外 Box）。`push()` 方法使用 `impl Into<CombinedConstruct>`。

3. **`impl Construct for Box<dyn Construct>` 转发实现**：设计文档未提及，但 `Dynamic` variant 需要 Box<dyn Construct> 的 Construct 实现来转发方法调用。

   确保每次嵌套在堆上分配，无栈溢出风险。

#### 设计偏离评估

**偏离 1：Dynamic(Box<dyn Construct>) 第 71 个 variant**

- **设计文档立场**：§6.6 明确写"Phase 11 不实现"，§5.4 建议测试改用内置构造器替代 mock
- **DEV 实际做法**：添加 Dynamic variant + `dynamic()` 辅助函数 + `impl Construct for Box<dyn Construct>` 转发
- **严重程度**：重要（非阻塞）
- **评估**：
  - 技术合理性：**充分**。设计 §5.4 建议的"用内置构造器替代 mock"会导致无法测试 error-propagation
    路径（如 FailingConstruct 的 always-fails 行为无法用内置构造器模拟）。Dynamic variant 是必要的。
  - 性能影响：**可忽略**。Dynamic variant 仅在 match 到该 arm 时发生一次虚分发（Box<dyn>），
    不影响其他 70 个 variant 的静态分发。enum_dispatch 的 match 分发仍然存在，编译器可对前 70 个
    arm 做内联优化。
  - 范围控制：**合理**。grep 确认 `dynamic()` 仅在 18 处测试代码中使用（core/mod.rs, focused_seq.rs,
    repetition.rs, stream_ops.rs, struct_.rs, sequence.rs），无生产代码使用。
  - **建议**：ARCH 应追认此偏离为设计修正（本质上是将 §6.6 的 escape-hatch 从 Phase 12+ 提前到
    Phase 11），更新设计文档 §6.6 为"已在 Phase 11 实现"。

**偏离 2：Select 用 Vec<CombinedConstruct> 而非 Vec<Box<CombinedConstruct>>**

- **设计文档立场**：§2.3 表格标注为 `Vec<Box<CombinedConstruct>>`，但 DEV 改为 `Vec<CombinedConstruct>`
- **严重程度**：建议（非阻塞）
- **评估**：**合理且更优**。CombinedConstruct 本身已是枚举（~80 字节），无需额外 Box 间接。
  `Vec<CombinedConstruct>` 直接内联，内存布局更紧凑（连续存储），缓存友好性更好。
  `push()` 使用 `impl Into<CombinedConstruct>` 接口灵活。建议设计文档追认。

**偏离 3：impl Construct for Box<dyn Construct> 转发实现**

- **设计文档立场**：未提及
- **严重程度**：建议（非阻塞）
- **评估**：**必要且正确**。Dynamic variant 的存在要求 `Box<dyn Construct>: Construct`。
  `(**self).parse(stream, ctx)` 转发模式标准且正确。

**偏离 4：CombinedConstruct 缺少 #[derive(Debug)]**

- **设计文档立场**：§2.2 展示了 `#[derive(Debug)]`
- **严重程度**：建议（非阻塞）
- **评估**：**不可避免**。Renamed 结构体含 `parsed: Option<ParsedHook>` 字段，其中
  `ParsedHook = Box<dyn Fn(&Value, &Context) + Send + Sync>` 不实现 Debug。因此 CombinedConstruct
  无法 derive Debug。设计文档的 Debug derive 是理想化描述，实际无法实现。CombinedExpr 和
  CombinedStream 正确 derive 了 Debug（其 variant 类型均实现 Debug）。
