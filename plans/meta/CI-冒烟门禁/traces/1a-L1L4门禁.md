### 2. 必查项逐项结论（6 项）

#### 2.1 PowerShell 5.1 兼容性 — ✅ 通过（含 1 个 UX 观察项 OBS-1）

**核查方法**：
- 用 `[System.Management.Automation.Language.Parser]::ParseInput` 对 3 个 .ps1 做 tokenize，**3/3 解析零错误**
- BOM 检测：3 个 .ps1 文件首 3 字节均为 `EF BB BF`（UTF-8 BOM），`.py` 文件首 3 字节 `22 22 22`（无 BOM，正确）
- param block 语法：4 个 `param(` 块均使用换行分隔参数（不使用尾逗号），符合 PS 5.1 解析要求
- `$args` 冲突规避：4 个脚本均未定义 `$args` 参数（避免与 PS 自动变量冲突）
- splatting 区分：`run_smoke.ps1::Invoke-L1Gate` L75 注释明确区分 "hashtable splatting 才是命名参数"，使用 `@l1Args`（hashtable）✓

**OBS-1（UX 观察项，非阻断）**：`run_smoke.ps1 -Level L1,L4`（**未加引号**）在 PS 5.1 下被解析为 `$Level=@("L1","L4")`，经 `[string]` 强制转换后变成 `"L1 L4"`（空格连接），导致 `Resolve-Levels` 报 "Unsupported level: L1 L4" 并 `exit 2`。

- 根因：PowerShell 5.1 native comma 是数组操作符；`[string]` 参数接收 array 时按空格连接
- 4 种调用形态实测：

| 调用形态 | 结果 | 退出码 |
|---------|------|-------|
| `-Level All` | ✅ PASS（L1+L4 全过） | 0 |
| `-Level L1`（单层） | ✅ PASS | 0 |
| `-Level L4`（单层） | ✅ PASS | 0 |
| `-Level 'L1,L4'`（**加引号**） | ✅ PASS（L1+L4 全过） | 0 |
| `-Level L1,L4`（**未加引号**） | ❌ FAIL（"Unsupported level: L1 L4"） | 2 |

- 修复建议：`param([string[]]$Level)` 接收数组后内部 `-join ','；或在 README 中明确要求多 level 必须加引号。属 META-CI-1d 文档批次处理范围。
- 影响评估：**不阻断 1a 验收**。常用形态 `-Level All` / `-Level L1` / `-Level L4` 全部 PASS。`-Mode quick` 在设计 §A.1 中是 single-value，未出现该问题；DEV 改为 `-Level` 后才暴露此 PS 5.1 native 行为。
