## 项目定位

用 Rust 重写 Python construct 库的内核，使其更快。交付物是 Python 包。

**核心原则**：
- pyo3 是核心依赖，不是可选附加
- 编译、parse、build 各只有一次 FFI 边界穿越
- Rust 内部直接操作 CPython C API，无中间表示层（parse 直接产 PyObject，build 直接读 PyObject）
- API 风格：mashumaro 式 dataclass mixin（非 pydantic BaseModel）
- 性能目标：≥4x vs Python construct 2.10.70（10x 为理想目标）

## 核心设计决策（Phase 2，8 项）

1. **废弃 `this`，用编译期字段引用**：`Bytes(count)` 而非 `Bytes(this.count)`
2. **表达式编译为 Rust 栈式 VM**：零 FFI 求值
3. **不提供 `len_()`**：用 `Tell()` + `Computed()` 替代
4. **嵌套跨层引用用显式 `context=`**：不用魔法 `this._._`
5. **三种 field 函数 RW/RO/WO**：数学完备分类，用户一眼可知字段角色
6. **default 自动 kw_only**：`field(subcon, default=value)` 解决字段顺序冲突
7. **`Default` 构造器不再需要**：field 层管用户语义，构造器层管字节语义
8. **字节顺序 vs init 顺序解耦**：声明顺序=字节布局，init 顺序=按性质重排

详见 `docs/模块设计-表达式系统.md`

## 已知技术债务

1. **Bytes build 不校验长度**：设计 §4.7 规定不校验，但 Python construct 实际校验（SF-1 待定）
2. **sizeof Expr 返回 Generic**：无 SizeofError 变体，跟随 greedy_bytes 先例
3. **MAX_INLINE_FIELDS=16 无编译期检查**：VET SF-1，超过 16 字段静默截断
4. **take_fields / force_setattr 保留但 parse 不再调用**：R4 后为 dead path
