## 项目定位

用 Rust 重写 Python construct 库的内核，使其更快。交付物是 Python 包。

**核心原则**（详见 `MEMORY.md` + `AGENTS.md §0`）：
- pyo3 是核心依赖，不是可选附加
- 编译、parse、build 各只有一次 FFI 边界穿越
- Rust 内部直接操作 CPython C API，无中间表示层
- API 风格：mashumaro 式 dataclass mixin
- 性能目标：≥4x vs Python construct 2.10.70（10x 为理想目标）

## 核心设计决策

详见 `docs/decisions/README.md`（ADR-001 ~ ADR-018，按 Phase 分类）。

历史决策一览（已迁移到 ADR）：

1. **废弃 `this`**（ADR-001）：编译期字段引用
2. **表达式编译为 Rust 栈式 VM**（ADR-006）：零 FFI 求值
3. **不提供 `len_`**（ADR-002）：用 `Tell()` + `Computed()` 替代
4. **嵌套跨层引用用显式 `context=`**（ADR-003）
5. **三种 field 函数 RW/RO/WO**（ADR-004）
6. **default 自动 kw_only**（ADR-005）
7. **parse 借用实例 `__dict__`**（ADR-008）：消除中间 dict
8. **Context Vec 化**（ADR-007）：GetInt 数组索引

## 已知技术债务

1. **Bytes build 不校验长度**：设计 §4.7 规定不校验，但 Python construct 实际校验（SF-1 待定）
2. **sizeof Expr 返回 Generic**：无 SizeofError 变体，跟随 greedy_bytes 先例
3. **MAX_INLINE_FIELDS=16 无编译期检查**：VET SF-1，超过 16 字段静默截断
4. **take_fields / force_setattr 保留但 parse 不再调用**：R4 后为 dead path
