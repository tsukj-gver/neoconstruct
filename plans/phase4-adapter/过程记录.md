### 具体问题

#### 问题 1：[中等级] TimestampAdapter 负时间戳处理不正确

- **文件**: `computed.rs` 第 886–891 行 (`integer_to_secs_nanos`)
- **描述**: Rust 的 `%` 运算符是"取余"（向零截断），Python 的 `%` 是"取模"（向下取整）。对于负时间戳（如 epoch 前的时间），非 Seconds 精度的 nanos 计算结果不正确。
  - 例：`-1500ms` 在 Python 中为 `(-2s, 500_000_000ns)`（正确：-2 + 0.5 = -1.5s = -1500ms）
  - 例：`-1500ms` 在当前 Rust 中为 `(-1s, <错误的nanos>)`（不正确）
- **影响范围**: 仅影响 Unix epoch 之前的负时间戳 + 非秒级精度。当前所有测试使用正时间戳，未暴露此问题。
- **建议修复**: 使用 `div_rem` 风格的正确向下取整除法（或 `num_integer::div_floor`），确保 nanos 始终为非负数。
- **是否阻塞**: **不阻塞**。TimestampAdapter 已文档标注为"简化实现"（Custom epoch 也未实现），且正时间戳路径完全正确。可作为后续优化任务。

#### 问题 2：[低等级] TimestampEpoch::Custom 未实现实际偏移计算

- **文件**: `computed.rs` 第 822–828 行
- **描述**: `epoch_seconds()` 对 Unix 和 Custom 变体均返回 0，`_offset` 变量在 `integer_to_secs_nanos` 中计算但未使用。Custom epoch 的 year 字段被存储但无实际效果。
- **建议**: 已文档说明为简化实现，可接受。后续阶段可引入 `chrono`/`time` crate 实现完整版本。
- **是否阻塞**: **不阻塞**。
