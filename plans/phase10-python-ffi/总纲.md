# Phase 10: Python FFI 封装 (PyO3)

## 阶段目标

将 Rust construct-rs 核心通过 PyO3 封装为 Python 可调用库，使 Python 用户能以与原版 construct 库一致的接口进行声明式二进制解析与构建。

**验收标准**：通过 construct 原版测试套件（`construct/tests/`），验收报告逐用例标注 pass/skip 及理由。

## 前置依赖

- Phase 1-9 全部完成（Rust 核心已验收）

## 已确认的设计决策

| 决策 | 方案 | 理由 |
|------|------|------|
| Crate 结构 | 独立 `construct-py/` workspace member | 保持 Rust core 纯净，PyO3 不污染核心 |
| 构建工具 | maturin + PyO3 0.22+ | 行业标准，支持 wheel 构建 |
| Python 导入名 | `construct_rust`（测试用 conftest.py 注入 `sys.modules['construct']`） | 与原版可共存，测试无侵入 |
| `compile()` | 抛 `NotImplementedError` | `common()` 已有 try/except 容错，自动跳过 |
| Deprecated gallery | 不纳入 Phase 10 | 23 个已废弃格式解析器，不在核心维护范围 |
| `construct.lib` 子模块 | 实现测试必需部分 | Container/ListContainer 用 PyO3；binary/py3compat/hex/bitstream 用纯 Python |
| 表达式桥接 | `PyClosure<T>` 包装 Python callable | Python 表达式 → Rust 闭包 → Evaluate trait |
| Container 实现 | 纯 Python（继承 dict） | `__dict__ = self` trick 和 method shadowing 是 Python 专属机制，PyO3 无法合理复刻；纯 Python 逐行移植零行为差异（ARCH 修正，PM 批准 2026-06-15） |
| Python 子类化支持 | 混合架构：纯 Python 基类 + PyConstructAdapter 桥接 | Adapter/Validator 提供为纯 Python 类供用户继承；嵌套在 Rust Struct 中时通过 PyConstructAdapter 回调 Python |

### 所有构造器包装的公共 API 契约

每个 `#[pyclass]` 构造器包装必须暴露以下 7 个方法：

| 方法 | 签名 | 说明 |
|------|------|------|
| `parse(data, **contextkw)` | `bytes → Value` | 解析字节，contextkw 注入为顶层 Context 初始条目 |
| `parse_stream(stream, **contextkw)` | `file-like → Value` | 从 Python 流解析，需 PyStream 桥接 |
| `parse_file(filename, **contextkw)` | `str → Value` | 打开文件（`'rb'`）后解析 |
| `build(obj, **contextkw)` | `Value → bytes` | 构建字节，contextkw 注入为顶层 Context |
| `build_stream(obj, stream, **contextkw)` | `Value → None` | 构建到 Python 流 |
| `build_file(obj, filename, **contextkw)` | `Value → None` | 打开文件（`'w+b'`，RawCopy 回读需要）后构建 |
| `sizeof(**contextkw)` | `→ int` 或抛 `SizeofError` | 计算大小 |

关键机制：

- **`**contextkw` → 初始上下文条目**：所有三个方法（parse/build/sizeof）接受 keyword 参数，注入为 Context 顶层条目（如 `parse(data, x=1)` → `context["x"] = 1`）。`common()` 依赖此机制（`common(fmt, data, obj, size, **kw)` 透传 kw）。
- **`SizeofError` 硬性导出**：`declarativeunittest.py:23` 用 `SizeofError` 作为 `common()` 默认参数值（导入时求值）。若未导出，所有测试文件 import 失败。这是最关键的单一导出名。
- **`CancelParsing` 异常处理**：`parse_stream` 包装层需捕获 Python 回调（parsed hook）抛出的 `CancelParsing` 并优雅退出（对应 `core.py:416-419`）。
- **Python 流桥接**（`PyStream`）：`parse_stream`/`build_stream` 接受 Python file-like 对象（BytesIO 等），包装为 Rust `Stream` trait 实现，回调 Python 的 `read`/`write`/`seek`/`tell`。
- **`build_file` 以 `'w+b'` 模式打开**：不是 `'wb'`，因为 `RawCopy` 需要回读刚写入的数据（issue #888）。

### 10.7 适配器 + 控制流 Python 包装层

#### 混合架构：Python 子类化支持

目标：支持 Python 用户继承 `Adapter`/`Validator` 创建自定义构造器（如 `class IpAddressAdapter(Adapter)`），并嵌套在 Rust Struct 中使用。

架构：

1. **纯 Python 基类**：`Adapter`/`SymmetricAdapter`/`Validator`/`Subconstruct` 作为纯 Python 类提供，包装 Rust subcon，在 Python 侧执行 `_decode`/`_encode`/`_validate`
2. **`PyConstructAdapter` 桥接器**：将任意 Python 构造器对象包装为 Rust `Construct` trait 实现，通过 GIL 回调 Python 的 `parse`/`build`/`sizeof`
3. **混合分发**：从 Python 创建 `Struct`/`Sequence` 时，检查每个 subcon：
   - Rust PyO3 对象 → 直接使用 `Box<dyn Construct>`
   - 纯 Python 对象 → 包装为 `PyConstructAdapter`

性能影响：仅用户自定义的 Python 构造器回调 Python，库内建构造器全速运行在 Rust 中。

对应测试：`test_ipaddress_adapter_issue_95`、`test_from_issue_244`

## 风险与注意事项

- **Container dict 子类模拟**：PyO3 中实现 dict 子类（`__dict__ = self` trick）的属性-下标等价性是最大技术风险点
- **SizeofError 导入时依赖**：`declarativeunittest.py:23` 用 `SizeofError` 作为默认参数值（导入时求值），未导出会导致所有测试 import 失败
- **表达式桥接性能**：每次表达式求值需要 Rust Context → Python Container 转换 + GIL 获取，可能影响解析性能。Phase 10 优先正确性，性能优化 post-project
- **运算符重载顺序**：`"name" / Byte` 依赖 Python 的 `__rtruediv__` fallback 机制，需确保 PyO3 wrapper 正确触发反射运算符
- **`common()` 的 compile 路径**：`format.compile()` 抛异常会被 `common()` 的 try/except 捕获，自动跳过编译测试。但 `test_compiler.py` 中 2 个专门测试会失败，需标记 skip
- **xfail 用例**：原版 15 个 `@xfail` 用例保留标记。如果我们的实现意外通过（XPASS），pytest 默认报告但不失败
- **GIL 阻塞**：长时间 Rust 解析（如大文件）持有 GIL 会阻塞 Python 线程。可考虑 `allow_threads` 释放 GIL，但需确保不回调 Python 表达式时才安全
- **混合架构性能**：`PyConstructAdapter` 每次解析需要 GIL 获取 + Context 转换 + Python 调用 + 结果转换。用户自定义构造器的嵌套层级影响性能
- **压缩编码覆盖不全**：Rust 仅支持 zlib/deflate，gzip/bzip2/lzma/lz4 测试用例跳过
