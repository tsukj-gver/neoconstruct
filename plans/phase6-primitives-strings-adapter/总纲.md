## 目标

1. **Primitives 收尾**（17 个未实现）：Byte/Short/Int/Long 别名 + Float 系列 + Int24 系列 + VarInt/ZigZag + BytesInteger + Float16

## PM 决策（基于 ARCH 三合一分析报告，2026-07-29）

### 决策 1：Strings 实现路线 = 方案 A（独立 Node）

- **方案 A**（接受）：6 个 String 构造器实现为独立 Node，直接处理 byte↔str 编解码，不照搬 Python macro 嵌套（PascalString→Prefixed / PaddedString→FixedSized）
- **理由**：Phase 6 自洽（避免跨 Phase 依赖 Prefixed/FixedSized）；符合 §0（一次 FFI，无中间表示层）
- **代价**：6 个 Node 各自实现编解码逻辑（少量重复），但远低于跨 Phase 耦合的成本

### 决策 2：Adapter 双层分离 = 两种独立构造器（用户强化，2026-07-29）

用户在 ARCH 分析报告后补充两点关键约束，PM 接受并强化决策：

**约束 1（类型层面分离）**：内置 Adapter 和用户面 Adapter **从类型上就是两种不同的 Rust 构造器**，不是一个类型内部两条路径。各自独立的 Node 变体（或 Python 类），不共享内部实现。

**约束 2（用户面 Adapter 在 Python 层）**：用户面 Adapter（通用 Adapter / SymmetricAdapter 基类）**基本在 Python 层实现**——用户继承写 parse/build Python 方法，Rust 层不专门做 Node 变体（最多提供最小通用钩子）。Rust 不背"通用用户回调"的包袱。

**双层分工**：
- **内置 Adapter**（Rebuild / RawCopy / Peek 等有明确语义的）= **Rust Node 变体**（零 FFI，编译期处理，高性能）
- **用户面 Adapter**（通用 Adapter / SymmetricAdapter）= **Python 层构造器**（用户主动选择慢路径，与 Phase 4 删 RepeatUntil PyCallable 兜底同一脉络）

**§0 合规**：内置 Adapter 零 FFI（符合一次 FFI）；用户面 Adapter 在 Python 层（不跨 FFI 边界，不引入中间表示层）。用户主动选 Adapter = 显式接受性能折衷（Phase 4 用户面设计原则 #2）。

**对 6.3 工作量的影响**：6.3 Rust 工作主要在"内置 Adapter 那几个有明确语义的"（Subconstruct/RawCopy/Peek/Rebuild）；用户面 Adapter 基本不在 Rust 层做（Python 层类定义）。Pass 也归 6.3。

### 决策 3：Pass 调入 Phase 6.3

- **接受**：Pass（no-op 构造器，< 100 行 Rust）调入 6.3 Adapter 核心子任务
- **理由**：Phase 7 If/Switch 默认值依赖 Pass；调入避免 Phase 7 启动阻塞；实现成本极低

### 决策 4：测试目录结构 = tests/{unit,parity,integration,errors}/ + bench/ 平级

- **接受**：按测试类型分类（业界标准），不按 phase 分
- **理由**：测试独立于 phase 演进；类型分类有利于 CI 选择性运行（如只跑 parity）
- **公共组件**：conftest.py 扩展 + _helpers/{parity.py, normalize.py, fixtures.py} + bench/_helpers/runner.py

### 决策 5：Benchmark 框架 = 自建轻量

- **接受**：基于 E01_O1_ab_stats.py 经验自建，不引入 pytest-benchmark
- **理由**：项目需要 Controlled A/B Test（L-09 教训）+ 跨进程隔离，pytest-benchmark 不匹配；已有经验可复用
