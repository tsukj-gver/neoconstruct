## 1. utf16/32 raw FFI SAFETY 评估（任务重点 1）

### 1.1 `decode_utf16_32_raw`（encoding.rs L295-371）

| 检查项 | 结论 | 证据 |
|--------|------|------|
| **P2a byteorder 语义** | ✅ 正确 | L302-307：`Utf16Le/Utf32Le => -1`、`Utf16Be/Utf32Be => 1`（强制序，不扫描 BOM）。**不是** v1 错误值 `0`（自动检测 BOM）。 |
| **P2a 验证 case** | ✅ 覆盖 | encoding.rs L833 `p2a_decode_utf16_le_does_not_consume_bom`：`b"\xff\xfeh\x00"` 解码为 `[U+FEFF, 'h']`（BOM 字节作为数据保留），与 Python `bytes.decode("utf_16_le")` 一致。greedy_string.rs L253 `parse_utf16_le_does_not_consume_bom` Node 级再验证。 |
| **SAFETY 前置条件** | ✅ 完整 | L282-294 函数级 doc + L316-321 unsafe 块内注释，5 项逐条列出：①GIL 持有 ②`bytes.as_ptr()` 有效 ③`bytes.len()` 字节数 + 尾部不完整单元由 CPython 拒绝 ④`&byteorder` 栈上指针（CPython 内部 cast away const 修改后不读） ⑤返回值所有权转移 + NULL 走 BC6 |
| **BC6 回退** | ✅ 完整 | L338-350：`ptr.is_null()` → `PyErr::fetch(py)` → `ConstructError::String`。无引用泄漏（NULL 时 CPython 已设 PyErr，fetch 取回并清除）。 |
| **所有权转移** | ✅ 正确 | L353-359：非 NULL 时 `Bound::<PyAny>::from_owned_ptr(py, ptr)` 消费指针（不 incref），与 ADR-019 U4 模式一致。 |
| **downcast 安全** | ✅ 防御性 | L361-369：`obj.downcast_into::<PyString>()` 失败时返回 `ConstructError::String`（理论上 PyUnicode_DecodeUTF16/32 必返回 str，但保留防御）。 |

**与 ADR-019 SAFETY 严谨度对照**：ADR-019 表格（L130-135）列出 U1-U4 unsafe API 的「安全前置 / 失败模式 / BC6 回退」三栏。本函数 SAFETY 注释同等严谨——每条 unsafe API（PyUnicode_DecodeUTF16/32 + Bound::from_owned_ptr）均覆盖三栏。

### 1.2 `encode_utf16_32_raw`（encoding.rs L397-481）

| 检查项 | 结论 | 证据 |
|--------|------|------|
| **P1 直接持 `&Bound<PyString>`** | ✅ 合规 | 签名 L397-402 `obj: &Bound<'py, PyString>`，**不**经 `Cow<str>`。encode() L246-258 入口已 downcast 后传 `&Bound<PyString>`。§0 #2 合规。 |
| **BOM 剥离算法** | ✅ 正确 | L450-463：CPython `AsUTF16/32String` 输出 = unit 字节 BOM + payload。本函数剥离前 `unit` 字节。极端边界（空字符串 → all_bytes.len()==unit 仅 BOM）有显式校验 L453-462（< unit 时返回 String error，理论上不可达但保留防御）。 |
| **byte-swap 算法** | ✅ 正确 | L467-471：`cfg!(target_endian)` 编译期常量，分支编译期消除。LE 平台 + Utf16Be/Utf32Be → swap；BE 平台 + Utf16Le/Utf32Le → swap；其他 → 直接拷贝。 |
| **swap 实现** | ✅ 正确 | L472-477：`chunks_mut(unit)` + `chunk.reverse()`。验证 case：`encode_utf16_be_byte_swap`（L876）LE 平台 `"h"` → `b'\x00h'`。 |
| **SAFETY 前置条件** | ✅ 完整 | L391-396 函数级 doc + L412-415 unsafe 块内注释：①GIL ②`obj.as_ptr()` 是有效 PyUnicode（downcast 后） ③非 NULL 所有权转移 / NULL 走 BC6。 |
| **BC6 回退** | ✅ 完整 | L422-432：NULL → `PyErr::fetch` → `ConstructError::String`。 |
| **PyBytes downcast 防御** | ✅ | L434-449：`downcast_into::<PyBytes>()` 失败返回 String error。 |

### 1.3 潜在改进点（非阻断）

| # | 位置 | 问题 | 建议 | 严重度 |
|---|------|------|------|--------|
| SAFETY-1 | encode L472-477 | byte-swap 依赖 CPython 契约「payload.len() % unit == 0」，无显式校验。若 CPython 未来版本行为变更（虽极不可能），`chunks_mut` 最后一个不完整 chunk 会被 reverse 损坏数据。 | 增加 `debug_assert!(payload.len() % unit == 0, "CPython AsUTF16/32String contract violated");` 作为运行时契约校验（debug 构建触发，release 零成本）。 | 低（CPython 契约稳定 30+ 年） |
| SAFETY-2 | encoding.rs L313, L470 | 两处 `unreachable!()` 无消息（`_ => unreachable!()`），上下文较弱。 | 改为 `unreachable!("encoding_name match only for utf16/32 variants")` 与 L306/L409 风格一致。 | 极低（代码风格） |

**SAFETY 总评**：utf16/32 raw FFI 的 SAFETY 论证**与 ADR-019 同等严谨**，前置条件 / 失败模式 / BC6 回退三栏完整覆盖。**首次正常路径 unsafe（区别于 ADR-019 的错误路径）的 SAFETY 规范成立**，可作为后续 Phase raw FFI 决策的参考。

**偏离合理性**：3 个偏离均持有 `Box<Node>`。审查既有 `Box<Node>` 节点：
- `BitwiseNode`（bitwise.rs L64）：`#[derive(Debug)]`

- `TransformNode`（transform.rs L132）：`#[derive(Debug)]`
