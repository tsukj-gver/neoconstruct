## 4. 偏离设计文档的地方

### 4.1 Adapter 类型识别策略（小幅偏离，更鲁棒）

**设计 §6.3**：compile.rs 通过 `type_name == "AdapterDescriptor"` 识别用户面 Adapter。

**实施**：双重视别策略：
1. `type_name == "AdapterDescriptor"`（直接匹配，设计原始方案）
2. **duck typing**：新增 `is_adapter_like(desc)` 函数，检查 desc 同时拥有可调用的 `_decode` 和 `_encode` 方法

**原因**：用户继承 `Adapter` 子类（如 `class HexAdapter(Adapter)`）的实例的 type name 是 `"HexAdapter"` 而非 `"AdapterDescriptor"`。若严格按设计，用户必须在子类中手动设置 `__class__.__name__ = "AdapterDescriptor"`（不优雅）。duck typing 让任意 Adapter 子类自动识别，更符合 Python 习惯。

**风险评估**：duck typing 仅检查属性存在 + callable，不会误判：
- StructMixin 子类（同时有 `_construct_compiled`）已在前面分支返回
- FormatFieldDescriptor / BytesDescriptor 等无 `_decode` / `_encode`，不会误判
- 防御性足够

**[设计质疑]**：建议 ARCH 在后续 ADR-022 中确认此 duck typing 策略，或显式要求用户继承 `AdapterDescriptor`。

### 4.2 Adapter 单独 parse/build 限制（已知限制，文档化）

**设计 §4.1**：`adapter.parse(b"...")` / `adapter.build(value)` 顶层入口。

**实施**：仅当 subcon 自身有 `.parse` / `.build` 方法时工作（如嵌套 Adapter 或 StructMixin 子类）。原子描述符（如 Int8ub）无 `.parse` 方法。

**原因**：construct-rs 的描述符（如 Int8ub）是无状态的"编译期标记"，与 Python construct 的 Construct 对象不同。Adapter 单独使用时无法直接调用 Int8ub.parse。

**用户面 API 建议**：嵌入 Struct 使用（设计 §4.2 主要场景）。
```
@dataclass
class P(StructMixin):
    v: str = field(HexAdapter(Int8ub))  # 推荐
```

错误信息已优化为引导用户使用 Struct 嵌入方式。

**[设计质疑]**：Phase 7+ 可考虑在 `Adapter.parse` 中自动包装 subcon 为匿名 Struct，恢复 Python construct 兼容性。

### 4.3 Rebuild int 常量表达式不支持

**设计 §1.4**：`func` 必须是 Phase 2 表达式（FieldRef/ExprRef/int 组合）。

**实施**：仅 FieldRef/ExprRef 路径工作。int 常量因 Python 侧 `_extract_and_compile_exprs` 不编译 int 常量（与 Computed 同行为），导致 Rust 侧 expr_programs 为 None，编译失败。

**用户面影响**：`rfield(Rebuild(Int8ub, 5))` 失败（常量场景无意义，应用 Const 替代）。`rfield(Rebuild(Int8ub, items_count))` 工作（设计 §1.4 主用例）。

**一致性**：与现有 Computed 行为一致（`Computed(42)` 也会失败，需 `Computed(items_count * 2)`）。

**结论**：与设计主用例一致（Rebuild 引用前序字段），int 常量场景无意义。不算偏离，仅文档化。
