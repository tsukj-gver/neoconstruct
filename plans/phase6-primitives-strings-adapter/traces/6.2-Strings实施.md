## 2. utf16/32 raw FFI SAFETY 注释确认

按设计 §2.2.2 + ADR-019（错误路径先例）+ ADR-021（编号已分配，首次正常路径 unsafe raw FFI）规范，
`encoding.rs` 的两个 unsafe 函数均附完整 SAFETY 注释：

### `decode_utf16_32_raw`（encoding.rs）

**byteorder 语义（P2a 修正）**：
- LE → `byteorder = -1`（强制 LE，**不扫描 BOM**）
- BE → `byteorder = +1`（强制 BE，**不扫描 BOM**）

验证 case：`p2a_decode_utf16_le_does_not_consume_bom`（数据流开头 `\xff\xfe` 作为 U+FEFF 字符保留，不被误判为 BOM 消费）

**SAFETY 前置条件**（注释中逐项列出）：
1. GIL 持有（py token）
2. `bytes.as_ptr()` 有效（&[u8] 切片）
3. `bytes.len()` 字节数（CPython 按 unit 分组，尾部不完整设 PyErr）
4. `&byteorder` 栈上指针（CPython 内部 cast away const 修改后不再读）
5. NULL → PyErr::fetch → ConstructError::String（BC6 回退）

### `encode_utf16_32_raw`（encoding.rs）

**BOM 剥离 + byte-swap 算法**（P1 修正）：
- CPython `PyUnicode_AsUTF16String`/`AsUTF32String` 输出**本机序 + BOM 前缀**
- 本函数：剥离前 unit 字节 BOM + 若目标序 ≠ 本机序按 unit 分组 swap
- `cfg!(target_endian)` 编译期常量，分支编译期消除

验证 case：
- `encode_utf16_le_strips_bom`：本机 LE 平台 "h" → `b'h\x00'`（无 BOM）
- `encode_utf16_be_byte_swap`：本机 LE 平台 "h" → `b'\x00h'`（swap 后无 BOM）
- `encode_utf32_le_strips_bom` / `encode_decode_utf32_be_round_trip`

**SAFETY 前置条件**：GIL / obj.as_ptr() 有效 PyUnicode / NULL → PyErr::fetch / 非 NULL → Bound::from_owned_ptr 所有权转移

| 偏离 | 设计文档 | 实际实现 | 原因 |

## 5. 设计质疑

无大问题。3 处小偏离已在 §4 列出，均按"自认为合理方式实现"处理：

1. **[设计质疑-小] Node Clone**：设计 §3 写 Clone 派生，但 Node enum 不可 Clone（项目既有约束）。实现跟随 BitwiseNode 惯例只用 Debug。若设计强需 Clone，需先让 Node enum 派生 Clone（影响整个项目，超出 6.2 范围）。

2. **[设计质疑-小] PyUnicode_AsUTF16String BOM**：设计 §2.2.2 注释说"输出无 BOM"，但 CPython 实际加 BOM。实现已正确剥离 BOM + byte-swap，行为符合 Python `str.encode("utf_16_le")`（无 BOM）。建议 ARCH 在 ADR-021 沉淀时修正此描述。

3. **[设计质疑-小] Python 侧范围**：任务书"实施范围"列了 6 项，未明确包含 Descriptor + pyfunction + compile.rs。我实施了最小 Python 侧（StringError + StringEncoded 别名）以保证 Rust 模块初始化不失败。若需端到端可用，PM 需分派 Python 集成子任务。

#### 8.2.2 Rust 侧 compile.rs 扩展（`build_node_from_descriptor`）

新增 6 个分支 + 6 个 helper 函数（参照 ArrayDescriptor / BytesDescriptor 模式）：

| type name | helper 函数 | 关键编译路径 |
|-----------|------------|-------------|
| `"CStringDescriptor"` | `build_cstring_node` | encoding 编译期解析 + term/include/require 提取 |
| `"GreedyStringDescriptor"` | `build_greedy_string_node` | 仅 encoding 编译期解析 |
| `"PaddedStringDescriptor"` | `build_padded_string_node` | length 常量/表达式分类（与 BytesDescriptor 同模式）+ encoding |
| `"PascalStringDescriptor"` | `build_pascal_string_node` | 递归编译 lengthfield（沿用 field_index）+ encoding |
| `"NullTerminatedDescriptor"` | `build_null_terminated_node` | 递归编译 inner + term/include/consume/require |
| `"NullStrippedDescriptor"` | `build_null_stripped_node` | 递归编译 inner + pad |

**公共 helper**（提取复用）：
- `parse_encoding_attr`：从描述符读 `encoding` 字符串 → 调 `Encoding::from_user_str` → 返回 `Encoding`（编译期失败携带 P2b/P8 引导文本）
- `parse_term_attr`：读 `term` 字节串（None → encoding 默认 term）
- `parse_pad_attr`：读 `pad` 字节串
- `parse_bool_attr`：读 bool 属性（带默认值）

**[设计质疑-小] 编码错误类型**：
设计 §10.2 P1 写"Encoding_from_user_str 在编译期被调，无后缀编码此处即抛 StringError"。
实际实现：encoding 编译期校验失败时由 `Encoding::from_user_str` 返回 `ConstructError::Compilation`（被 `__init_subclass__` 映射为 Python `CompilationError`），而非 `StringError`。
**原因**：要在 Python 侧 __init__ 阶段抛 `StringError`，需暴露 `Encoding_from_user_str` pyfunction（设计 §10.2 P2），增加 FFI 入口。
**取舍**：选择与 BitsIntegerDescriptor 同模式（编译期校验在 compile.rs 完成 CompilationError），减少 FFI 入口数量。错误时机仍在编译期（`__init_subclass__`），错误信息含 P2b/P8 引导文本，用户可读性等同。
建议 ARCH 在 ADR-021 沉淀时确认此偏离。
