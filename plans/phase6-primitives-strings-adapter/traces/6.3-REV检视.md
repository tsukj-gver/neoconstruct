### 5.4 小问题（非驳回项，建议 ARCH 补充）

**问题 1（RawCopy build None + flagbuildnone 分支未处理）**：

- **位置**：设计 §1.3.2 RawCopyNode.build（L256-276）
- **问题**：Python core.py L4797-4798 处理 `obj is None and self.subcon.flagbuildnone` → `obj = dict(value=None)`。设计未处理此分支。
- **影响评估**：construct-rs 整体不使用 flagbuildnone 概念（SubconstructNode/RawCopyNode 均无此字段），所以这是边缘场景。若 RawCopy 字段值为 None，construct-rs build 会尝试 `obj.__contains__`，None 无此方法 → Generic 错误（而非 Python 的优雅回退）。
- **建议**：在 §5.3 已知差异表补充一行"RC-build-2：RawCopy build 不处理 None obj + flagbuildnone（construct-rs 无此标志）"，或在 §1.3.2 build 路径显式处理 None obj（决策由 ARCH 定）。

**问题 2（Rebuild 接收 callable 限制未在差异表记录）**：

- **位置**：设计 §1.4.1（L316 "不接收 Python lambda/callable"）+ §5.1 RB-5（编译期拒绝 callable）
- **问题**：Python Rebuild.func 可以是任意 callable lambda（core.py L3006 `evaluate(self.func, context)` 支持 callable）。construct-rs 收窄为仅 Phase 2 表达式。这是已知的 API 收窄（与 ADR-014 RepeatUntil v5 同脉络），但 §5.3 已知差异表未列出。
- **影响评估**：用户面 API 收窄，文档化即可。RB-5 已在边界条件中标注编译期拒绝。
- **建议**：在 §5.3 已知差异表补充一行"RB-callable：Rebuild func 仅接受 Phase 2 表达式，不接受 Python callable（与 ADR-014 同脉络）"。

**问题 3（§4.4 论证 2 与 §4.5 设计内在矛盾）**：

- **位置**：设计 §4.4 论证 2（L591）vs §4.5（L621 AdapterCallbackNode）+ §3.1（Node enum 第 6 变体）+ §6.3（compile.rs "AdapterDescriptor" 分支）
- **问题**：§4.4 论证 2 声称"用户面 Adapter 不在执行树内"，但 §4.5 把 AdapterCallbackNode 设计为 Node enum 变体（§3.1）并在 compile.rs 编译（§6.3），这意味着 AdapterCallbackNode **在执行树内**，每次该字段 parse 都回调 Python _decode（2 次 FFI）。论证与设计自相矛盾。
- **影响评估**：**不影响结论**。PM 决策 2 约束 2 已明确允许"最小通用钩子"，PM 决策 6.3-D1 已接受 AdapterCallbackNode。§4.4 论证 3-4（用户主动选择 = 显式接受折衷；不属于中间表示层语义）才是正确论证路径。
- **建议**：修正 §4.4 论证 2 为"承认 AdapterCallbackNode 在执行树内，但 2 次 FFI 是用户主动选择的后处理开销（PM 决策 2 已接受），不属于 §0 #1 禁止的'中间表示层'（中间表示层指 Rust 端临时数据类型再转换，非用户 Python 回调）"。删除"不在执行树内"这一与 §4.5 矛盾的表述。
