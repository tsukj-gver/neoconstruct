# Phase 9：系统测试

## 目标

用真实二进制协议验证 construct-rs 的端到端能力：仅用已实现的构造器组合，实现协议定义 + parse/build round-trip + parity vs Python construct 2.10.70。

**这是集成测试，不引入新构造器**——验证现有能力的组合表达力。

## 范围（候选协议，DEV 选 3-4 个实现）

| 协议 | 复杂度特征 | 测试重点 |
|------|-----------|---------|
| **Modbus RTU** | 功能码条件分支 + 寄存器数据 + CRC16 | Switch + Checksum(CRC) + Array |
| **CAN / CAN-FD** | bitfield ID（标准/扩展帧）+ DLC + 数据 | BitStruct + BitsInteger + 条件分支 |
| **IEC 104** | APCI 帧头 + ASDU 多类型 + 序列号 | Struct + Switch + 嵌套 + Array |
| 其他（DEV 判断） | 含 bitfield + CRC + 条件分支的复杂协议 | 综合覆盖 |

DEV 自主选协议，优先选**条件分支 + bitfield + CRC 都有**的复杂协议（对齐 Phase 10 验证标准）。

## 出口标准

1. 每个协议：parse 真实/构造的报文 → 验证字段 → build 回原始字节（round-trip 一致）
2. parity：vs Python construct 2.10.70 同协议定义（若 construct 原版能表达），parse/build 结果一致
3. 不引入新构造器（若发现 API 不足，记录为 follow-up，不强加）
4. 过程记录每个协议的实现 + 测试结果
