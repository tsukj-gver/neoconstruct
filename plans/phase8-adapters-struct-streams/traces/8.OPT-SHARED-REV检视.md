## 2. 逐维度检视

### 2.1 §0 合规(L-01 对策)— ⚠️ 结构合规但前提崩塌

**正面**:
- ADR-023 §0 对照表(L221-232)+ 设计文档 §2(L567-578)均提供 8 条原则逐条对照
- 对照逻辑正确:O1-A 直读得到的是实例 `__dict__` Python 对象本身(与 R4/ADR-008 语义一致),不引入 Rust 中间数据类型
- 不引入新 trait、不引入 per-field 抽象层(§0 #3)
- pyo3::ffi 仍是唯一 Python 绑定(§0 #4)

**问题**:
- §0 对照**建立在 cpython 子模块可用的前提上**。本检视证伪该前提(详 §2.3 可行性)。在 abi3 fallback 路径下,§0 对照对 fallback 路径(已有 R4 getattr / PyDict_SetItem / as_bytes)的论证是 trivial 的(因为这些是当前实现,本来 §0 合规)
- **建议**:ADR-023 §0 对照表应区分"unsafe fast-path 的 §0 合规"和"abi3 fallback 的 §0 合规",目前混在一起

### 2.2 unsafe 安全论证 — ✅ 理论充分(但实际不执行)

**正面**:
- 每个 unsafe 块附 SAFETY 注释模板(指针来源/生命周期/别名规则/不变量)
- ABI 稳定性论证逐项展开(O1-A L236-254 / O1-B L428-438 / O2-A L529-539)
- 退化路径覆盖:abi3 / managed dict / 未来 CPython 改字段 / 字段类型不符 / 返回值异常
- Python 3.12+ managed dict 已识别(L249-253,L792 提示 #7)
- 论证深度与 ADR-019(O3 U1-U4 SAFETY 表)/ ADR-021(D1/E1 SAFETY 表)先例**一致**

**问题**:
- 在当前 abi3 编译环境下,**所有 unsafe 路径不执行**(cfg fallback 走 safe 路径),SAFETY 论证无实际意义
- 若 abi3 问题解决(详 §3 必须修复项),SAFETY 论证可复用

### 2.3 可行性 — ❌ **致命问题,直接驳回**

#### 2.3.1 致命可行性问题:cpython 子模块在当前项目实际编译环境下完全不可用

**ARCH 论证**(ADR-023 L76-77 + 设计文档 §6 L754-762):
> "当前项目为非 abi3 模式(`pyproject.toml` 未设 `abi3 = true`,`Cargo.toml` `pyo3 = "0.22"` 无 abi3 feature),cpython 子模块可用。"
> "当前 instance.rs 注释(L26-37):注释提到 `PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1` + `Py_LIMITED_API`,但 pyproject.toml + Cargo.toml 均未启用 abi3——**该注释可能是历史遗留或文档错误**。实际编译时 `Py_LIMITED_API` 不应被定义。"

**REV 独立核查**(逐条证伪):

**证伪 1**:pyo3 abi3 启用有**两条独立路径**:
- 路径 A:`Cargo.toml` 启用 `pyo3/abi3` feature(`CARGO_FEATURE_ABI3` cargo env var)
- 路径 B:环境变量 `PYO3_USE_ABI3_FORWARD_COMPATIBILITY=1`

**ARCH 只检查了路径 A,完全忽略了路径 B**。源码证据:
```rust
// pyo3-build-config-0.22.6/src/impl_.rs L738-741
fn is_abi3() -> bool {
    cargo_env_var("CARGO_FEATURE_ABI3").is_some()
        || env_var("PYO3_USE_ABI3_FORWARD_COMPATIBILITY").map_or(false, |os_str| os_str == "1")
}
```

**证伪 2**:abi3 模式下 pyo3 build script 输出 `Py_LIMITED_API` cfg flag:
```rust
// pyo3-build-config-0.22.6/src/impl_.rs L180-182
if self.abi3 {
    out.push("cargo:rustc-cfg=Py_LIMITED_API".to_owned());
}
```

**证伪 3**:pyo3-ffi cpython 子模块由 `#[cfg(not(Py_LIMITED_API))]` 守护,abi3 下完全不编译:
```rust
// pyo3-ffi-0.22.6/src/lib.rs L455-459
#[cfg(not(Py_LIMITED_API))]
mod cpython;
#[cfg(not(Py_LIMITED_API))]
pub use self::cpython::*;
```

**证伪 4**(实测铁证):construct-rs 项目实际编译时,pyo3_ffi crate 编译命令带 `--cfg Py_LIMITED_API`(本检视运行 `cargo build --lib --release --verbose` 验证):
```

```

#### 2.3.2 ARCH 设计的 cfg fallback 是"安全网"还是"自欺欺人"?

设计文档/ADR-023 反复强调"所有 unsafe 路径配套退化路径(Py_LIMITED_API → fallback)"。**但这恰恰是问题所在**:

- 设计的三条优化在 abi3 模式下**全部走 fallback**(因为 `#[cfg(not(Py_LIMITED_API))]` 的代码根本不编译)
- fallback 路径 = 当前的 safe 路径(getattr / PyDict_SetItem / as_bytes),节省 = 0 ns
- 设计预测的"共享税从 180ns 压到 135-155ns"在 abi3 模式下**数学上不可能达成**
- 10 项 parse case 的 10x+ 目标在 abi3 模式下**数学上不可能达成**

cfg fallback 的设计本意是"未来若切 abi3,优化自动降级"——但**当前项目就是 abi3 模式**,这意味着优化从一开始就降级到零节省。

#### 2.3.3 对 ARCH 的建议方向

ARCH 必须在 ADR-023 + 设计文档中**重新评估**以下三条路径之一:

| 选项 | 描述 | 可行性 | 性能影响 |
|------|------|-------|---------|
| A | 取消 abi3 模式(`PYO3_USE_ABI3_FORWARD_COMPATIBILITY=0`)| ❌ 违反项目硬约束(phase5 L163 + 项目 Python 3.14 兼容性)| 损失 Python 版本兼容性 |
| B | 用 PyType_GetSlot 替代 tp_dictoffset 直读(类似 phase5 B-conservative)| ⚠️ 需重新设计 | `tp_dictoffset` **不是标准 PyType_GetSlot 插槽**(设计文档 L257-258 已识别),需另寻 stable ABI 路径 |
| C | 用 stable ABI 替代 `_PyDict_SetItem_KnownHash` + `PyBytes_AsStringAndSize` | ⚠️ stable ABI 的 dict 操作无法跳过 hash,O2-A 已是 stable ABI fallback | O1-B 不可行;O2-A fallback 已 = 当前实现 |
| D | 完全重新设计优化方案(放弃 cpython 子模块依赖)| ⚠️ 需重新分析瓶颈 | 未知 |

**REV 不替 ARCH 决定选哪条**,但要求 ARCH:
1. **实测验证**:在 ADR-023 §6 提供 `cargo build --lib --release --verbose 2>&1 | grep "Py_LIMITED_API"` 输出,确认当前编译模式
2. **重新评估**:基于实测结果,重新评估三条优化的可行性
3. **不可甩锅**:不可写"DEV 实施前必须验证"(设计 §7 #1-#4 已暴露此问题)

**文档位置**:设计文档 §1.2.2 L374-378

**建议**:对照表区分两栏(unsafe fast-path §0 合规 / abi3 fallback §0 合规),前者是新增论证,后者是已有合规。

#### v2 最关键新风险（GenericGetDict）独立验证 — ✅ 全部通过

ARCH v2 把 O1-A 从"tp_dictoffset 直读"改为"`PyObject_GenericGetDict(obj, NULL)`"。我做了 CPython 官方文档 + pyo3 0.22 源码双重独立验证（**不复述 ARCH 论证**）：

**独立验证项 1：PyObject_GenericGetDict 是否真是 CPython stable ABI？**

CPython 3.14.7 官方文档（`docs.python.org/3/c-api/object.html#c.PyObject_GenericGetDict`，REV 通过 webfetch 独立获取）原文：
> `PyObject *PyObject_GenericGetDict(PyObject *o, void *context)`
> *Return value: New reference.* **Part of the [Stable ABI](stable.html#stable) since version 3.10.**
> A generic implementation for the getter of a `__dict__` descriptor. **It creates the dictionary if necessary.**
> Pass `NULL` for *context* when calling it.

✅ **Stable ABI since 3.10 确认**（项目目标 3.13 > 3.10，适用）。注：函数本身 Added in version 3.3（非 v2 文档所说的"自 Python 2.x 起存在"，但不影响结论）。

**独立验证项 2：GenericGetDict 在 Python 3.13 managed dict 下行为是否正确？**

CPython typeobj.html `tp_dictoffset` 节（REV 独立 webfetch）原文：
> The `tp_dictoffset` should be regarded as **write-only**. To get the pointer to the dictionary **call `PyObject_GenericGetDict()`**.
> If the `Py_TPFLAGS_MANAGED_DICT` bit is set in the `tp_flags` field, then `tp_dictoffset` will be set to `-1`, to indicate that **it is unsafe to use this field**.

CPython typeobj.html `Py_TPFLAGS_MANAGED_DICT` 节：
> Added in version 3.12.（注：非 v2 文档所说"3.13 引入"——3.12 引入 flag，3.13 默认对所有 heaptype 启用）

✅ **CPython 官方推荐用 GenericGetDict 替代 tp_dictoffset 直读**，且明确"`may need to allocate memory for the dictionary`"（即触发 lazy materialize）—— v2 设计文档 §Python 3.13 managed dict 调研 §实证 2 描述完全一致。

**独立验证项 3：from_owned_ptr + downcast 的所有权/生命周期论证是否充分？**

pyo3 0.22 源码独立核查（`~/.cargo/registry/src/index.crates.io-*/pyo3-0.22.6/src/instance.rs` L115-126）：
```rust
impl<'py> Bound<'py, PyAny> {
    /// Constructs a new `Bound<'py, PyAny>` from a pointer. Panics if `ptr` is null.
    /// # Safety
    /// - `ptr` must be a valid pointer to a Python object
    /// - `ptr` must be an **owned** Python reference, as the `Bound<'py, PyAny>` will assume ownership
    pub unsafe fn from_owned_ptr(py: Python<'py>, ptr: *mut ffi::PyObject) -> Self {
        Self(py, ManuallyDrop::new(Py::from_owned_ptr(py, ptr)))
    }
}
```

CPython 文档：GenericGetDict "Return value: New reference"（即 owned reference）。
- `dict_ptr`（GenericGetDict 返回值）是 owned reference
- `Bound::from_owned_ptr(py, dict_ptr)` 接管 ownership（不 incref，假设 ptr 已带 ownership）
- `downcast_into::<PyDict>()` 仅类型转换，不改 ownership
- Bound drop 时自动 decref（ManuallyDrop + Py::from_owned_ptr 内部链）

✅ **所有权链完整无泄漏**。v2 设计文档 §1.1.2 L284-288 SAFETY 注释 + §7 提示 #3（L898-900）"GenericGetDict 返回值是 owned reference，必须用 from_owned_ptr 接管"正确。

**独立验证项 4：v2 ARCH 的 4 条路径交叉验证是否合理？**

## 3. 非阻塞建议（描述精度，P0 解决后供 ARCH/DEV 参考）

### NB2-1：PyObject_GenericGetDict 的稳定 ABI 起始版本描述不精确

**文档位置**：
- ADR-023 L99-101（"自 Python 2.x 起存在，签名稳定"）
- 设计 §1.1.2 L259-262（"自 Python 2.x 未变"）
- 设计 §1.1.3 ABI 稳定性表 L334（"自 Python 2.x 未变"）

**问题**：CPython 3.14.7 官方文档（REV 独立 webfetch 确认）明确：
- 函数本身 **Added in version 3.3**（非 2.x）
- **Part of the Stable ABI since version 3.10**（非 2.x）

**影响**：项目目标 Python 3.13 > 3.10，结论不受影响（Stable ABI 适用）。

**建议**：DEV 实施时或 ARCH 下次修订 ADR 时修正为"Added in 3.3，Stable ABI since 3.10"。不阻塞。

### NB2-2：Py_TPFLAGS_MANAGED_DICT 引入版本描述不精确

**文档位置**：
- ADR-023 §Python 3.13 managed dict 影响 L221（"Python 3.13 引入 managed dict"）
- 设计 §Python 3.13 managed dict 调研 L106-108（"Python 3.13 引入 managed dict"）

**问题**：CPython typeobj.html `Py_TPFLAGS_MANAGED_DICT` 节（REV 独立 webfetch 确认）明确 **Added in version 3.12**。Python 3.12 引入 flag，Python 3.13 默认对所有 heaptype 启用（之前 opt-in）。

**影响**：不影响结论。项目目标 3.13，managed dict 默认启用，v2 实测（设计 §实证 1）正确。

**建议**：DEV 实施时或 ARCH 下次修订时修正为"Python 3.12 引入 `Py_TPFLAGS_MANAGED_DICT` flag，3.13 默认对所有 heaptype 启用"。不阻塞。

### NB2-3：pyo3 对 PyObject_GenericGetDict 的 cfg 守护条件描述不精确

**文档位置**：
- ADR-023 L103（"不依赖 cpython 子模块，abi3 / 非 abi3 均可用"）
- 设计 §模块位置 L27-29（"不依赖 cpython 子模块，abi3 / 非 abi3 均可用"）
- 设计 §1.1.3 L344（"abi3 / 非 abi3 均可用"）

**问题**：REV 独立 grep `pyo3-ffi-0.22.6/src/object.rs` L372 实际守护条件是：
```rust
#[cfg(not(all(Py_LIMITED_API, not(Py_3_10))))]
pub fn PyObject_GenericGetDict(arg1: *mut PyObject, arg2: *mut c_void) -> *mut PyObject;
```
即"abi3 + Python < 3.10"时不可用，其他场景（非 abi3 / abi3+Python≥3.10）均可用。

**影响**：项目目标 Python 3.13 > 3.10，无论是否切 abi3都可用，结论不受影响。但"abi3 / 非 abi3 均可用"的措辞漏了 `Py_3_10` 例外条件。

**建议**：DEV 实施时或 ARCH 下次修订时修正为"在 Python ≥ 3.10 下，abi3 / 非 abi3 均可用"。不阻塞。
